## 1. ДОКТРИНА МОНОТОННОГО ХРАПОВИКА (QUALITY RATCHET)

### 1.1 Почему храповик не имеет обратного хода
> *«A ratchet that cannot see a defect class rewards moving debt into that class (Goodhart)».*

Обычные системы контроля качества позволяют агентам «накручивать» зелёные галочки:
- Агент удаляет сложный интеграционный тест — число упавших тестов падает до нуля!
- Агент меняет эпсилон `1e-4` на `10.0` — тест внезапно «проходит».
- Агент комментирует `// assert` — ошибок больше нет.

**Монотонный Храповик ([`tools/quality_ratchet.py`](file:///C:/gigahrush2/tools/quality_ratchet.py)) делает такой саботаж невозможным:**
1. **Полы (Floors):** количество боевых файлов, тестовых файлов и общее число проверок (`total_assertions`) **НИКОГДА не могут уменьшаться относительно зафиксированного бейслайна** (`.data/quality-ratchet-baseline.json`).
2. **Потолки (Ceilings):** количество заглушек (`TODO`, `FIXME`, `HACK`) и опасных кастов (`reinterpret_cast<void*>`) **НИКОГДА не может расти**.
3. **Автоматическое затягивание (Monotonic Tightening):** как только разработчик или агент добавляет новые проверки или снижает число долгов, храповик **автоматически затягивается** на новом максимуме и блокирует любой откат назад.

## 2. ПРАВИЛА АНТИ-МАНИПУЛЯЦИИ (ANTI-GAMING INTEGRITY RULES)

1. **Anti-Gaming Rule №1 (Сравнение с git HEAD):**
   - Никакой локальный бейслайн в рабочей директории не может содержать полы ниже, чем в коммите `git HEAD`!
   - Попытка занизить цифры в `.data/quality-ratchet-baseline.json` вручную немедленно блокируется сравнением с историей git.
2. **Hard Zero Invariant (Абсолютный ноль):**
   - Скипнутые тесты (`// TEST_DISABLED`, `test.skip()`) и брошенные заглушки — жесткий ноль. Их нельзя «забазировать» как легальный долг.
3. **Закон Двойного Счётчика:**
   - При сносе костылей замеряется число реальных проверок CTest: сокращение числа `TODO` не должно приводить к падению числа assertions.

## 3. ПАСПОРТ МЕТРИК ХРАПОВИКА GIGAHRUSH 2

Текущие зафиксированные показатели монотонного пола движка:
- **Боевых модулей (`src/`):** $\ge 287$ файлов.
- **Тестовых сьютов (`tests/`):** $\ge 81$ файлов.
- **Общее число проверочных инвариантов (`assertions`):** $\ge \mathbf{9\,244}$ проверок.
- **Заглушек, TODO и костылей в боевом коде:** **СТРОГО 0**.
- **Опасных бестиповых кастов (`void*`):** $\le 2$ (строго изолированы в низкоуровневых драйверах Vulkan Staging).

## 4. ПЯТЬ ЗАГРАДИТЕЛЬНЫХ КОЛЕЦ IRON GATE PRE-COMMIT

При каждом коммите скрипт [`.git/hooks/pre-commit`](file:///C:/gigahrush2/.git/hooks/pre-commit) прогоняет полную проверку:
1. `[1/5] Diff Guard` — запрет удаления тестов, ослабления ассертов и TODO в `git diff`.
2. `[2/5] Code Invariants` — слои архитектуры L1–L6, запрет `sleep`, RFC 4180 CSV.
3. `[3/5] Agent Barrier` — санитарный контроль от заглушек и пустых `catch`.
4. `[4/5] Monte Carlo Dice Audit` — Кубик Тимаэрта (100–175 точек со случайными сидами).
5. `[5/5] Quality Ratchet` — контроль монотонного пола тестов и потолка долга.

Любой сбой блокирует коммит и выводит развернутый **Failure Manifesto на русском языке**.
