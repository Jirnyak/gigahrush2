## 1. ПРИНЦИПЫ АРХИТЕКТУРНОЙ СТЕНЫ В КОДЕ

### 1.1 Не проза, а компилятор (`row_law.h`)
- Архитектурные требования к формам данных («никакого ООП на горячих путях», «ноль виртуальных методов», «ноль динамических аллокаций в тике») **не могут держаться текстовыми обещаниями**.
- Любая структура данных, которая:
  - Умножается на ёмкость этажа или пула (сущности, части тел, субмаски).
  - Сериализуется в байтовый снимок сейва (`run.sav`).
  - Переливается через Staging Buffer в Vulkan / GPU SSBO.
  **ОБЯЗАНА** быть защищена контуром `GIGA_ROW(T)`:
  1. `std::is_trivially_copyable_v<T>` — переливается через `memcpy`, исключает любые контейнеры с кучей (`vector`, `string`, `unique_ptr`).
  2. `std::is_standard_layout_v<T>` — строгая C-совместимая раскладка без скрытых смещений компилятора.
  3. `!std::is_polymorphic_v<T>` — ноль указателей на vtable.
  4. `std::is_trivially_destructible_v<T>` — удаление слота есть простое зануление памяти без вызова деструкторов.

### 1.2 Паспорт размера (`GIGA_ROW_BYTES(T, Bytes)`)
Если размер структуры зафиксирован в паспорте памяти (например, `sizeof(SubMask) == 64`), макрос `GIGA_ROW_BYTES` блокирует компиляцию при любом случайном добавлении невыровненного поля.

## 2. ИЗОЛЯЦИЯ АРХИТЕКТУРНЫХ СЛОЕВ (LAYER DISCIPLINE)

В движке действует строгая однонаправленная иерархия зависимостей:
```
[Layer 1: src/core]      (Базовая математика, wrap тора, тики, row_law)
         ▲
[Layer 2: src/world]     (Монолит 128³, сетка SubMask, воксели, гравитация)
         ▲
[Layer 3: src/sim]       (Физический солвер, Swept-AABB, контакты, рэгдолл)
         ▲
[Layer 4: src/render]    (Vulkan конвейер, DDA-реймарш, проходы шейдеров)
         ▲
[Layer 5: src/game]      (ECS-геймплей, A-Life, потребности, деяния, позы)
         ▲
[Layer 6: src/app]       (Точка входа main, окно SDL3, конфигурация)
```

### Абсолютные запреты слоев:
1. `src/core` — запрещено включать `world`, `sim`, `render`, `game`, `app`.
2. `src/world` — запрещено включать `sim`, `render`, `game`, `app`.
3. `src/sim` — запрещено включать `render`, `game`, `app`.
4. `src/render` (GPU пайплайн и проходы) — запрещено включать `game`, `app` (исключение: UI оверлеи интерфейса `*_ui.*` в слое представления).
5. `src/game` — запрещено включать `app`.

Механический контроль осуществляется скриптом [`tools/check_code_invariants.py`](file:///C:/gigahrush2/tools/check_code_invariants.py) в CTest.

## 4. ДЕТЕРМИНИЗМ СИМУЛЯЦИИ И ЗАПРЕТЫ В КОДЕ

1. **Запрет `sleep` в горячих путях:**
   - Никаких `sleep_for`, `sleep_until`, `Sleep`, `usleep` в симуляции (`core`, `world`, `sim`, `game`).
   - Мир шагает дискретными квантами по 125 Гц ($dt = 0.008$ с).
2. **Запрет исключений и RTTI:**
   - В ядре запрещены `throw`, `catch`, `try`, `dynamic_cast`, `typeid`.
   - Ошибки возвращаются кодами возврата `Result<T>` или булевыми статусами.
3. **Стандарт IEEE 754 Float32:**
   - Математика мира тора строго полагается на детерминированные операции над `float32` (`std::numeric_limits<float>::is_iec559 == true`).
   - Координаты при wrap нормализуются в интервал $[0, 256.0)$ без денормализованных выбросов.

## 5. ЦЕЛОСТНОСТЬ ДАННЫХ CSV (SINGLE SOURCE OF TRUTH)

Все файлы в `data/*.csv`:
1. Строго UTF-8 **без BOM** маркера (`ef bb bf`).
2. Строки с текстовыми описаниями, содержащими запятые или переносы, **обязаны быть экранированы кавычками** `""`.
3. Уникальность первичного ключа:
   - Одиночные ключи (`id`, `source_id`, `item`, `prop`) обязаны быть уникальными во всей таблице.
   - Составные ключи (например, `(form, seg)` в `prop_forms.csv`) обязаны быть уникальными в паре.
4. Механический гейт `check_code_invariants.py` проверяет количество колонок, кодировку и уникальность ключей перед коммитом.
