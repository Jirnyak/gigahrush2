Пройди по мёртвым столбцам `data/items.csv` из
`Docs/specs/17_ITEM_DATA_AND_CONTAINERS.md` (утверждение «14 мёртвых из 42»
верифицировано ревью 2026-08-10 до строки; сам разбор НЕ делался).

Порядок:
1. Перепроверь список на живом дереве: для каждого столбца — есть ли читатель
   в `src/` или `tools/gen_item_table.py` (подстрочные совпадения имени
   столбца читателем не считаются — нужен реальный потребитель значения).
2. Для каждого подтверждённо мёртвого столбца предложи владельцу решение
   через AskUserQuestion, сгруппировав по смыслу, с вариантами:
   - **убить** — выкинуть из CSV и генератора (закрытие удалением — законный
     исход, см. problems.md §2/§14);
   - **подключить** — только если потребитель очевиден и дёшев по существующей
     механике (пример: `durability` имеет смысл лишь если владелец хочет
     износ — это дизайн-решение, не техническое);
   - **оставить с пометкой** — данные впрок, задокументировать в спеке 17.
3. НЕ изобретай новые механики ради оживления столбца (jirnyak.md: новые
   универсальные системы запрещены). Столбец без дешёвого потребителя = кандидат
   на удаление, а не на систему.
4. Известная ловушка из волны marko1olo: его jamming «читал» `wear`-колонки,
   которых в CSV нет вообще — сначала факт-чек, потом код.

Верификация: `tools/gen_item_table.py` прогоняется, сгенерированный
`item_table.cpp` идентичен по всем живым полям, build + полный ctest, пины
только на 0 failures. Спеку 17 обнови по итогу (что убито, что подключено).
