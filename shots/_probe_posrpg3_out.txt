1|// RPG progression — levels, XP, the three attributes, and every derived stat.
2|//
3|// Ported from the reference `systems/rpg.ts` (418 lines). The reference's own
4|// `data/rpg_progression.ts` is TWO LINES — just the two caps — so the numbers below
5|// come from the system file, not from a data table. That is why this lands as a
6|// header of constants rather than a generated CSV table like items/mobs: there are
7|// no ROWS here, only formulas. The one genuinely row-shaped thing in the reference
8|// (per-kind kill XP, 36 authored entries over 69 kinds) belongs in data/mobs.csv
9|// beside the stats it scales, not in a second parallel file.
10|//
11|// WHAT ALREADY EXISTED, and is deliberately not duplicated. `mob_table.h` already
12|// carries the monster-scaling half of `rpg.ts`: `mob_hp_at_level` is that file's
13|// `scaleMonsterHp` (1 + 0.12*(L-1)). The dmg/speed curves (1 + 0.10, 1 + 0.02) are
14|// documented there as inline. This file is the PLAYER/NPC half, which had nowhere
15|// to live: level, xp, attrPoints, str/agi/int, psi, and the 13 derived multipliers.
16|//
17|// FIXED POINT, x1000, for the same reason [status.h] gives: this tree pins bit-exact
18|// digests and a float multiplier chain is not guaranteed identical between MSVC and
19|// Clang ([AGENTS.md]). x1.0 is 1000. The reference computes in doubles; every value
20|// here is the rounded x1000 integer of that double, and the tests pin the reference's
21|// own worked examples.
22|//
23|// NOT PORTED, deliberately, with the reason:
24|//   * `regenPsi` — the reference body is empty (PSI recovers only from items and
25|//     level-ups). An empty function is not a feature; the absence IS the design.
26|//   * `randomGaussian` / `generateHeight` — this tree already has `height_for_age`
27|//     in [population.h], and a Box-Muller pair needs stored RNG state, which the
28|//     stateless `(id,salt)` hashing in [core/rng.h] exists to avoid.
29|//   * `calcZoneLevel` — its ZONE_CELL is W/8 over the reference's flat 1024-wide
30|//     zone grid. This engine's danger model is the V-shape about the hub keyed on
31|//     floor NUMBER ([mob_table.h] `mob_level_for_floor`), which is already built and
32|//     is not the same function. Porting the zone version would be a second,
33|//     disagreeing definition of monster level.
34|//   * `questDifficulty` / `questXpReward` / `questMoneyReward` — quest rewards are

36|//     is exactly one XP awarder.
