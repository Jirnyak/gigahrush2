## Лестница выведена, не назначена

Сим 125 Гц (`core/tick.h:26`, `kSimHz` выведена: 8 мс ровно), SLA уже мыслится степенями
двойки (`rebake.h:71`, потолок 8192), игровой час сегодня 60 с (`room_zone.h:228`). Берём
ближайшую 2^n к существующему часу:

| Единица | Тиков | Реального |
|---|---|---|
| такт | 2^13 = 8 192 | 65.5 с — бывший игровой час |
| вахта | 2^16 = 65 536 | 8.7 мин = 8 тактов |
| цикл | 2^19 = 524 288 | 70 мин = 8 вахт |
| эпоха | 2^22 = 4 194 304 | 9.3 ч = 8 циклов |

Каждый уровень ×8 = три бита. **Смысл степеней двойки — сдвиги вместо делений:**
`вахта = tick>>16`, `цифра = (tick>>16)&7`, `фаза света = (tick>>17)&3`.

**`kGameHourSec` умирает дёшево.** Проверено грепом: у него **ровно один читатель**, и тот
в том же файле — `room_zone.h:258`, `kRoomRecovery[Medical].hpBank = 100.0f / kGameHourSec`.
Ни одного .cpp, ни одного теста, ни одной CSV.

## Часы ничего не толкают

Время — счётчик и функции над ним. Системы времени, которая чем-то управляет, **не
существует**. Границы выводятся сравнением `вахта(now) != вахта(prev)`; если нужна рассылка
— в существующий `event_bus.h`, а не в свою шину.

Четыре способа показать — **четыре потребителя, а не четыре системы**, три из них не код:

| Показ | Чем является |
|---|---|
| свет дома | программа щитка (ниже) — данные |
| гудок на смене вахты | проп-ревун (S3), подписан на границу |
| табло в мире | проп с 9 лампами, 3 группы по 3 — **дефолтный вид** |
| строка в худе | читает тот же счётчик |

### `event_bus` годится, с четырьмя оговорками

`Event::tick` уже `uint64` и штампуется продюсером — номер тика границы приезжает
бесплатно. Публикация из drain-цикла безопасна по контракту (`event_bus.h:161-167`), этим
уже пользуется `relations_drain_deaths`. Но: (1) каждое новое значение обязано назвать
грепаемого продюсера (`:47-51` — четыре типа когда-то врали, что их шлют) + правка
`kEventTypeCount`; (2) `clear()` зовётся раз в **кадр**, а сим делает до 8 подшагов —
читать надо внутри сим-цикла; (3) сырой тик уже в `tick`, дублировать в `a/b/c` не надо;
(4) шина не переживает загрузку, как и `simTick` (`save.h:166`).

## Свет идёт через щиток

Ложится на `powergrid.md` (2026-08-17: «параметры сети живут НА ЩИТКЕ»). **Фаза цикла —
ещё один параметр щитка** рядом с нагрузкой и частотой. Время не трогает лампы.

Дефолт — четыре фазы по две вахты: полный → рабочий → дежурный → тьма, по 17.5 мин.

### Шаг 0 (предпосылка): свести время

**Мерцание идёт на wall-clock** — `currentTimeSec = SDL_GetTicks()/1000` (`main.cpp:6766`),
тот же скаляр уходит на GPU (`main.cpp:7052` → `prop.frag:253`). Фаза цикла по S15 —
функция `simTick` (`main.cpp:2074`). Решение владельца 2026-08-20: **перевести мерцание на
сим-тики**. Побочно: мерцание замирает на паузе и становится детерминированным, то есть
тестируемым в headless.

Цена: править **две копии формулы синхронно** — `flicker.h:34` и `shaders/flicker.glsl:28`.
Синхронность плафона и света держится исключительно их идентичностью; гейт E (`.spv` из
`-D`) это стережёт.

### Шаг 1: связь «лампа → щиток» в данных

Сегодня связи нет вообще: щитки сеются `seed_wall_interactables`
(`prop_system.cpp:419-498`), лампы — `seed_ceiling_lights` (`:501+`, шаг 8 клеток), спавны
независимы, **ни одного общего идентификатора**. Обе сидилки уже зовутся подряд
(`main.cpp:1103`, `:1121`).

- колонка `mains/autonomous` в `props.csv` → `PropDef.pad0_` (`prop_table.h:74`,
  **свободен**, размер 32 Б не меняется);
- `std::uint16_t shieldId` в `PropLight` (`prop_system.h:73-81`) — обычный ECS-компонент,
  ни один буфер и ни один шейдер не трогается;
- проставление: хэш блока сетки ламп — он же и есть «район щитка», детерминированно и
  дёшево.

### Шаг 2: программа щитка как данные

Компонент на сущности щитка (`Kind::ElectricalShield`, `data/interactables.csv:3`):
`{phaseOffset, phaseLenTicks = 2^17, levels[4] = {1.0, 0.6, 0.25, 0.0}}` + параметры сети
из `powergrid.md` §4. **Побочно чинит**: `PowerGridState` сегодня — локальный POD в `main()`
(`main.cpp:1917`), не в ECS и **не в сейве**; компонент на щитке это закрывает.

### Шаг 3: применение — точка одна

`main.cpp:348-362`. Предикат `is_power_cut` (`combat.h:87-103`, вместе с литералом
`12.0f * 12.0f` на `:98`) заменяется на «щиток моего id жив?». Множитель фазы умножается в
существующую строку `:361-362`. `add_light` (`gpu_light_grid.cpp:217-229`) сам отбрасывает
`intensity <= 0.001` — **фаза «тьма» гасит лампу без единой дополнительной ветки**.

### Шаг 4: синхронный emissive

Иначе обесточенная лампочка светит плафоном — сегодняшнее расхождение с `powergrid.md` §3
(«свет И emissive синхронно»): `prop.frag:276` считает emissive из статического байта, GPU
про питание не знает. Дешевле всего — поднять `propPassNeedsRebuild` на границе фазы
(редко, раз в 17.5 мин) и записать `pi.emissive = базовый × уровень` в `main.cpp:1343`.

## Что получается даром

- **Часы по свету локальны**: у каждого щитка своя программа, районы гаснут по-своему,
  рассинхрон сам становится сигналом «в том крыле что-то не так».
- **Диверсия**: вырубил щиток перед налётом → темно → предложение *логово* выросло
  (S12.4, СРЕДА) → твари. Ноль нового кода.
- **Процедурные режимы позже** — другая программа щитка, не правка времени.
- **Время влияет на алайф физически**, через поле света: решение «время на выбор не влияет»
  (S13) остаётся верным буквально.

## Гейты

1. **Ни одного `%` и ни одного деления** в вычислении времени — грепом.
2. **Граница вахты ровно одна на 65 536 тиков** — счётчик за длинный прогон.
3. **Детерминизм мерцания**: два прогона с одинаковым `simTick` дают одинаковый факт
   (сегодня невозможно — wall-clock).
4. **Паритет CPU/GLSL**: тест сравнивает `flicker.h` и `flicker.glsl` на сетке значений.
5. Фаза «тьма» действительно гасит: `GIGA_LIGHT_DBG` показывает падение `lit`.
