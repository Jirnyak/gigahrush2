# Кластеризация света: стоимость кадра не зависит от контента — по построению

Решения владельца 2026-08-20 (ночь-2): (1) направление — **кластеризация
хвоста в бейке**, топ-K честных ламп + хвост слит в кластеры **тем же структом
PointLight**; камерный кап отвергнут (воскрешение похороненного капа-512);
(2) **кластеры без теневого марша** — весь бюджет лучей уходит сильнейшим.
Мотив владельца: «любая сцена с многим светом ложит fps» — класс должен
умереть, а не лечиться ручками; «сделать и потом не крутить никакие параметры».

## 1. Почему это одна система, а не новая

- `PointLight` уже универсален: лампочка, прожектор, трассер и **неон-кластер
  светоматериалов** (`bake_material_lights` уже сливает светящиеся субвоксели
  в кластерные лампы: центроид + радиус охвата + сумма). Кластер ламп — та же
  идея, применённая уровнем выше. Потребители (surface_light, light_grid.comp)
  **не меняются ни строчкой** — кластер неотличим от лампы.
- Бейк видимости уже даёт каждой клетке отсортированный по вкладу список
  достижимых ламп. Кластеризация — пост-шаг над готовым списком.

## 2. Дизайн

### 2.1 Кластер = пространственный бакет ламп, слот в статик-таблице

Кластер на клетку синтезировать нельзя (262144 × M записей); кластеры —
**общие**, по пространственным бакетам: лампы группируются по блоку
**8 м = 2×2×2 клетки светосетки** (вывод: ошибка позиции кластера ≤
полудиагонали бакета ≈ 6.9 м — хвостовые лампы по построению дальние/слабые,
их угловая ошибка тонет в аттенюации; подтверждается замером и глазами,
§4). Кластер бакета: позиция = центроид членов, взвешенный силой; радиус =
охват членов (максимум дистанции до члена + его радиус); сила = Σ членов;
цвет = взвешенное среднее. Кластеры живут **в статик-таблице** обычными
слотами после ламп (kRootLights 131072 — места навалом: ~12.5k ламп + единицы
тысяч бакетов).

### 2.2 Состав клетки решает бейк

Для каждой клетки после сортировки по вкладу:

```
слоты клетки = топ-K честных ламп (по вкладу, как сейчас)
             + кластеры бакетов, в которые попал ХВОСТ (по одному id на бакет,
               отсортированы той же метрикой — суммарным вкладом хвоста бакета)
```

- **K = 8**: вывод — максимум теневого бюджета пикселя (4 близко) × запас 2 на
  отбраковку порогом/ndotl (список один на клетку, лучи выбирает пиксель).
  Финал K — замером (mean длина списка, fps, глаза), но это константа С
  ВЫВОДОМ, а не ручка.
- Кластеры ниже порога-надгробия (kTombstoneIntensity на дистанции клетки) —
  выброшены с печатью (S11, молча не режем).
- Списки клеток становятся ~K+M ≈ 8-12 вместо 63 → скан на пиксель дешевеет
  на порядок, и **worst case перестаёт зависеть от контента**: зал с 500
  ламп = коридор с тремя.

### 2.3 Кадр: интенсивность кластера — сумма членов

CPU уже обновляет интенсивности всех статиков каждый кадр (мерцание,
обесточка, надгробия). Кластер = ещё один проход: `intensity[слот кластера] =
Σ intensity[члены]` по CSR-списку членов (десятки тысяч сложений — доли мс).
Что выпадает даром: мерцание кластера статистически усредняется (физически
честно для толпы ламп); обесточка района щитком гасит его кластер; разбитая
лампа-надгробие уменьшает сумму тем же кадром.

### 2.4 Тени и инварианты

- Кластер **не маршится** (решение владельца): он запечённо-достижим для
  клетки (достижимость = хоть один член достижим — консервативно), ошибка
  только «посветить лишним» в 4-м гранулярности — инвариант (б).
- Грязные клетки (карв-фолбэк) биннят всю таблицу дистанционно — увидят и
  члены хвоста, и их кластер: временный двойной свет до свапа ребейка. Ошибка
  в сторону света, инвариант (б); ребейк ужимает.
- S7 чист: состав клетки — функция геометрии, камера ни при чём.

## 3. Инкременты

1. **Бейк**: в `light_vis_bake` пост-шаг — бакетизация хвоста, синтез
   кластеров (CSR членов наружу), укладка K+кластеры в GpuGridCell. Формат
   клетки/шейдеры НЕ меняются.
2. **Таблица**: кластерные слоты при Fresh/Rebake-свапе (стабильные на
   поколение, как статики), CPU-сумма интенсивностей в collect_scene_lights.
3. **Suite**: оракул потока — на сэмплах (клетка, точка) суммарный вклад
   (топ-K + кластеры) ≈ вклад полного списка в пределах вывода §2.1; пин
   бейка (хеш состава клеток); обратная полярность — сломать суммирование,
   тест обязан покраснеть.
4. **Замер**: A/B тем же GIGA_LIGHT_BUDGET-приёмом + fps владельца в худшем
   зале; печать сводки: mean/max длина списка, число кластеров, выброшено
   ниже надгробия.

## 4. Что подтверждается замером (не ручки, а верификация выводов)

Бакет 8 м, K=8 — константы с выводами; если глаза владельца увидят ступень
кластера (дальний зал «плоский») — бакет уменьшается вдвое с перезамером, это
изменение вывода, а не подгонка. Цель владельца: поставил и забыл.
