# Свет: перф-эпик (моя зона — пропы/рендер). Диагноз закрыт 2026-08-18

## Два независимых доказательства одного диагноза

Кривая GIGA_LIGHT_BUDGET (падик, один бинарь): 512 ламп → 21.7 мс GPU-кадра,
128 → 19.8, 32 → 18.2, 8 → 10.5. ~11 мс (52%) — марши теней к перекрытым лампам;
платит плотность ламп в клетках у камеры, не общее число (провал 32→8).
Параллельный агент подтвердил кодом: (2) kFogRadius = kWorldExtent*0.5 = 128 м
при максимуме тороидальной дистанции 128 м — отсечение пропускает 66% мира;
(3) окклюжна в сборе света нет вообще. Контент честный (падик 12 552 источника),
режет и тормозит рендер.

## Очередь правок (моя)

1. **PropPass::add_instance** — кап 4096/форму режет по порядку вставки молча →
   на падике (6240/6661 мешей) пропадают плафоны при живом свете. Правка: отбор
   по вкладу/дистанции + печать вслух (приём светосетки). Срочная — владелец
   видит «свечение без плафона» прямо сейчас.
2. **Дизайн-док запечённой видимости «лампа→клетка светосетки»** — центральный
   рычаг (кривая: даёт ~производительность B=8 при качестве B=512). Инварианты
   владельца: пиксельный марш остаётся живым (тени от стен/пропов/дыр — кадр в
   кадр); на карве dirty-клетки мгновенно расширяются до «все лампы радиуса»
   (свет хлынет тем же кадром), фоновый ребейк ужимает; ошибка всегда в сторону
   «посветить лишним». Убивает камерный отбор 512 (гаснущие дальние комнаты).
   Десятая строка реестра допекания (async-rebake).
3. **Отсечение сбора**: радиус из дистанции полной черноты тумана (~64 м), не
   полупериод; НО кривая предупреждает — само по себе счёт-отсечение почти не
   вернёт фпс (32 лампы всё ещё 18.2 мс), это гигиена CPU/биннинга.
4. **sort_lights_by_distance** — std::sort всего стейджинга каждый кадр →
   nth_element/отбор под кап; после бейк-видимости может умереть вовсе.
5. **Renderscale** — дефолт внутреннего рендера ~2048 с апскейлом (S7-пузырь),
   независимый рычаг для 4К.

Порядок: 1 (срочный видимый баг) → 2 (дизайн на ревью владельцу) → 3+4 попутно
→ реализация бейка → 5.

## Решения владельца по капам (2026-08-18, поздний вечер) — канон S11 дополнен

Семь капов рендера — не бюджеты, а размеры SSBO, писанные по одному на пасс
(вывод есть только у kStagingLights). Порядок сломан: PropPass режет на 4096 по
вставке ДО GpuCullPass, который честно отсёк бы по видимости. Решения:
- **Пропы**: кап убрать — буфер от реального контента этажа (или ≥16k минимум),
  видимость решает существующий GpuCullPass, переполнение печатается.
- **Свет**: kMaxPointLights (512) и kStagingLights (16384) умирают ВМЕСТЕ с
  бейк-видимостью (грузим все лампы этажа, отбор делают клеточные списки);
  до неё не трогать — залить 12k ламп в нынешний пиксельный марш = хуже.
- **Частицы**: пул 32768 — образец, не трогать.
- **Верле/антураж**: три капа (wire 1024 / cloth 512 / push 512) → один
  универсальный GPU-пул антуража (32768-класс) в рамках обобщения верле
  (этап 2/SoA); рендер и так рядом с игроком.
Общий закон: капы убирать где можно, вводить эмпирически по замеренным лагам.
