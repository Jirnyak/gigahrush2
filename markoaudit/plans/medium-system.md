# Мир-автомат (S16) — материя и её единственный двигатель

Эталон — [CANON.md] S16, записан с ДВУХ диалогов с владельцем 2026-08-21. Ключевые
решения владельца: мир = автомат (не «слой сред» — та формулировка снята в тот же день
как второе хранилище материи); GPU compute — осознанная часть ядра, headless = «без
окна», не «без GPU»; фазы нет — континуум параметров материала; осевшие обломки снова
геометрия; связь с телами — агрегаты на клетку 128³; самосбор — программа правил над
тем же гридом (механика бесплатна, режиссура своя); carve — писатель грида, материя
не испаряется.

## Почему эпик дешевле, чем звучит

`render/voxel_mirror.h` УЖЕ возит весь субвоксельный мир на GPU: маски SubMask дословно
(uint[16]/клетку), CellType, страницы `sub_material` **слот-в-слот с CPU-пулом**
(uint16/субвоксель = 1 КиБ/страницу), O(dirty-клеток) инкрементальный апдейт от карва и
дверей. Сверка 2026-08-23: SSBO у зеркала **восемь** (+ classes/fluid/stainIdx/stainPool,
voxel_mirror.h:107-123), потребителей **пять** — raymarch (полный сет), body+prop
(shadow set: masks+class), verlet (masks), particle (masks), gas (class). Писатель ровно
один — `flush()` вне рендер-пасса (main.cpp:7456); автомат станет **вторым писателем тех
же буферов** — барьерная дисциплина проектируется на инкременте 2. Готовый актив для
обратного шва: `verify()`/`readback_compare` (voxel_mirror.h:158,186) — рабочий GPU→CPU
ридбек с fence. Эпик не строит грид — он **оживляет существующее зеркало**: даёт ему
автомат и обратный поток. Байт-копия GPU→CPU честна, только если живой брик держит
субвоксель в u16 (1 КиБ/брик, слот-в-слот); u8-упаковка = repack, не memcpy — см.
инкремент 2.

Прочие активы: `fluid.cpp` — контракт правила годный (масса-сохранение, двухбуферность,
детерминизм, `moved`-наблюдение), но сверка 2026-08-23: **в игре мёртв** — `fluid_step`
не вызывается нигде, кроме двух тестов (main.cpp:5467-5482 прямо пишет «Water is painted
and frozen»); «слияние» = удаление мёртвого кода + переезд двух тестов, ломать в игре
нечего; `mark_fluid_dirty()` зеркала — мёртвый API без вызывающих. `gas_sim.comp`
(изотропный downStep пуш-константой, probe-ридбек) — жив, но шагает **фиксированным
1/60 вне сим-тика** (визуальное поле, main.cpp:7310-7313) и несёт **захардкоженную химию
горения** (расход кислорода, дым, затухание — gas_sim.comp:90-109): слияние в
детерминированный автомат — смена класса системы, и химия либо теряется, либо это ровно
отложенные владельцем фазовые переходы — ВОПРОС ВЛАДЕЛЬЦУ до инкремента 4. `destruct.h`
(карв уже знает материал вырезанного — `CarvedVoxel{cell,bit,mat}`, готовый писатель;
`carve_roll`/`carve_hash` — образец `pour()`), `materials.csv` (21 строка × 21 колонка,
`density_kg_m3` есть; воздух = материал 0, но `cpp_name` у него пуст — константы
`kMatAir` нет, есть `kCellAir` в macro_grid.h). `sim/cell_bins.h` (2026-08-21, позже
первой редакции плана): единый закон ключа `cell_bin_key`/`cell_coord` — агрегаты S16.4
обязаны индексироваться им же (иначе шестая выписка закона); сам контейнер `CellBins`
агрегатам НЕ подходит (обратный индекс «клетка→сущности», а агрегат — прямой массив
`kMacroCells`, это `Field<T>`).

Каждый — зелёное дерево, проверка владельцем в игре.

### 1. Таблица: колонки текучесть/диффузия — ПОСТРОЕН 2026-08-23

Сборка Release + ctest 6/6. Колонки `phase,flow,diffusion` в materials.csv
(21 строка, счёт не менялся — пин Rule 7 цел); значения выведены, вывод в
note строк (вода = референс 1.0 при 1 мПа·с; жижа = вязкость_воды/вязкость =
0.1; rubble 0.1 из угла откоса ~40°; воздух = референс diffusion 1.0).
Генератор гейтит расхождение метки и параметров (жидкость обязана течь, газ —
диффундировать, воздух — газ), гейт мутирован в обе полярности. Эмит:
`material_props.h` (`MatPhase`/`kMatPhase`/`kMatFlow`/`kMatDiffusion`/
`material_phase()`) + `material_surface.glsl` (`kMatMedium` vec2, `kMatPhase`).
Находка: строка `rubble` (id 15) уже существует — насыпная 1800 против 2400
бетона; rubble_*-строки инкремента 5 лягут рядом тем же швом.

`materials.csv` + `gen_material_table.py` → колонки `flow` (0..1, 0 = твёрдое),
`diffusion` (0..1) и `phase` (тв/жид/газ — МЕТКА для геймплейных предикатов:
проходимость, плавучесть, дыхание; движение её не читает — S16.2). Факты кодогена
(сверка 2026-08-23): сегодня 21 строка × 21 колонка; эмит в ЧЕТЫРЕ цели —
`world/materials.h`, `world/material_props.h`, `render/material_table.h`,
`shaders/material_surface.glsl` (gen_material_table.py:40-43); Rule 7
(check_source_rules.cmake:375) пинит счёт строк — при добавлении строк поднять пин;
у воздуха пустой `cpp_name` (`kMatAir` нет — либо завести `cpp_name=Air`, либо
пользоваться `kCellAir`). Значения вывести, не назначить (S11): вода из вязкости,
бетон 0, туман из скорости расползания.

**Решение владельца 2026-08-23: рыхлое = ОТДЕЛЬНЫЕ строки CSV (`rubble_*` на исходный
материал), НИКАКИХ битов-флажков.** «Худшее, что можно сделать — для каждой механики
генерить флажок»: минимум систем, механики рождаются эмерджентно из параметров строки
(как разруб трупов родился из единых якорей). Рыхлость — это просто flow>0 у
rubble-строки; движение читает параметры, ветки «рыхлый?» не существует. Параметры
rubble-строк вывести от исходного материала (плотность насыпная — чуть ниже исходной,
flow малый >0, diffusion 0). Кода сима в инкременте ноль.

### 2. Автомат на зеркале (ядро эпика) — ПОСТРОЕН 2026-08-24

Сборка Release без ворнингов, ctest 7/7, мутация правила (своп→копия)
красная в тесте массы. Решения владельца этой сессии: **такт = каждый 4-й
сим-тик** (31.25 Гц; падение 0.25×31.25 = 7.8 м/с — реальное свободное
падение 4 м даёт среднюю 4.4 м/с, автомат чуть быстрее, приемлемо); первая
материя приёмки — ВОДА; видимость — марш по материи (мост до инкр. 6);
налив — существующей `sphere water [r]` (моя команда `pour` отвергнута:
«спавн сферы воды должен делать сферу воды, а гравитация и клеточный
автомат сами сделают своё дело»; вероятностный pour() остаётся законом для
эмиттеров-процессов).

**Дизайн-отличия от плановой редакции (все — упрощения, найденные кодом):**

- **Пул живых бриков НЕ строился.** Страница `sub_material` УЖЕ плотный
  1 КиБ u16 — автомат работает **Margolus-блоками 2×2×2 IN-PLACE прямо в
  каноническом pagePool** ([shaders/medium_sim.comp]): перестановка внутри
  непересекающихся блоков = масса по построению, ноль гонок, ноль
  ping-pong. «Живой брик» = клетка в списке диспатча
  ([render/gpu_medium_pass.h], кап 32768 с выводом и печатью, воркгруппа =
  клетка, поток = блок). Двухбуферность канона оказалась не нужна — блочная
  дисциплина сильнее.
- **Сдвиг решётки — полный 8-фазный цикл Маргулуса** (offset оси = свой бит
  подтика). Диагональный 2-фазный (0,0,0)/(1,1,1) ОПРОВЕРГНУТ красным
  тестом уровня: нужным парам колонок/уровней не совпадают чётности —
  ступень в 2 кванта переживала фикспоинт.
- **Правило растекания — строго выравнивающая диагональ** (ход только
  вниз-вбок в пустую колонку). Симметричный горизонтальный шаг ОТВЕРГНУТ
  дизайном: вечное случайное блуждание лужи = сон недостижим = спящая
  материя не бесплатна (S16.1). Следствие-фикспоинт: **перепад соседних
  столбов ≤ 1 квант** — это и есть «нашла уровень» в этом формате; дальняя
  гидростатика (U-сосуд, сифон) НЕ выравнивается — известное ограничение
  простых CA, дверь на потом.
- **«flow==0 — только падение без опоры» СКОРРЕКТИРОВАНО**: двигается
  только материя БЕЗ бита SubMask, чья строка даёт flow>0 или diffusion>0.
  Иначе пробуждение роняло бы потолки (у любого навеса «нет опоры» под
  каждым субвокселем). Обломки = строки `rubble_*` (flow>0) БЕЗ масок —
  войдут carve-унификацией (инкр. 5), когда автомат научится писать маски.
- **Рендер-мост — класс-байт 3** «частичная с материей сред»: только такие
  клетки платят фетч страницы на пустых битах маски в DDA (raymarch
  march_cell(matter)); обычный мир стоит как стоил. CPU-двойник закона — в
  classify() зеркала; shadow_march трактует 3 как 2 (пол в клетке с лужей
  затеняет, вода — нет). `sphere` фазозависима: бит маски только у
  phase=solid.
- **Wake-протокол**: писатели будят (ensure_page + mark_dirty при
  отсутствии CPU-страницы; полнотвёрдые клетки не будятся); автомат
  репортит ActOut (изменение/касание +октанта/материя у грани/кванты);
  CPU будит соседей, 16 тихих подтиков = сон. ActOut читается без фенса —
  рваное слово даёт лишний wake (безвреден) или ложный quiet (будят
  соседи); точный шов — инкр. 3.
- Кадр: poll_activity ДО flush() зеркала, подтики owed = simTick/4 − done
  сразу ПОСЛЕ flush (барьеры внутри record_substeps), кап 8/кадр — длинный
  фриз списывается вслух, не спиралит. Кодоген: kMatDensity добавлен в
  GLSL-эмит (движение читает плотность по канону S16.2).

**Фидбек владельца 2026-08-24 (первый заход приёмки) — исправлено тем же
днём:** (1) `sphere water` падал «unknown material» — строка звалась
легаси-именем `water_mark`; переименована в `water` (kMatWater, ноль кода);
(2) «carve агностик должен быть — просто удаляет субвоксели» — ПРАВ:
карв роллил только биты маски (легаси до-S16) и вовсе не видел материю
сред, а `remove_key` по опустевшей маске ронял ВСЮ страницу (карв одного
бетонного атома уносил воду клетки). Теперь: кандидат карва =
`atom_exists()` (бит маски ИЛИ атом страницы ≠ воздух ИЛИ однородная
клетка материи сред) — бетон, вода, газ режутся ОДНИМ роллом, различие
только в твёрдости строки; страница живёт, пока в ней есть материя;
однородная водная клетка раскрывается перед удалением атома. Предикат
«материя сред» выписан ЕДИНОЖДЫ — `material_is_medium()` в
material_props.h (кодоген), читатели: классификация зеркала, карв,
GPU-двойник mobile(). Карв теперь и БУДИТ задетые клетки (оба сайта) —
соседняя вода стекает в свежую дыру. Тест: 3 сценария карва в
medium_test (45/45).

**Фидбек владельца, второй заход 2026-08-24 (оба бага мои, исправлены):**
(1) «вода не растекается — кучка-пирамидка» — строгая диагональ первой
редакции была правилом ПЕСКА (угол откоса). Теперь у жидкости ТРИ хода:
диагональ + ДАВЛЕНИЕ (столб >= 2 выдавливает нижний атом в пустоту того же
уровня) + СКОЛЬЖЕНИЕ ПО ОПОРЕ (горизонтальный шаг, помеченный
НЕ-структурным: не сбрасывает счётчик сна — лужа дышит и разливается, но
штиль наступает; вечное дрожание не вернулось). Фикспоинт формы = «нет
столбов >= 2 и перепадов >= 2» = плоская лужа глубиной в квант; тест:
128 квантов → 128 колонн, высота 1, перепад 0, сон за 232 подтика.
(2) «в пропасти вода падает лесенкой вода-пустота» — ось гравитации в
раскладке сдвига Маргулуса сидела на бите 2 (чётность раз в 4 подтика):
падение шло 1 субвоксель/4 подтика (~2 м/с вместо выведенных 7.8) и струя
рвалась стратами. Ось гравитации теперь чередуется КАЖДЫЙ подтик (бит 0),
латерали — биты 1-2. Остаточное разрежение струи периодом 2 субвокселя в
свободном падении — фундаментальное свойство блочного CA (атом падает <= 1
кванта/подтик): визуально струя капель; сплошной столб в полёте потребовал
бы колоночного пасса — дверь на потом, если владельцу глазами не зайдёт.
Ответ на вопрос владельца «сделать материю просто дата-дривен»: УЖЕ ТАК —
движение читает только density/flow/diffusion строки; phase — метка
геймплейных предикатов и вывод бита маски (S16.2), правило её не читает.

**Третий заход 2026-08-24 — ЧИСТЫЙ МАРКОВ (мандат владельца: «только
субвоксели, связность, свойства материала — каждый тик только соседи,
условия типа гравитации, и НИЧЕГО кроме»).** Давление/скольжение/пометка
«структурности» ВЫРЕЗАНЫ как знание о макроформе внутри правила. Правило —
три хода, каждый из одного параметра строки: (1) плотность — плотный тонет;
(2) flow — скат вниз-вбок (сыпучее само держит конус откоса); (3)
diffusion — изотропный обмен с воздухом с единственным ограничением,
выведенным из того же закона плотности: диффузия не поднимает плотное над
лёгким. Жидкости получили выведенную диффузию (вода 0.5 — самовыравнивание
лужи, вывод в note строки; жижи flow×0.5): вода/песок/газ различаются
ТОЛЬКО числами строки. Сон — чисто внешний наблюдатель («ни одного свопа
16 подтиков»), правило о нём не знает: спят щебень, запертая и глубинная
вода; ПОВЕРХНОСТЬ открытой лужи живёт вечно — осознанная цена владельца
(«всё равно же GPU»), live растёт с поверхностью, не объёмом.
**СФЕРА УНИВЕРСАЛЬНА (решение владельца):** `sphere <мат> [r]` честно пишет
шар материала в истину и точка; маска — производный кэш (solid→бит,
иначе снять) → `sphere air` = детерминированный шар воздуха тем же законом
(боевой карв с роллами по твёрдости остаётся оружейным путём). Писатель
будит задетые клетки И их грани (вода течёт в свежую дыру) — оба
карв-сайта и краска. Фантомы «вода замещает пол» убиты этим же ходом:
краска больше не рождает «маска-solid + материал-вода». Тест: 128 квантов
→ 128 колонн монослоем (высота 1, перепад 0), замурованная вода засыпает,
живая поверхность 39 клеток (138/138; ctest 7/7).

**Известные разрывы (закрыть инкрементом 3):** CPU-flush клетки, чью
материю GPU уже сдвинул, перетирает её стейлом (карв рядом с лужей может
«съесть» воду); сейв не знает про GPU-материю; verify() зеркала после
движения материи честно краснеет по classes/pool — он диагностика, не
кадровый путь. Вертикальной диффузии газов нет до слияния gas_sim
(инкр. 4: воздуху нужна честная плотность вместо 0).

Тест ([tests/medium_test.cpp] 36/36): бассейн 10×10, столб 128 квантов
двумя клетками выше дна — падение сквозь спящие нераскрытые клетки
(пробуждение по граням), растекание за границы клеток (woken 23), масса
128/128, сон за 128 подтиков, каждый квант на опоре, перепад ≤ 1.

**2а. Безоконный bring-up — ПОСТРОЕН 2026-08-23** (ctest 7/7).
`VulkanDevice::init_headless()`: без SDL-окна/surface/swapchain, устройство по
одной compute-семье, present-поля алиасят её — ВСЯ существующая машинерия
(VulkanBuffer staging, будущий VoxelMirror) работает без правок. Новый
ctest-бинарь `medium_test` (линкует vk_device/vk_buffer/vk_common напрямую по
прецеденту world_test — таргет `giga_gpu` НЕ понадобился, минимум систем):
смоук CPU→GPU→CPU раундтрипа (шов инкремента 3), побайтное сравнение, мутация
копии — красная. Машина без GPU = НЕ зелёное дерево (осознанно, S16.3).
Тесты правила автомата добавляются в этот же бинарь.

- Compute-пасс над буферами VoxelMirror + **рабочий пул живых бриков**: живой брик =
  клетка, распакованная в плотные **1 КиБ (8³ × u16 материала — слот-в-слот со
  страницей `sub_material`)** на время движения; спящие клетки остаются в каноническом
  формате маска/страница. u16, а не u8 — иначе обратный шов инкремента 3 перестаёт быть
  байт-копией и становится repack (сверка 2026-08-23; u8-упаковка — возможная
  оптимизация потом, внутри автомата). Кап пула корневой, переполнение печатается
  вслух (S11).
- **Второй писатель зеркала**: сегодня у буферов зеркала один писатель (`flush()` вне
  рендер-пасса, main.cpp:7456) и пять читающих пассов в кадре (raymarch, body+prop
  shadow set, verlet, particle, gas). Автомат пишет в те же буферы — спроектировать
  барьеры/очерёдность в кадре ДО кода.
- Правило одно, двухбуферное, checkerboard: падение по downStep фрейма; `flow==0` —
  только падение без опоры (обломки); иначе растекание ∝ flow; `diffusion` —
  расползание; плотность < воздуха — всплытие.
- Писатели будят: карв, эмиттеры (моча/кровь/труба) — dirty-клетка + wake. Субвоксель
  БИНАРНЫЙ, рождение ВЕРОЯТНОСТНОЕ — зеркало carve_roll (решение владельца
  2026-08-21, «рождение/уничтожение — симметрия»): `pour(клетка, материал, литры,
  seed)` → `floor(литры/15.6)` квантов гарантированно + stateless-ролл хешем на
  остаток. Эмиттер = процесс расход×dt. Ноль состояния, воспроизводимость по seed
  как у карва; масса сходится в ожидании. Брызги мельче субвокселя — существующие
  стейны сразу, материя — статистикой.
- Headless: автомат гоняется Vulkan compute **без окна** — тест масса-сохранения и
  «вода находит уровень» в ctest. Сверка 2026-08-23 — это НЕ «просто не создавать

- Дебаг `GIGA_MEDIUM_DBG`: подсветка живых бриков; печатать каждый прогон: живых

- Проверка владельцем: вылить воду на этаже 5 — лужа находит уровень; моча копится.

### 3. Обратный шов GPU→CPU

Уснувший брик пакуется назад в маску/страницу и байт-копируется в CPU-канон (формат
слот-в-слот u16 — трансляции нет; готовый ридбек-путь с fence уже есть — `verify()`/
`readback_compare`, строить на нём); CPU применяет через существующие dirty-контракты,
дальше всё само: коллизия, нав-допекание (S9), свет. «ONE-WAY FLOW» в voxel_mirror.h
умирает как строка и как ограничение. Допуск канона: материя в полёте видна CPU с
отставанием до кадра.

перестанут сходиться, планировщик будет печься вечно. Решить дросселирование до кода:
осевший брик — не карв (дешевле контракта), либо коалесцировать дельты по вахтам
планировщика. Туда же: мёртвый долг `for_each_dirty_light_cell`/`mark_dirty_light_cell`

платит; вычистить ДО инкремента 3, иначе автомат сделает мёртвую плату непрерывной.

## Риски

- **Слоение зависимостей**: `giga_core` не включает Vulkan (AGENTS.md, уточнение

- **Полоса**: трогать только живые брики; спящая материя бесплатна на обоих
  процессорах.
- **Сейв**: канон сериализуется как сегодня (CPU-вид); материя в полёте на сейве
  осаждается или пишется бриками-отличиями — решить на инкременте 3.
- **Детерминизм**: checkerboard + целочисленная материя; эквивалентность прогонов
  гейтится тестом масс-инварианта.
- **Частичные маски — массовая новизна** (сверка 2026-08-23): `fluid.cpp:14-27`
  фиксирует, что сегодня НИКТО в дереве не пишет частичную маску (`fill_cell`/
  `clear_cell` — всё-или-ничего, ёмкость всегда 1.0/0.0). Автомат впервые породит
  массово-частичные клетки; проверить потребителей: nav `patch_carved_cells`,
  `capacity_frac`, class-байт зеркала, `carve_touches_light_material`.
- **Свет**: непрерывный поток dirty от осевших бриков (см. инкремент 3) + рядом с
  пуш-блоком света мёртвая vec4-лейна держит офсеты (урок аварии 9a2b5214: пуш-блок
  шейдера и host-структура — один layout, поля убирать только с обеих сторон).
