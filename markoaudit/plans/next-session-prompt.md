## ГЛАВНАЯ ЗАДАЧА: инкремент F — ПОЛНАЯ ПЕРСИСТЕНТНОСТЬ (S20.6)

План — `markoaudit/plans/skeleton-anchor.md` §F; канон — CANON.md S20.6.
Решение владельца принято диалогом 2026-08-29: этаж помнит ВСЁ накопленное —
материю И сущности; «сорванная лампа возрождается» — устранённая
недосказанность, не компромисс. Четыре оговорки — сами законы:

1. **Стабильный ID сущностей снимка** — entt-хэндл в сейв не едет никогда.
   Заделы: генерационный образец NpcHandle/NpcRef.gen; позиционный
   `OpenedContainerKey` (умирает с F).
2. **Restore НЕ сеет**: сидеры сущностей бегут ТОЛЬКО на generate; ветка
   restore берёт сущности из снимка. Развилка — `floor_stream.cpp`
   (ЗАКОНЫ→развилка→ПРАВИЛА; сидеры сейчас в «правилах» обеих веток —
   растащить). Дубли = главный риск, гейт обязателен.
3. **Restore завершается якорной пробой** всех якорей против восстановленной
   материи (та же `anchor_alive(w, a)`) — несовместимость снимков невозможна
   как состояние; что не выжило — честный детач первым тиком.
4. **Версия генерации модуля в снимке**: модуль изменился → снимок этажа
   инвалидируется целиком, полуслияние запрещено.

Что везти в снимок (POD-ами): пропы (PropId + якорь + слой + Interactable
state + PropLight slot перештампуется), контейнеры с инвентарём (ключ по
клетке умирает — ID), трупы (FormId пересборка уже есть в save.cpp:1039 —
решить: пересборка ИЛИ полный POD), лут на полу. Линки/CarriedBy транзиентны
(жнец), антураж — чистая функция (перебейк). Сейв-версия ++, миграция со
старых снимков = честная инвалидация (закон 4).

Гейты F: «сорви лампу → уйди → вернись: НЕ возродилась»; «поставь ящик,
набей, уйди-вернись: бит-в-бит»; «restore не сеет: счёт сущностей после
ревизита == после generate первого входа»; «якорная проба на restore роняет
вещь, чья опора выкарвлена в снимке»; смена версии модуля → перегенерация.
