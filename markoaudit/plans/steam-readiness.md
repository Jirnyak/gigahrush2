## ТРЕК A — материалы страницы (можно начинать сейчас, ядро почти не трогает)

### A1. Скриншоты — процедура работает уже сегодня

Проверено по коду: PNG-писатель (`src/render/screenshot.cpp`) корректен для
загрузки в Steam — CRC на каждый чанк, zlib stored-блоки, Adler-32, глубина 8,
truecolour, БЕЗ интерлейса. BGR↔RGB решается по формату свопчейна.

Разрешение снимка берётся из экстента свопчейна (`screenshot.cpp:123-125`), а НЕ
из `kWinW/kWinH`. Значит фулскрин даёт нативное разрешение дисплея — выше
требований Steam. Сверять по строке `[render] swapchain %ux%u`
(`vk_swapchain.cpp:54`).

**Ловушка, стоившая бы серии:** флаг `--no-hud` — ПУСТЫШКА. `showHud` по
умолчанию уже `false` (`main.cpp:2147`), а флаг присваивает ему `false` же
(`main.cpp:2166`), и относится он к дебаг-панели ImGui, а не к худу игрока. Худ
игрока снимается только через `gigahrush2.ui` рядом с бинарём или меню настроек:

```
fullscreen 1
crt 0
hud crosshair 0
hud health 0
hud needs 0
hud psi 0
hud hands 0
hud time 0
hud status 0
hud interact 0
hud alerts 0
```

Кадрирование: `--pos x y z` (метры), `--yaw/--pitch` (**радианы**), `--orbit`
(+0.015 рад/кадр). Ограничение: позиция и углы применяются ТОЛЬКО при стартовом
спавне на этаже 0 (`main.cpp:2624-2631`) — на других этажах кадр ловится
`--orbit`'ом и позой прибытия. Этажи с разным лицом: 4 (padic), 5 (blame),
6 (хрущи). `--frames` брать от 900: `--floor` срабатывает на кратных 420 кадрах.

Вес PNG без сжатия ≈ `w·h·3 + h`; 1920×1080 = 6.2 МБ. Прогонять `oxipng -o4`.

Запускать **из корня репозитория**, иначе текстуры молча не грузятся и мир
рендерится процедурным (`material_textures.cpp:36-41`, прецедент — `problems.md`
§«весь A/B-прогон на нетекстурированных скринах»).

### A2. Два дефекта снять ДО серии

1. **Кровь с чужого этажа на чистых стенах.** `SubField<StainRGB>` не чистится
   при переиспользовании слота этажа; генераторы чистят только `CellType`
   (`padic_gen.cpp:569`, `khrushi_gen.cpp:757`, `blame_gen.cpp:652`).
   `problems.md` §30. Прямой позор на стоп-кадре.
2. **Полурезный свет включён дефолтом вопреки решению владельца.**
   `CMakeLists.txt:358-360` даёт `-DGIGA_LIGHT_SAMPLED` безусловно; вердикт
   «это ручка настроек, а не дефолт» записан в `ddalight.md:72-77`. Симптом —
   квартальные тени и плоская нормаль во вторичном свете.

Остальное (бандинг, полосы §60, крестовой ореол блума, зелёный подмес CRT)
терпимо или лечится подбором ракурса.

### A3. Трейлер — снимать нечем, писать руками

Катсцен, полёта камеры по данным, реплея и записи видео в коде **нет вообще**
(грепом: `cutscene/cinematic/replay/keyframe/camera path` — ноль). Роадмап
обещает, что «катсцена-система сама снимет трейлер» — это фаза 4.1, до неё ещё

На этой неделе: OBS/запись экрана, куски по 5-15 с (лифт, бой, обрушение стены,
сирена самосбора, толпа), пролёты — консольным `noclip` + `mouselook`. Музыки в
проекте нет ни одного файла.

* заголовок окна — дев-строка `"gigahrush2 — voxel core"` (`main.cpp:2195`),

### A5. Тексты и анкета

**README для магазина использовать НЕЛЬЗЯ**: псевдонимы авторов «Klaus Schwab» и

### Windows: новость хорошая

Все **211 единиц трансляции** прогнаны синтаксическим чеком с виндовыми
предупреждениями. На 88 тысячах строк не соберутся **ровно две**:
`__builtin_popcountll` в `main.cpp:5622` и `tests/medium_test.cpp:309` (остальное
дерево давно на `std::popcount`). Ни POSIX-заголовков, ни VLA, ни интринсиков,
ни экзотики C++23, ни `setlocale` (то есть русская Windows не сломает `atof`).

Дерево **реально было зелёным на MSVC 2026-07-28** (`9af5b79c`); с той точки
влито 130 000 строк без единой проверки. Дисциплина слоёв держит: 54 000 строк
`src/game` физически не могут содержать платформенного кода.

Страшен не порт кода — страшны **паритет драйверов** (валидационные слои против
NVIDIA/AMD не запускались никогда) и **полное отсутствие дистрибуции**.

**Честная оценка:** до зелёного билда на Windows 4-7 человеко-дней (при наличии
машины); до играбельного — ещё 4-10; до дистрибутива win+mac — ещё 5-8; до CI с
артефактами — ещё 2-4. Итого **15-29 человеко-дней, реалистично ~20**.

## ЗВУК — фундамент лучше ожидаемого, проводка отключена

Бэкенд SDL3 кроссплатформенный, микшер на 32 голоса, лимитер честный (`tanh` на
мастер-шине), окклюзия субвоксельная, DSP покрыт тестами (385 строк
`suite_audio.inl`), **загрузчик WAV из `data/sounds.csv` написан и работает**.
Ломать нечего.

Но у аудио **ровно один вход из игры** — поле шумов. `play_3d` и `trigger_ui` не
вызываются ниоткуда; `EventBus` принимается в сигнатуре и глушится
`(void)bus;` (`audio_system.cpp:138`) — единственная из 29 глушилок в дереве без
строки оправдания. Молчат: лифт, разрушение, ближний бой, речь, ревун щитка,
амбиент на тип модуля (обе ручки — константы), UI целиком.

**Блокер композитора со сроком 29 сентября: весь тракт МОНО**
(`audio_system.cpp:238-239`) — стерео-пак схлопнется, музыка тоже. Плюс: только
WAV, один музыкальный трек на игру, десять слотов SFX без вариаций, а UI/сирену/
гейгер/амбиент композитор переопределить не может вовсе — `SampleBank` их не
знает.

Чинить ДО первого пака. Оценка до «демо-минимума по звуку»: 3-4 плотные сессии,
почти всё — проводка, а не DSP.

## СОСТОЯНИЕ КОДА — что НЕ надо чинить

Чтобы не тратить заходы на здоровое: **ноль TODO/FIXME/HACK, ноль
функций-заглушек, ноль `#if 0`, ноль закомментированных блоков ≥4 строк** во всём
дереве. Мёртвого API 31% против 36% на прошлом большом аудите — стало лучше.

Редактор биндов полный, с шестью тестами. Ввод на сканкодах — **WASD работает на
ЙЦУКЕН** (грабли, на которых спотыкается большинство инди).

**7558 строк из 9670**, и в нём живёт ~36% игровых правил (закон кражи внутри
тела ImGui-виджета, четыре вида мобов хардкодом мимо готовой `monster_traits.h`,
лифтовая машина, арбитраж рук). Все 34 подключённые системы имеют ровно одного
вызывающего — `main.cpp`. Файлы-адресаты для выноса уже существуют.
