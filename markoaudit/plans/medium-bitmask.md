## 0. Диагноз одним абзацем (почему фундаментально, а не патчами)

Кор-физика здорова: Марголус 8 фаз, материалы-параметры, вероятностные
рождение/смерть — не тронуть. Больна «нервная система» — LIVE-СПИСОК с
очередями пробуждений: (а) зомби-исполнители граничных блоков обязаны
жить в списке вечно (66% списка на сейве владельца — сухие); (б) сон —
свойство самопродления, а не состояния: часы тишины тикают только в
собственных исполнениях, и бюджет физики душит собственный сток — петля
«live↑ → p↓ → сон↓ → live↑» ДОКАЗАНА A/B (с бюджетом live растёт без
плато 1.4k→17k за 31 с; без бюджета — горб 23.9k и рассасывание);
(в) пробуждение — очередь с капами/переносами/фильтрами, которые
ошибаются (полнотвёрдый рабл невидим будильникам; повторно карвнутая
клетка получает один подтик — висяки); (г) обратный шов возит списки
окнами с фенсовой дисциплиной, которая по признанию кода — «ЛОЖЬ, GPU
отставал на 3-45 кадров», а «ретрай» не существует. Список — CPU-мышление
на GPU. Канон S16.3: «мы применяем GPU в том формате, который она
примет»; родной формат — плотный проход + битмаска.

## 1. Целевая архитектура

### 1.1 Битсет активности вместо списка

* `uActive` — 1 бит на клетку 128³ = 2 МБит = **256 КиБ**, GPU-буфер.
* `uQuiet` — часы тишины, 8 бит на клетку = 2 МиБ (хватит 5 бит, но байт
  адресуем атомарно парой And/Or как u16 пула; решить по месту).
* Активный счётчик `activeCount` — atomic при переходах бита 0→1/1→0
  (atomicOr/And возвращают old — переход виден точно). Он же —
  знаменатель бюджета вместо длины списка.
* **Пробуждение = atomicOr бита + обнуление часов.** Идемпотентно.
  Умирают: `wake_next`, `wake_face`, `run_inject`, вся CPU-очередь
  (`wakeQueue_`, `appendPending_`, `drain_wakes`, `kAppendCap`, перенос
  «wake carry», `WAKE CAP HIT`, `kListCap`), фильтры «кого будить»
  (ошибочный `masks().full()`-отсев — корень В2 — умирает вместе с самим
  вопросом: писатель ставит бит, не думая).

### 1.2 Плотный диспатч с ранним выходом

* Каждый подтик — диспатч по ВСЕМ 2М клеток (64 треда на клетку как
  сейчас? НЕТ — сначала 1 тред/клетка-гейт: читает биты, решает
  «исполнять», и только исполняемые разворачиваются). Две формы на выбор
  замером (инкремент 0):
  - А: плотный 2М-гейт → компактация исполняемых в indirect-диспатч
    рабочего пасса (компактация = маленький префикс-сум/atomic-append,
    но это ОДНОразовый на подтик список-однодневка без жизненного цикла
    — не возвращение старого списка: нет сна/пробуждений/переносов);
  - Б: плотный диспатч рабочего пасса напрямую с ранним выходом.
  Ожидание: гейт-пасс ~2М бит-чтений = десятки микросекунд; НЕ ГАДАТЬ —
  стенд меряет первым инкрементом.
* **Правило исполнения клетки: активна ОНА или любой из 7 «+»-соседей**
  (блоки minG-владельца тянутся в «+», материя +соседа лежит в наших
  блоках — сегодняшние зомби именно это эмулировали списком). Чтение
  8 бит — вместо удержания соседа в списке. Зомби умирают по построению
  (корень К1), «усыновление блоков» становится ненужным.
* Фазы/правила Марголуса (гравитация/скат/диффузия/истаивание,
  medium_sim.comp шаги 1-4) — БЕЗ ИЗМЕНЕНИЙ.

### 1.3 Сон — состояние; бюджет режет только физику

* Часы тишины судятся КАЖДЫЙ подтик у каждой активной клетки,
  НЕЗАВИСИМО от бюджета физики (инкремент байта дёшев; бюджет
  стохастический p = budget/activeCount применяется только к шагам
  материи). Петля К2 умирает: сток работает на полной скорости всегда.
* `kActChanged` (сброс часов чужой записью) — как сейчас, но на битсете.
* Порог сна kSleepSubsteps=16 — не меняется. Клетка засыпает → atomicAnd
  бита (+декремент счётчика). Проснувшаяся писателем — часы 0 (корень В1
  умирает: повторный карв даёт полные 16 подтиков).

### 1.4 Подвижная материя — GPU-резидентна; CPU канонит только статику

* CPU-канон: маски + типы + страницы СТАТИКИ (как сейчас). Подвижная
  материя (вода/газ/rubble_* в полёте и в кучах) живёт ТОЛЬКО в GPU-пуле
  страниц. Закон S16.3 «материя В ПОЛЁТЕ видна CPU с отставанием до
  кадра» уже принят владельцем — расширяется до «подвижная материя видна
  CPU агрегатами и снапшотами».
* НАЗАД едут: (а) агрегаты `medium_level` на клетку (как сейчас — HUD,
  плавучесть, дыхание, полевые цели AI); (б) **ПОЛНЫЙ СНАПШОТ-РИДБЕК** по
  редким событиям: сейв, выход с этажа, явный запрос (vkDeviceWaitIdle +
  копия пула; миллисекунды раз в минуты). Покадровый пак-шов с окнами,
  фенсами, гейтом свежести, подписями и несуществующим ретраем — УМИРАЕТ
  (корни всего класса «мешанина/стейл/воскресшие атомы»).
* ПИСАТЕЛИ: статики (карв твёрдого, дверь, конверсия судьи в rubble на
  CPU-страницах статики… ВНИМАНИЕ: конверсия рождает ПОДВИЖНОЕ — см.
  ниже) — CPU-канон + flush, как сейчас. Писатели ПОДВИЖНОГО (pour,
  эмиттеры, карв по куче, конверсия судьи) — ИНЖЕКТ-КОМАНДЫ в GPU
  (кольцевой командный буфер «записать материал M в атом/объём», GPU
  применяет в начале подтика; сид в команде — детерминизм сохранён).
  Карв кучи = инжект «воздух в сферу по подвижному» + CPU-статика как
  сейчас. Same-tick: выстрел в кучу песка получает дыру со следующего
  подтика (≤ кадр) — принятый лаг подвижного.
* Конверсия большого суда: вердикт снимает статику из CPU-канона
  (маски/страницы — как сейчас, support_gen растёт) и инжектит рождённый
  rubble в GPU. Кэш оправданий суда становится корректным ПО ПОСТРОЕНИЮ:
  опора — только статика (S20.5), статику двигают только CPU-писатели,
  которые ген растят (корень В4 умирает).
* Сейв/этаж: floor-файл v5 — секция подвижной материи из снапшота.
  Restore: статика в CPU-канон + подвижное инжектом в GPU + биты
  активности на все клетки с подвижным (умирает будильник этажа с его
  слепотой к рыхлому — корень В6).

### 1.5 Что осознанно НЕ меняется

Правила материи и их параметры (materials.csv), вероятностные законы
(carve_roll/pour/истаивание), агрегаты S16.4, рендер сред Бэром, закон
каденса («физика — функция номера подтика»), изотропия/тор/фрейм
гравитации, бюджет как закон (только знаменатель честнеет), малый и
большой судьи (только их пробуждение упрощается до битов).

  1. СХОДИМОСТЬ ПОД БЮДЖЕТОМ — стенд «сейв владельца»: большая вода +
     кучи; activeCount обязан выйти на плато и рассасываться ПРИ

     Мутация «правило +соседей выключено» — куча не падает вдоль границы
     (красная по другому гейту) ИЛИ activeCount хвост (красная тут).
  3. ВИСЯКИ: куча → сон → повторный карв половины → ни одного атома без
     опоры за N подтиков (детерминированный стенд корня В1/В2).
  4. ПЕРФ ПЛОТНОГО ГЕЙТА: стенд-замер цены 2М-гейта на пустом/типичном/
