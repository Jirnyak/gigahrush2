# Контейнер один, агностичный, якорный

Канон [CANON.md] S14, решения владельца 2026-08-20. Формулировка владельца: **«пропы это
пропы, а контейнер просто якорится к любому пропу агностично»**.

Это не эпик слияния, а **подключение** (исход №1): определение уже дано, остаётся привести
код. Сегодня одна система написана четырежды.

## Целевая модель

```
контейнер — КОМПОНЕНТ, якорится к носителю и не знает его:
    проп  (ящик, шкаф, сейф, стойка, станок)
    труп
    агент (рюкзак — тот же контейнер)
    клетка (тайник в стене)

ёмкость 64 у всех (решение владельца): один POD, байт-копия, ноль аллокаций
разреженность ВСТРОЕНА В ЯКОРЬ: контейнеров ровно столько, сколько создано
```

**Хранилище полем внутри пропа запрещено:** корневой кап пропов 131072 (`prop_pass.h:46`)
× 384 Б = 50 МБ буфера ради ~100 занятых записей. Контейнер — отдельная таблица со ссылкой
на носителя, как антураж к вокселю.

## Что удешевляет правку (уже готово)

1. **Ящик уже наполовину проп** — `container.cpp:357-358` вешает `SubVoxelAnchor` и
   `PropFallMode::SimpleFall`, то есть физика отрыва (`prop_system.cpp:265-300`) на него уже
   действует.
2. **UI уже абстрактен** — `InvUiSide` берёт `const ItemSlot* slots; int count`
   (`inventory_ui.h:52-56`), 526 строк виджета почти не трогаются.
3. **`inventory_give` уже канон** с 12 корректными call-site'ами.

## Что закрывается побочно

- **Коллизия ключа ящика 13 %** на Residential-этаж — измерена и задокументирована
  (`save.h:418-425`). `OpenedContainerKey` (ключ по этаж+макро-клетка) умирает, когда
  контейнер якорится к пропу с устойчивым id.
- **Потеря `condition`** в `loot_corpse_interact` (`loot.cpp:530-545`) — дюп-ремонт через
  обыск трупа.
- **Двойная структура** `Corpse`/`CorpseLootPending`.
- **Долг S3 «трупы → RagdollRoll»** — той же правкой (см. ниже).

## Труп → `RagdollRoll`-проп

Структурно ничто не мешает: `PropFallMode::RagdollRoll` существует (`prop_system.h:21`) и
обрабатывается (`prop_system.cpp:182-188`).

Сегодня `finalize_deaths` (`combat.cpp:530-646`) снимает `Velocity` (`:531`), плющит AABB
(`:538-542`), двигает `pos.y -= 0.45` (`:543-545`, **привилегированная ось, причём Y**) и
затемняет цвет (`:546-549`) — ровно «отдельная сущность со своей косметикой», которую S3
запрещает. Замена: три `emplace` вместо ручной геометрии.

Ломается: `CorpseRecord` пишет `pos/colour/half` (`save.cpp:826-832`) — при рагдолле нужна
ориентация либо согласие, что труп ложится заново при загрузке.

## Сделка — две стороны, сторона это НАБОР контейнеров

```
обыск ящика   А = игрок {рюкзак}   Б = {ящик}                     свободно
обыск трупа   А = игрок {рюкзак}   Б = {труп}                     свободно
свой склад    А = игрок {рюкзак}   Б = {свои контейнеры}          свободно
ТОРГОВЛЯ      А = игрок {рюкзак}   Б = торговец {рюкзак + склад}   бартер
```

`barter.{h,cpp}` — 262 строки, ядро (`move_marked`, `move_cash`, `slot_value`) работает
через `Inventory&` + `inventory_give` и **уже обобщаемо**. Мешают три предположения:
ровно два `Inventory&` (`barter.h:81-94`); маска `u64` жёстко = 64 слота
(`barter.cpp:107`); ящик и труп в бартер не попадают вообще — `main.cpp:5821-5850` идёт
мимо `barter_*` шестью лямбдами.

Правило «свободно» **уже выразимо данными**: `BarterTerms{0, 0}` даёт цену 0.

## Инкременты

**A. Контейнер как компонент + якорь.** Живёт рядом со старым, никто не переключён.
**B. Ящик → строка `props.csv` + контейнер.** Умирает `spawn_floor_containers` (77 строк),

**C. Труп → `RagdollRoll` + контейнер.** Закрывает S3.
**D. Сделка.** Шесть лямбд переноса → один примитив «сторона↔сторона», `barter` обобщается,
`loot_corpse_interact` (111 строк) умирает.
**E. Сериализация.** `kSaveVersion` 16→17, `kContainerRecWire` 27→327, `kCorpseRecWire`
81→…, `OpenedContainerKey` умирает. Политика формата — жёсткий отказ без миграций
(`save.h:125-127`), это осознанно.

## Гейты

1. **Ни одной второй реализации «добавить»** — грепом: закон `stackMax` встречается ровно в
   `inventory_give`.
2. **`condition` переживает круг** «сумка → ящик → труп → сумка» — сегодня падает.
3. **Носитель не влияет на операцию**: один тест гоняет одинаковый сценарий на четырёх
   якорях (проп, труп, агент, клетка) и требует идентичного результата.
4. Оракул сериализации: сохранить → загрузить → побитовое равенство содержимого.
