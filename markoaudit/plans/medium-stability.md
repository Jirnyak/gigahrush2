# СТАБИЛИЗАЦИЯ МИРА-АВТОМАТА — свод разведки 2026-09-01

Приказ владельца: «кор-идея отличная — полируем и ищем баги». Три read-only
разведки по gpu_medium_pass/medium_sim/destruct/voxel_mirror/main; КОД НЕ
ТРОНУТ. Все адреса перепроверяемы. Симптомы плейтеста: (1) прогрессирующее
замедление обрушений; (2) висячие субвоксели после повторного карва кучи.

## КОРНИ СИМПТОМА 1 — «каждый следующий слом медленнее»

* **К1. Вечные зомби-остатки на каждую кучу.** Осевшая куча оставляет 2–8
  вечно живых клеток (−исполнители граничных блоков Марголуса; их держит
  безусловный face-пуш settle:538-543). Это МНОЖЕСТВО без стока: N
  обрушений → N×(2–8) клеток навсегда (сток один — clear_live на смене
  этажа, main:4169). total растёт лесенкой → p = budget/total падает →
  весь этаж замедляется. Запинено моим же тестом как «принятый хвост»
  (medium_test test_rubble_settles_fast: live 2/2/2 стабильно).
* **К2. Петля live↑ → p↓ → сон↓ → live↑.** Часы тишины замерзают у
  неисполненных (settle:439-446), время до сна = 16·total/budget подтиков,
  а чужие kActChanged копятся и обнуляют часы в первый же ход. Сток
  (усыпление) ≤ budget/16 клеток/подтик и от total НЕ зависит; источники —
  до 10 пушей на исполненную клетку. Механизма сокращения списка под
  нагрузкой нет. Второй порядок: замороженная клетка не делает face-пуши →
  −сосед-исполнитель выпадает → падение вдоль стен идёт скважностью ~p².
* **К3. Помпа вердикта покадровая при потиковом суде.** Суд конвертирует
  512 узлов/ТИК (до 8 тиков/кадр на хитче — суд разгоняется на лагах), а
  drain_wakes дренит ~1170 источников/КАДР (kAppendCap/7). Хрущёвка: до
  350k аппендов против 70k/с при 60 fps (35k/с при 30) — бэклог растёт
  именно на обрушении; темп снова зависит от fps; ЛИФТ ждёт эту очередь
  (main:3823 wakes_pending) — обрушение на этаже прибытия = запертая
  кабина.
* Усилители: wake_cells снимает frontierDone записанной клетки → на
  обрушении возвращаются ~2.6M проб фронтира/кадр; open_frontier R=6
  монотонно плодит страницы воздуха → каждый следующий флеш дороже.

## КОРНИ СИМПТОМА 2 — «висячие субвоксели после повторного карва»

* **В1 (главный). Пробуждение не сбрасывает часы тишины.** wake_next
  ставит только kActInList; quiet обнуляет ТОЛЬКО реальный своп. Клетка
  осевшей кучи имеет quiet ≥ 16 → любой CPU-инжект (повторный карв!) даёт
  ей РОВНО ОДИН подтик: move → settle видит quiet=17 → вылет из списка
  БЕЗ face-пушей. А атом НИЖНЕГО СЛОЯ (L=0) может упасть только если
  (а) подтик нечётной фазы off=1 И (б) жив −сосед-владелец пары {−1,0}.
  При чётной фазе он неподвижен абсолютно → ~50% повторных карвов обязаны
  оставлять нижний слой висеть. Свежий рабл первого слома рождается с
  quiet=0 и живёт полные 16 подтиков — вот почему «первый раз идеально».
* **В2. Полнотвёрдая рыхлая клетка невидима будильникам.** wake_cells:306,
  touch:326, open_frontier:101 фильтруют masks().full() («под маской
  двигать нечего») — но rubble_* полномасочен И подвижен (flow 1.0).
  Клетка, целиком забитая рыхлым, не будится и не пейджится НИЧЕМ;
  её L=0 уронит только живой −сосед, которого держит только она сама.
* **В3. Однородная рыхлая клетка теряет страницу.** set_sub_material:781
  → collapse_if_uniform → drop_page: CellType=rubble_*, полная маска,
  writable=false → вечный монолит, разбиваемый только прямым карвом.
* **В4. Кэш оправданий суда слеп к ходу автомата.** support_gen растят
  только CPU-писатели; автомат унёс опору → оправданный регион не
  пересуживается никогда, идущее дело не признаётся грязным
  (destruct:1072-1187, 1271). «Первый обвал идеален, второй — нет».
* **В5. Сон быстрее доставки.** Порог сна 16 подтиков ≈ 2–8 кадров;
  страница/инжект в бэклоге едут дольше → клетка засыпает об
  недоставленную цель и (по В1) невоскресима. Отягчение: конверсия суда
  меняет материал БЕЗ маски — клетка остаётся full() → В2.
* **В6. Рыхлое не поднимается будильником этажа.** medium_recount считает
  только Liquid/Gas → medium_level рыхлой клетки = 0 → main:4188 её не
  будит; судья висячее рыхлое не судит по построению (S20.5). Висяки
  переживают смену этажа и сейв.
* **В7. Stain-грязь без пробуждения** (main:8935): страница клетки
  откатывается зеркалом, wake нет.
* **Шов:** «ретрай непринятого региона» — НЕ ВЫПОЛНЯЕТСЯ кодом (регион
  переписывается тем же кадром, apply/record делят rbGen_ % 3); kRbRegions
  = 3 даёт нулевой запас; гейт свежести систематически выбивает область
  активного писателя → CPU-канон отстаёт именно там, где обрушение.
  Признание в коде: «фенсовый счёт — ЛОЖЬ, GPU отставал на 3-45 кадров».
* CPU→GPU: voxel_mirror:461 безусловно заливает CPU-страницу грязной
  клетки — откат GPU-состояния назад; LIFO-переиспользование слота пула +
  сортированное окно флеша даёт окно «два pageIdx в один слот» (мешанина).

## КАНДИДАТЫ ЛЕЧЕНИЯ (обсудить с владельцем, порядок — по силе/цене)

1. **Инжект гасит часы тишины** (run_inject ставит kActChanged или чистит
   quiet): «писательское пробуждение = часы с нуля». Одна строка закона;
   лечит В1 (клетка живёт полные 16 подтиков после карва). ДЕШЕВО.
2. **Фильтр full() → «полнотвёрдое НЕПОДВИЖНОЙ материи»**: предикат из
   существующего материала (bears_load/flow==0 — законы S16.5/S20.5, не
   новая ветка) в wake_cells/touch/open_frontier; лечит В2+В5-хвост.
3. **Не схлопывать страницу подвижного материала** (collapse_if_uniform
   учитывает фазу/флоу) — лечит В3.
4. **support_gen растёт от применения шва** (ход автомата = писатель
   опоры) — лечит В4; цена: пересуды чаще (кэш регионный, переживёт).
5. **Усыновление блоков полнотвёрдого владельца** (записанный §63-хвост,
   problems.md:3380): полнотвёрдый minG → блок исполняет +сосед; убивает
   К1 в корне (зомби-остаток кучи → 0), live горба ÷3-4. СРЕДНЕ/КРУПНО.
6. **Помпа вердикта на сим-тики + кап порций суда на кадр** — лечит К3.
7. **Будильник этажа видит рыхлое** (medium_recount или отдельный
   предикат подвижного solid) — лечит В6 (висяки не переживают загрузку).
8. Stain-грязь будит (В7); честный ретрай регионов шва или смерть прозы.
9. К2 (петля) — частично лечится 1+5 (меньше live), остальное — вопрос
   владельцу: нужен ли механизм сокращения списка под нагрузкой.
