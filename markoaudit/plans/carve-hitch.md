## Вердикт замера (лог владельца, carve_log.txt, 7 карвов)

**Карв-путь чист: худший `[carve] total` = 4.56 мс.** Максимумы по
компонентам: antr 2.86, prop_skin 0.71, anchor 0.64, lgrid 0.26, sphere
0.11, patch 0.04, mirror_mark 0.03, vis 0.02, mirror_flush 0.01, diff 0.00,
unmeasured 0.00. Все пять подозреваемых списка оправданы числом:

1. `bake_material_lights` — ветка ни разу не сработала (на этаже 0 НОЛЬ
   светоматериалов: `[lights] baked 0 emitters in 0.8 ms` — весь скан 0.8 мс).
2. Свап видимости света — `light_swap upload` 13.6 мс на входе, 1.6–3.0 мс
   дальше. Не хитч.
3. Проп-скин — 0.5–0.7 мс на ребилд. 4. Зеркало — метки ≤0.03, flush ≤0.01.
5. Диффузия — 0.00.

**Реальный ~1.1 с хитч — это `[lightvis] floor 0 FRESH: 12646 lamps ->
262140 lit cells ... 1144 ms sync`** — синхронный Fresh-бейк видимости света
НА ВХОДЕ НА ЭТАЖ, главный поток, внутри `start_fresh` ([game/rebake.h]).
Приёмка «хитч 0.1–0.3 с принят владельцем» стояла на ложной цене — реальная
1144 мс. Число один в один совпадает с хитчем ~1.1 с из памяти светового
эпика (light-vis-built): хитч всегда был про вход на этаж, не про карв.

Фоновый цикл честен: каждая пачка карвов → lightvis rebake 1.8–2.0 с @ 6
потоков + rooms/coarse/fine 0.5 с, всё в фоне, свапы по готовности (gen 1–7
за сессию).

Инкремент 2 (кандидат, решение владельца): унести Fresh-свет из
синхронного `start_fresh` в воркер тем же приёмом, что Rebake — первые ~2 с
этажа свет живёт без бейка видимости (прямой свет без запечённых теней),
свап по готовности. Цена: короткая «сырость» света на входе. Альтернатива —
принять 1.1 с на входе осознанно и закрыть эпик.

## Инкремент 1б ПОСАЖЕН: детектор хитча (владелец: «не знаю, может GPU»)

Владелец не смог назвать, ГДЕ чувствует хитч — значит, ощущение больше не
источник данных. Детектор в топе кадра (`src/app/main.cpp`, рядом с
wall-кольцом): любой кадр дольше порога печатает

    [hitch] frame X ms | carve A, light_swap B, prop_skin C, entry 0/1 |
            gpu peak F ms: lgrid, vflush, cull, simphys, world, bodies,
            props, drawphys, hud (dropped N)

- Порог ВЫВЕДЕН: ~3 vsync-периода = 50 мс при 60 Гц (заметно глазу);
  `GIGA_HITCH_MS` переопределяет.
- CPU-виновник — виден метками кадра (FrameMark: карв/свап света/проп-мерж/
  вход на этаж). GPU-виновник — длинный кадр при ПУСТЫХ метках; проход
  называют пики GPU-таймера (окно 31 кадр — спайк доезжает строкой-двумя
  позже; растущий dropped = цифрам не верить).
- Владелец просто играет с редиректом stderr; каждый почувствованный затык
  обязан оставить строку — сопоставляем ощущение с логом.

## ВЕРДИКТ 2 (hitch_log.txt, 2026-08-21): виновник пойман — GPU-фоллбэк грязных клеток света

Владелец воспроизвёл: chain_ball в светлой комнате, карв потолка → 60→20
fps, повторяемо; карв лампы — то же. Детектор поймал: `[hitch] frame 61/51
ms | все CPU-метки 0.00 | gpu peak 41.8 ms` — **чистый GPU** (на MoltenVK
пер-проходному сплиту не верить — gpu_timer.h; фрейм-тотал точен: 42 мс
против ~14 мс фона).

Механика (подтверждена `shaders/light_grid.comp:169-193`): карв метит
грязным ШАР R_max=24 м (до ~15k клеток) вокруг каждой карвнутой клетки;
грязная воркгруппа падает с запечённого списка (в среднем 10.6 ламп) на
**полный дистанционный биннинг по всей статик-таблице — 12646 ламп** («все
лампы радиуса», железный инвариант (б) владельца) + до 30 теневых маршей на
пиксель вместо ~10. Окно грязноты = дебаунс 256 тиков (2.05 с) + полный
lightvis-ребейк 1.79 с = **~4 с @ 20 fps после каждого карва возле света**,
затем свап поднимает genBaked и fps возвращается (тайминги в логе: карв
:824 → hitch :838 → свап gen 1 :858, ровно по этой арифметике).

chain_ball невиновен (antr 1.1 мс) — он лишь заставил карвить потолок в
светлой комнате. Оба репро владельца — один виновник: свет + карв.

Кандидат инкремента 3 — ЧАСТИЧНАЯ перепечка света: воркер печёт видимость
ТОЛЬКО грязных клеток (CPU и так знает список — for_each_dirty_light_cell).
Вывод цены: полный бейк 262140 клеток = 1790 мс @ 6 потоков → 6.8 мкс/клетка
→ грязный шар ~15k клеток ≈ **100 мс** вместо 1.8 с; заливка на GPU — только
изменённые клетки (вместо полной, 42 мс на входе). Окно 4 с → ~2.2 с (дебаунс
остаётся) или меньше, если дебаунс секции света ужать. Полный бейк остаётся
на своём расписании. Инвариант (б) цел: фоллбэк не трогаем, ужимаем ОКНО.

Второй хвост (отдельно): Fresh-бейк света 1044-1144 мс синхронно на входе
этажа + заливка 42 мс (кадр входа ~1 с). Решение владельца: уносить в воркер
(первые ~2 с этаж «сырой» по свету) или принять цену входа осознанно.

## Что посажено (инкремент 1, только замер)

`CarveTiming g_carveT` в `src/app/main.cpp` (рядом с `g_worldGen`): компоненты
копятся за кадр на ОБОИХ карв-сайтах (консоль + боевой дренаж), строка
печатается в хвосте кадра после `voxelMirror.flush()` — когда известны и
prop_skin, и цена стейджинга:

    [carve] total X ms (N cells): light_mat, vis, prop_skin, mirror_mark,
            mirror_flush, lgrid, sphere, diff, patch, anchor, antr, part,
            unmeasured

- `unmeasured` = скобка всего сайта минус Σ компонентов — если хитч там,
  меряли не то.
- `lgrid` (collect_scene_lights+update_and_dispatch) и `mirror_flush` идут
  каждый кадр — на кадре карва интересен их ВСПЛЕСК над фоновым уровнем.
- Отдельная строка `[carve] light_swap upload X ms (gen N)` — цена GPU-свапа
  бейка видимости на ЕГО кадре (кадр свапа ≠ кадр карва, фон).

Владелец: carve в игре БЕЗ цепей и С цепями (и выстрелом в светоматериал —
ветка light_mat живёт только на relight), принести строки [carve]. Чинить —
только после чисел.

2. Свап/перепечка видимости света (light_vis_bake) — «свет первым в
   очереди», но сам свап и его триггер на карве не замерены.
3. Перестройка проп-скина (`propPassNeedsRebuild` после detach/anchor_validate).
4. Залив воксель-зеркала (VoxelMirror mark_dirty — «инкрементален», проверить).
5. `diffusion_mark_cell` O(1) существует и имеет 0 вызовов — диффузия

## Метод (закон дома: мерь то, на что смотрит владелец)

Инкремент 1 — ТОЛЬКО измерение: покомпонентные тайминг-принты `[carve]` на
всём карв-пути (каждый подозреваемый — своя строка, мс, печатается каждый
карв). Владелец делает carve в игре БЕЗ цепей и С цепями — числа называют
виновника. НИКАКИХ починок до чисел: сигнал, совпадающий с известным
паттерном, может иметь другую причину.

Инкремент 2+ — виновника в существующий воркер RebakeScheduler (не новый
механизм!), свап по готовности, устаревание на секунды — норма (S9).

## Гейты

- Тесты SLA — в сим-тиках, headless, без wall-clock (решение владельца).
- Число печатается каждый прогон (`[carve] total X ms: light_mat A, vis B,
  prop_skin C, mirror D`) — регрессия видна числом, не ощущением.
- Обе полярности: после фикса карв С хитчем в замере обязан исчезнуть, а
  запечённое — реально обновиться (свет в выкарванной дыре меняется).
