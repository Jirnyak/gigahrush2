# Позвоночник сюжета — сюжетные NPC, квесты, дневники, катсцены

Решения владельца 2026-08-26 (диалог; реф — `/Users/jirnyak/Mirror/gigahrush`
«первая часть и прототип: берём однозначно лучшее, остальное делаем ещё
лучше и сразу по уму»). Статус: ПЛАН, кода нет. Кандидат на канонизацию
(S17) при старте эпика.

## Рамка

Сюжет ЛИНЕЙНЫЙ (авторская цепочка), но истина одна — **макро-алайф на
миллион** (S6). Сюжетный NPC — обычная запись пула с битом и PlotId:
ест, спит, торгует и боится ТЕМ ЖЕ скором (S13, ни одной ветки «если
сюжетный» в выборе цели). Игрок в игре не отличит сюжетного от
процедурного — у сюжетных просто анкеты прописаны заранее.

## 1. Анкеты — единая таблица, НЕ модули этажей

- `plot_npcs.csv` + кодоген по образцу materials/props (единый закон
  данных; формат опционально расширяем — решение владельца). Колонки:
  slug, PlotId, имя, рост/пол, фракция, характер (те же 8 слотов
  атрибутов, что у всех — S7), стартовый инвентарь строками item-slug,
  якорь: ТЕГ комнаты + этаж приписки, диалоговый ключ.
- **PlotId — замороженная таблица**, резолв при регистрации, не
  счётчиком. Урок рефа (quests.md «заморозка слотов»): счётчик заморозил
  32 поля у 30 квестов в undefined — TALK-квесты не предлагались вовсе.
- Сидер генезиса пишет сюжетных в пул ПЕРВЫМИ, остальной миллион —
  после. Дальше запись живёт как все (позиция, инвентарь, смерть — в
  пуле; S7: игрок такая же запись).

## 2. Модули этажей — чистые редакторы (S10)

Модуль НЕ знает сюжета. Анкета требует «комната с тегом `yakov_lab` на
этаже N» — модуль при генерации объявляет комнату с тегом (свободные
теги — канон S12.2) и не знает, кто придёт. Связывает воплотитель через
персистентные якоря (S13.8). Модуль тега не дал — ГРОМКАЯ жалоба, не
молчаливая дыра. Модули друг о друге не знают; весь сюжет/лор/динамика —
через единую таблицу макро-алайфа.

## 3. Квест-движок — данные + существующие каналы

- Шаг квеста = строка таблицы (`quests.csv` + кодоген): глагол
  (TALK/FETCH/KILL/VISIT/DELIVER/ESCORT...), цель ТОЛЬКО стабильными id
  (PlotId / item-slug / тег комнаты / фракция; сравнение по
  display-имени запрещено — реф запрещает, мы наследуем), что впрыснуть,
  событие завершения — существующий event_bus.
- По канону S13.2 квест **впрыскивает спрос и связь, приказов нет**:
  квестового NPC может перехватить мир, и это правильно.
- Состояние = ПРЕДМЕТЫ и факты мира, не скрытые флаги: «принёс
  документ» — документ лежит в нужном инвентаре, и точка. Ручной сюжет
  и процедурные задания — ОДИН язык и один движок.
- Позвоночник = та же таблица, шаги связаны цепочкой (реф: от туториала
  через природу Самосбора к финалу — структура годная, контент наш).

## 4. Смерть и дневники — «любой квест проходим»

- **Смертность сюжетных: только на АКТИВНОМ этаже, от настоящих событий**
  (бой при воплощении, самосбор). Макро-СТАТИСТИКА (болезни/убыль
  числами) сюжетных НЕ трогает — иначе сюжет рвёт невидимая арифметика.
  Фоновой смерти нет вовсе (решение владельца: «не стоит полагаться на
  фоновую систему, это слишком сложно»).
- Тихих респавнов квестгиверов НЕТ. Смерть = consequence, но цепочка
  живёт: **дневник** — NOTE-предмет с PlotId в данных, падает в обычный
  дроп (труп = RagdollRoll-проп с контейнером, S14 готов). Дневник в
  рюкзаке «говорит за покойного»: шаги становятся giverless, TALK
  закрывается чтением, FETCH/KILL — без сдачи.
- **Дневник роняет ЛЮБОЙ участник квеста**, не только сюжетные (решение
  владельца): закон — у каждого шага есть путь завершения при смерти
  любого его участника.
- ЛУЧШЕ рефа: у рефа был лимит сейва → машинерия ре-воплощения дневника
  на месте смерти + анти-дюп сканом. У нас **сейв = полный шот этажа**
  (S8): предметы не исчезают ВООБЩЕ, дневник просто лежит где упал —
  вся ре-материализация не нужна по построению. (Бюджет S8 ~10 ГБ —
  следить.)

## 5. Катсцены — система повествования ВСЕГО

Камера уже канонически отвязана от игрока (S7: «надевается» и может
свободно летать). Катсцена = данные (маршрут полёта + тайминги + куда
вернуться), не скрипт в main:

- влёт на новый этаж: камера летит к сцене и возвращается в тело
  (Doom-3-стиль; проверено в первой части — «круто»);
- тот же примитив для сюжетных бит, финала, показа самосбора.
Мир при катсцене ЖИВЁТ (изотропия к игроку, S7) — сцена снимает живую
симуляцию, не декорацию.

## 6. Порядок работ

Квестам нужны RoomId и теги → **сначала К3-комнаты** (rooms-3d.md:
боксы, roomAt, теги, вектор предложения) → якоря сюжетных → квест-движок
→ дневники → контент позвоночника. Катсцены — параллельно (камера
отвязана уже). Всё после конца стабилизации ядра
(core-stabilization.md — мораторий).

## Чего НЕ делаем (анти-уроки рефа)

- Сравнения по display-имени, room по имени — только id/теги.
- Логика контента в main — всё через registries/таблицы.
- Ре-воплощение предметов — не нужно при полном шоте этажа.
- Фоновая смерть сюжетных — не полагаться на фоновую систему.
- Приказ, обходящий сумму выбора цели (S13.9) — и для квестов тоже.
