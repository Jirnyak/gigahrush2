# ДВЕ РУКИ — универсальные слоты ЛКМ/ПКМ, верб решает тип предмета

**Статус: ПЛАН + инкремент 1 ПОСАЖЕН (825c17a7). Записан 2026-08-31 со слов
владельца, обсуждение живое — сверять до каждого инкремента.**

## Замысел (слова владельца, 2026-08-31)

«Два слота у NPC/игрока в инвентаре и ПКМ/ЛКМ — по сути и смыслу ДВЕ РУКИ.
Он уже что угодно может класть в каждый слот, и оно работает через свою
систему — какого оно типа. Игрок положил гранату в ПКМ, а пистолет в ЛКМ:
на ПКМ кидается граната, на ЛКМ выстрел; а если фонарик на ЛКМ — светится
фонарик. Универсально расширяемо, потом всё там. И бесплатно эмерджентно:
проп можно брать, только если свободен один из слотов, — и он занимает
руку.»

Страх владельца (закрыть по построению): «вдруг нахардкодим». Ответ: верб
диспатчится ТАБЛИЦАМИ, не switch по именам — типы уже данные:
- огнестрел = строка weapons_ranged.csv → «стрелять»;
- метательное = ranged_is_thrown (предмет — сам себе боеприпас) → «бросить»;
- холодное = weapons_melee.csv → «ударить»;
- используемое = UseEffect → «применить»;
- светящее = свет-колонки items.csv (light_radius/intensity УЖЕ есть) →
  «светить» (верб инкремента 3).
Новый тип предмета = строки CSV, ни одной ветки в диспатче.

## Что уже есть (не строить второе, S11)

- Equipped 4 байта: weapon (становится рукой ЛКМ) / armor / tool /
  свободный байт (станет рукой ПКМ). Валидация «слот протух → нет решения»
  прикрывает и старые сейвы (фантомный 0 отсеивается по def предмета).
- «Одна пара рук» уже закон: player_ranged_step и player_throw_step делят
  один cooldownMs. Для двух рук: кулдаун ОБЩИЙ или на руку? (вопрос 2).
- Переноска пропов: CarriedBy + бросок с наследованием скорости
  (рагдолл-эпик, инкремент 9) — «проп занимает руку» сшивается с ней.
- NPC-решатель: ai_equip_step уже решает слоты по своим проходам.
- Zажим-взгляд с ПКМ ВЫРЕЗАН (приказ 2026-08-31, 825c17a7); взгляд — Tab.

### 2. ПКМ-рука — ПОСАЖЕН (9b3cd196)
Решения владельца вписаны: руки НЕЗАВИСИМЫ (свой throwCooldownMs, старый

Приёмка владельцем: ствол ЛКМ + граната ПКМ — очередь и бросок
одновременно.

### 2-старое. ПКМ-рука (исходный план)

- Input: rmbHeld → тот же верб-диспатч, что ЛКМ (одна функция на руку —
  параметр, не копия).
- Console: `equip <слот> lmb|rmb`, UI сетки — выбор руки при Equip.
- ai_equip_step: решает обе руки (ствол + граната — уже осмысленно).
- Гейты: расширение test_grenade на вторую руку (пистолет ЛКМ + граната
  ПКМ — оба верба работают, кулдаун-политика по решению вопроса 2).

### 3-старое. Верб «светить»: фонарик
Предмет со свет-колонками в руке = динамический источник на теле
(механизм динамического света есть — бакеты 16³). Налобник S5 мёртв —
фонарик В РУКЕ ему не противоречит: рука занята, свет честный.
Гейт: свет от предмета в руке виден light-гридом headless.

### 4. Проп занимает руку (эмерджентность владельца)
Взять проп можно только со свободной рукой; CarriedBy пишет номер руки;
верб занятой пропом руки = «бросить проп» (существующий бросок переноски).
Следствия бесплатно: с ящиком в обеих руках не стреляешь; бочка = ПКМ.
Гейт: pickup отказывает при двух занятых руках; бросок освобождает.
