# Комната как ОБЪЕКТ — фундамент под S12/S13/S14/S19

**ЭПИК ЗАКРЫТ 2026-08-28: все шесть инкрементов A–F посажены за один день**
(коммиты f58297c0 A+B+C, 436b65b5 D, 08ea2aad E, F — финальный). Комнаты =
раскраска клеток 128³ настоящими зонами модулей; старая решёточная таксономия
умерла целиком с грепным гейтом. Хвосты, УЕХАВШИЕ по решению владельца:
якоря (ModuleId, RoomId) + комнатная наводка интентов + реальное потребление —
эпик agent-goals (яма поведения до него принята владельцем: «ядро важнее»);
слагаемые СРЕДА/ФОРМА/НАРОД supply — со своими системами; RoomRep — с
witness-system (предложение: вектор по глаголам деяний с выцветанием).

Канон [CANON.md] S12 + уточнения владельца 2026-08-28 (записаны в S12.1). План переписан
2026-08-28 при старте эпика: все отложенные вопросы закрыты владельцем, добавлена разведка
референса `../gigahrush` (отчёт сверен с его кодом), эпик слит с `verbs-table.md` — шли

**Почему это первый эпик.** Комнаты не существует как вещи: хеш-колонны без z, 11 битов
«вида», вторая навигация flow-полями, белые списки вместо глаголов. Пока нет `RoomId` —
мертворождены: вектор предложения (S12.4), запас (S12.5), владелец (S14.3), репутация
(S13.6), свидетельство S19 (нужны `roomAt` + владелец + уместность), честный выбор целей
S13, сюжет (plot-spine: «сначала К3-комнаты»).

## Решения владельца 2026-08-28 (все развилки закрыты)

1. **`roomAt` — плоский u16 на клетку**, 4 МиБ на резидентный этаж. Вопрос
   «ещё подумаю» закрыт: платим. На балансе −18 МиБ (умирают 11 полей по 2 МиБ).
2. **Жизненный цикл — закон масок S18.** Декларация перештамповывается на generate И
   restore, в сейве только накопленное (репутация; владелец — если сменился).
   `roomAt` штампуется ОДИН раз на входе, в `RebakeScheduler` ему делать нечего —
   допекание нужно вектору предложения (СРЕДА/ФОРМА меняются карвом), не границам.
3. **Квартиры не существует.** Комната = элемент соц-алайф-мира; «квартира» —
   эмерджентность соседних комнат. У хрущей каждая BSP-комната — отдельная комната.
4. **Комната = ЗОНА, агностичная к геометрии.** О стенах не думаем вовсе: стены
   эмерджентны (1 субвоксель или 3 клетки — не константа). Модуль объявляет объёмы;
   гейт непересечения — про объявленные зоны.
5. **Ссылки контента: теги-биты + псевдонимы модуля.** u16 tags — глобальный словарь
   КЛАССОВ (hermetic, nest…); конкретная авторская комната — таблица псевдонимов у
   МОДУЛЯ (alias → RoomId) + assert «объявленное вырыто» после генерации.
6. **Спавн-политика — полностью в модуле** (S10). `MobDef::roomMask` /
   `ItemDef::roomMask` умирают без замены в общем коде.
7. **Якоря агентов — (ModuleId, RoomId)**, межэтажные (S13.8), раздаются при заселении
   по declared-вектору и вместимости: дом — «спать», работа — «работать», семья —
   общий якорь дома. Маски homeRooms/workRooms умирают.
8. **Скоуп: rooms-object + verbs-table одним эпиком.** Room рождается сразу с
   `declared[K]`/`supply[K]`, K из `verbs.csv`.

## Целевая модель

```
struct Room {                       // объявляет модуль этажа при генерации (S10, S12.1)
    RoomId    id;                   // u16, локален этажу; порядок объявления детерминирован
    Box       boxes[N];             // 3D-ЗОНЫ в клетках; композиция под одним id
    u16       tags;                 // классы: hermetic, nest, …  (глобальный словарь)
    u16       owner;                // NPC или фракция (S14.3); стартового даёт модуль
    i16       declared[K];          // неразрушимая часть предложения (S12.4)
    i16       supply[K];            // кэш: оснащение + запас + среда + форма + народ
    RoomRep   reputation;           // одна запись, с выцветанием (S13.6) — сейвится
};

roomAt[cell] : u16                  // 128³ × 2 Б = 4 МиБ; штамп на входе, не в допекании
модуль → таблица псевдонимов: alias → RoomId  (+ assert после генерации)
якорь агента: (ModuleId, RoomId)   // межэтажный, переживает выгрузку (S13.8)
```

`roomAt[]` — единственный шов: в какой комнате агент / чей контейнер / куда упал труп /
какая комната у клетки карва / собственник места для свидетеля S19.

## Инкременты (verbs-table слит сюда; детали таблиц — в verbs-table.md)

**A. `verbs.csv` + кодоген + `verb_table.h`.** Словарь + терпение, ноль потребителей.
Гейт: K не встречается литералом; дубль id — ошибка генерации. Калибровка — перенос
из референса (`room_affordances.ts`: 15 строк, шкала 8..40, отрицательные законны;
терпение `NPC_UTILITY_INTENT_PATIENCE` + порог `58 + p·42`).

**B. `Room` + store этажа + `roomAt` + API объявления.** Модуль объявляет зоны
(боксы+теги+declared+владелец+псевдонимы) на generate И restore (закон масок S18);
временный мост из сегодняшней решётки, чтобы старое жило рядом. Гейты: изотропия
(поворот объявления x↔y↔z → идентичный roomAt), ни клетки в двух зонах, ни комнаты
без клеток, RoomId бит-в-бит между двумя генерациями.

**C. Модули объявляют по-настоящему.** Падик отдаёт BSP (`padic_gen.cpp:171` — vector
уже собран и умирает), хрущи отдают BSP квартир (`stamp_section_flats`), blame — свой
минимум. Assert псевдонимов. Гейт: каждый модуль объявляет ≥ 1 комнату, мост из решётки
умирает.

**D. Столбцы `props.csv`/`items.csv` + supply-кэш.** Инкрементально по событию (предмет
лёг/взят, проп умер, среда ребейком). Гейт: полный пересчёт и инкрементальный — побитово
одинаковы (оракул, как walk_bits). `нажива` у предметов выводится из цены (S11).

**E. Потребители переезжают.** По одному, каждый с зелёным ctest: гермозона → тег
(`door.cpp:91`), контейнеры (`container.cpp:350`), спавн мобов/лута → политика модуля
(`mob_spawn.cpp:340`, `item_table.cpp`), якоря по вектору вместо homeRooms/workRooms
(`role.h`, `ai.cpp:887`). Гейт: `floor_room_mask` теряет всех вызывающих.

**F. Смерть старого.** `floor_room_mask`, `floor_room_stride`, `floor_room_bit_index`,
`RoomBit`, `flow[11]`, `nearRoom[11]`, `bake_near`, `bake_flow`, `room_route`,
`kRoomAffordance`, `kRoomRecovery`, `MobDef/ItemDef::roomMask`, вторая решётка
`population.cpp:22-32`. Замер: пиковая память этажа −~18 МиБ. Грепный гейт в
`check_source_rules.cmake`, мутация в обе полярности ([[cmake-text-gate-traps]]).

## Разведка референса `../gigahrush` (2026-08-28, сверено с его кодом)

Реф пришёл к той же модели независимо и оставил документированные грабли. **Берём:**

- `roomAt` плоским массивом (их `roomMap: Int16Array`, O(1), ~40 потребителей) —
  совпало с решением владельца; источник истины — карта, не AABB.
- Доказательство «нулевой строки»: SHOP/BAR/MARKET добавлены без единой подсистемы —
  строками аффордансов; ноль в `store` сам сделал их адресами доставки.
- Точка внутри комнаты — R2-последовательность от id актора (центр = аттрактор).
- Забитость вместо очереди: перепись раз в 0.5 с, вместимость из площади, штраф
  `толпа/вместимость`. Ничья: интерес → расстояние → джиттер личности (не id!).
- Инвалидация индекса по фактам мира (указатель+длина+версия), не по флагу грязи.
- Радиусный запрос возвращает надмножество, точную дистанцию считает вызывающий.
- `named_rooms.ts` — образец псевдонимов + assert (решение 5).
- Форма репутации места (`room_memory.ts`): severity, TTL, ступенчатое выцветание;
  читает не только AI (торговец поднимал цену на 18-35%). Предложение к S19: RoomRep =
  вектор по глаголам деяний того же verbs.csv с выцветанием — утвердить при посадке.

**Уроки-предупреждения (их документированные ошибки):**

- «Аффорданс ≠ наличие»: 1521 комната с назначением store, ящики в 7 — рейсы в пустоту.
  Наш S12.5 (запас от реальных инвентарей) закрывает это по построению.
- Правило владения обязано быть ОДНО на все комнаты (у их штаба было своё — база
  «одновременно захвачена и нет»). Наше поле owner это закрывает.
- Плотная матрица next-hop 28k×28k = 1.7 ГБ OOM; регион-узел = клеточный КОМПОНЕНТ
  связности, не клетка (наш иерархический судья уже так делает).
- Четыре независимые проекции комнат с разными тактами — у нас store один + roomAt.
- Плотный массив по id без пропусков; enum только в конец (сейвы).
- Два смысла на одном поле не живут (их homeRoomId: поводок стаи vs привязка к посту).

**НЕ берём:** `RoomType` (их главный дефект: посты объявлялись «коридорами», чтобы
часовой ходил), `apartmentId` (квартиры нет), владелец большинством клеток
`factionControl` (дорого, багообразно), `roomsByName`, два слоя выбора комнаты,
`PLOT_ROOMS`-дубль, комнаты как узлы навграфа (у нас нав есть; комната — цель,
прибытие = внутри зоны).

## Риски

- **RoomId в якорях и ключах** обязан быть устойчив между сессиями: источник —
  детерминированный порядок объявления модуля (пин бит-в-бит в гейте B).
- Кап комнат на этаж — корневой по S11, выводится от геометрии, не назначается.
  У хрущей комнат тысячи (BSP всех квартир) — u16 хватает с запасом.
- Клеточная гранулярность `roomAt`: субвоксельная стена внутри клетки не делит клетку
  между зонами — модуль сам решает, чья клетка. Комнаты — макровопрос (S2), это законно.
