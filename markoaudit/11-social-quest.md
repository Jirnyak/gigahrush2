**Generalisation proposal — a `Minigame` vtable, ~1 file, ~120 LOC once:**
```
struct MinigameDef {
  const char* id; const char* label; ItemId gate; std::uint16_t order;
  bool (*start)(MinigameState&, NpcPool&, NpcId p, NpcId n, std::uint32_t seed);
  void (*act)(MinigameState&, NpcPool&, MinigameVerb v);   // Advance/Hold/Quit
  void (*render)(const MinigameState&, MinigameView& out); // fills a POD view
  const char* (*outcome_line)(const MinigameState&);
};
```
- `MinigameState` = a fixed 64-byte POD union (dice needs 44 B today).
- `ConvActionKind::Minigame` carries a `const MinigameDef*` — **one** enumerator, **one** branch in `main.cpp`, **one** `minigame_ui_draw` that renders the `MinigameView` (header + two score rows + N key hints). Dice, домино, шашки, дурак become one table row + one rules file each.
- Deletes: `ConvActionKind::Dice`, the dice pre-empt branch, `dice_ui_draw`. New game cost drops from ~149 LOC / 5 files to ~60 LOC / 1 file.

### 6.2 Bank — GENERAL account system, ONE-OFF counter

The account itself is general and good: `BankAccount` is a 352-byte POD with a term deposit, a credit line, an accrual ring and a per-band `BankTerms` table (`bank_terms(band)`, `economy.h:333`). It ticks on the sim clock (`main.cpp:3240`), it saves (v16, `save.h:315`), it is conservation-tested (`suite_economy.inl:350-374` asserts `net_worth` invariance across every op but `bank_step`). It closed a real §52 row (`problems.md:2567`).

The **counter** is the one-off part:
- `bank_visible` (`conversation.cpp:94-97`) hard-gates on `RoleId::Duty`. Duty is 2-5 % of a floor (`role.h:38`) with no visual marker — so the bank is behind talking to a random 1-in-30 body.
- `bank_ui_draw` (`conversation_ui.cpp:145-187`) is 43 lines of literal key bindings (`Enter/T/D/W/L/R/Esc`) that bypass `keybind.h` entirely.
- `main.cpp:6206-6270` is 65 lines of `if (br.x) { verb(); snprintf(convLine, …); }` — 6 near-identical blocks with 6 inline Russian literals.
- Only the `*_all` wrappers are wired. `bank_deposit`, `bank_withdraw`, `bank_take_loan`, `bank_repay` (the amount-taking forms) have **zero `src/` callers** — reachable only through the wrappers. `bank_last_entry`, `bank_op_name`, `net_worth` have **zero `src/` callers** at all: the accrual ring and the human-readable ledger are written and never displayed.

**Proposal:** the six teller verbs are already a uniform `(acct, led, tick) -> int32` shape. Make them a `TellerVerb` table row `{key, label, fn, resultLineId}` and the 65-line cascade collapses to a 6-row table + one loop. Then the same table serves the future "склад от продакшена" (increment D) desk. Wire `bank_last_entry`/`bank_op_name` into the counter (the ring exists and is saved) or delete them.
