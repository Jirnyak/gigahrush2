`ai_init` вызывается из двух мест (`main.cpp:1377`, `main.cpp:1914`), `ai_step`

## 2. Контекст и проблемы кода

### 2.1. Роли не существует как понятия

`kFactionTraits` ([ai.h:387-394](../../src/game/ai.h)) — таблица на 6 строк,
индексируемая **фракцией**. Все шесть строк имеют `workDrive = 0.50f`, и это
задокументировано как заглушка: *«workDrive is the reference default 0.5
everywhere until occupations land»*.

Следствие: Жилец, Дежурный, Санитар, Мародёр и Сектант **неотличимы**, если
принадлежат одной фракции. Поведенческая дисперсия сегодня берётся только из
`identity_seed`-джиттера, то есть это шум, а не роль.

### 2.2. Три интента выигрывают и никуда не идут

`kRoomAffordance` ([room_zone.h:120-125](../../src/game/room_zone.h)) содержит
ровно четыре строки:

```
IntentEat    -> Kitchen
IntentDrink  -> Kitchen
IntentToilet -> Bathroom
IntentSleep  -> Living
```

`IntentWork`, `IntentSocial`, `IntentPatrol` строк не имеют, и заголовок это
прямо называет: *«work/social/patrol are a ROW away and deliberately not taken
yet»*. Побеждая, они делегируют `wander_step` — то есть решение «идти на работу»
неотличимо от блуждания.

### 2.3. `IntentHeal` — подтверждённый дедлок

[hunt.h:38-42](../../src/game/hunt.h): *«nothing heals a crowd body ([needs.h]
ticks the camera holder's row alone)»*. Строка `Medical` в `kRoomRecovery` —
нулевая, и [room_zone.h:178-180](../../src/game/room_zone.h) объясняет почему: HP
у толпы целочисленное, дробного банка нет. Тело с низким HP выбирает `IntentHeal`,
восстановиться не может и залипает в неудовлетворимой аварии до смерти.

### 2.4. Шесть видов памяти не имеют ни одного производителя

[ai.h:1009-1013](../../src/game/ai.h) честно перечисляет: `MemFood`, `MemWater`,
`MemRest`, `MemToilet`, `MemFoe`, `MemAlly` **не пишет никто** в `src/`. Читающая
сторона готова (`ai_recall` → `Perception::localScore`/`targetPenalty`), но термы
всегда нулевые. Это дефект класса §35 «данные, которые код не читает», только
зеркальный: **читатель есть, писателя нет**.

Прямое следствие для `grudge`: `Perception::grudge` заполняется из `MemFoe`,
которого никто не создаёт, поэтому `IntentFactionAssault` не может сработать по
личной обиде — только по матрице фракций.

### 2.5. `Perception::armed` всегда false

[ai.h:721](../../src/game/ai.h) — поле стаба. Скорер `IntentCombat` читает
`armed`, `IntentFlee` вычитает по нему. Оружие в инвентаре есть
(`ranged_pick.cpp` выбирает лучший ствол), но в восприятие оно не попадает.
Толпа принимает решения «драться или бежать», не зная, вооружена ли она.

### 2.6. Таксономия комнат двумерна

[room_zone.h:71-76](../../src/game/room_zone.h): комната — это **колонка сквозь
все этажи-перекрытия**, ключ `(kind, number, rx, ry)`, без `z`. Кухня на первом
ярусе и кухня на седьмом — одна и та же комната для поля. Это осознанное решение
(три существующих потребителя читают так же), но оно ограничивает «свидание в
конкретной комнате» из манифеста §4.

### 2.7. Скрытые издержки на теле-тик

Из частичного аудита (подтверждено чтением заголовков): `door_nearest_shelter`
для каждого бегущего тела делает линейный проход по дверям, а
`diffusion_gradient` — рассыпанные чтения в 128³. Оба на пути `ai_step`. При 16k
воплощённых это не O(n) с малой константой, а O(n·D).

## 3. Проектируемые структуры

### 3.1. Роль как строка таблицы, а не как ветвление

Роль **ортогональна** фракции: Санитар-Цитизен и Санитар-Учёный — одна роль,
разные фракции. Поэтому это второй индекс, а не расширение `kFactionTraits`.

```cpp
// src/game/role.h  (НОВЫЙ ФАЙЛ, giga_game)

// Занятие тела. Ordinal — индекс в kRoleTraits, поэтому порядок load-bearing
// ровно так же, как порядок IntentId ([ai.h] «The INDEX is load-bearing»).
enum class RoleId : std::uint8_t {
    Resident = 0,  // Жилец   — дом, кухня, сон; работы почти нет
    Duty,          // Дежурный— патруль по маршруту, реагирует на шум
    Medic,         // Санитар — идёт к раненым, единственный носитель heal-банка
    Looter,        // Мародёр — идёт к контейнерам и трупам, избегает патрулей
    Cultist,       // Сектант — идёт в Hq/Smoking, собирается в группы
    kRoleCount
};

// То же по форме, что kFactionTraits: чистые данные, без поведения.
// Умножается на фракционные черты, не заменяет их — фракция говорит
// «кто мы», роль говорит «чем занят».
struct RoleTraits {
    float workDrive;     // множитель к IntentWork
    float patrolDrive;   // множитель к IntentPatrol
    float sociability;   // множитель к IntentSocial
    float scavengeDrive; // НОВЫЙ терм: тяга к контейнерам/трупам
    float careDrive;     // НОВЫЙ терм: тяга к раненым
    std::uint16_t homeRooms;  // RoomBit-маска «где я живу»
    std::uint16_t workRooms;  // RoomBit-маска «где я работаю»
};

inline constexpr RoleTraits kRoleTraits[static_cast<std::size_t>(RoleId::kRoleCount)] = {
  /* Resident */ {0.30f, 0.05f, 1.00f, 0.10f, 0.05f,
                  room_bit(RoomBit::Living), room_bit(RoomBit::Common)},
  /* Duty     */ {1.00f, 1.00f, 0.60f, 0.05f, 0.20f,
                  room_bit(RoomBit::Living), room_bit(RoomBit::Hq)},
  /* Medic    */ {1.00f, 0.20f, 0.80f, 0.10f, 1.00f,
                  room_bit(RoomBit::Living), room_bit(RoomBit::Medical)},
  /* Looter   */ {0.20f, 0.10f, 0.40f, 1.00f, 0.00f,
                  0,                        room_bit(RoomBit::Storage)},
  /* Cultist  */ {0.60f, 0.40f, 1.20f, 0.30f, 0.10f,
                  room_bit(RoomBit::Living), room_bit(RoomBit::Smoking)},
};
```

**Где хранится роль.** НЕ компонентом. По тому же аргументу, по которому `Needs`
и `AiMemory` живут в пуле, а не на сущности ([ai.h:140-148](../../src/game/ai.h)):
лифт уничтожает тело, а роль обязана пережить поездку. Роль — 3 бита в
**существующем** 8-слотовом блоке `attrs` пула (`NpcPool`, слоты 3..7 свободны по
[README.md](../../README.md) §5), либо новая узкая колонка `role_` шириной 1 Б =
1.0 МиБ при 2²⁰. Рекомендация: **отдельная колонка `uint8`**, потому что `attrs`
зарезервирован манифестом под 8 RPG-атрибутов и займётся ими.

### 3.2. Расширение таблицы аффордансов — строки, не код

```cpp
// src/game/room_zone.h — ДОПОЛНЕНИЕ к kRoomAffordance
inline constexpr RoomAffordance kRoomAffordance[] = {
    {IntentEat,    room_bit(RoomBit::Kitchen)},
    {IntentDrink,  room_bit(RoomBit::Kitchen)},
    {IntentToilet, room_bit(RoomBit::Bathroom)},
    {IntentSleep,  room_bit(RoomBit::Living)},
    // --- НОВОЕ ---
    {IntentWork,   room_bit(RoomBit::Production) | room_bit(RoomBit::Office)
                 | room_bit(RoomBit::Hq)},
    {IntentSocial, room_bit(RoomBit::Common)  | room_bit(RoomBit::Smoking)},
    {IntentPatrol, room_bit(RoomBit::Corridor)},
    {IntentHeal,   room_bit(RoomBit::Medical)},
};
```

`kRoomFieldMask` вычисляется из таблицы автоматически, поэтому бейк подхватит
новые биты без правки. **Цена:** поля пекутся только для битов, реально
присутствующих на этаже (`bake_room_zones` фильтрует), но верхняя граница растёт
с 3 до 8 бит × 2 МиБ = **16 МиБ на этаж**. Это укладывается в бюджет
[performance.md](../../performance.md) и должно быть напечатано в логе бейка.

`IntentPatrol → Corridor` — намеренно вырожденный случай: коридор есть везде, и
поле коридора почти всюду `kFlowArrived`. Патруль обязан получить **маршрут**, а
не точку, поэтому для него нужна отдельная механика (§3.4), а строка выше —
только чтобы интент перестал молча делегировать.

### 3.3. Heal-банк: закрытие дедлока §2.3

Минимальное изменение, которое делает `IntentHeal` осмысленным. Дробный банк —
одно `float`-поле в существующей структуре `Needs`, а не новая система:

```cpp
// src/game/needs.h — ДОПОЛНЕНИЕ
struct Needs {
    // ... существующие поля ...
    // Дробный банк заживления. HP у толпы целочисленный, поэтому «+2.8 HP/с»
    // невыразимо напрямую: банк копит дробь, а целая часть переливается в hp
    // и списывается отсюда. Тот же приём, что pendingPee/pendingPoo уже
    // используют для давлений — накопитель, а не второй счётчик здоровья.
    float hpBank = 0.0f;
};
```

```cpp
// src/game/room_zone.h — строка Medical перестаёт быть нулевой
struct RoomRecovery {
    float food, water, sleep, pee, poo, pendingPee, pendingPoo;
    float hpBank;   // НОВОЕ: + HP в секунду, дробно
};
/* 7 Medical */ {0,0,0,0,0,0,0, /*hpBank*/ 1.2f},
```

Санитар (`RoleId::Medic`) получает право нести восстановление **с собой**: это
единственная роль, для которой `room_recover` применяется к соседу, а не к себе.
Так «Санитар» становится ролью с механикой, а не перекраской.

### 3.4. Патруль как маршрут по решётке — переиспользование, а не новая система

Патруль не нуждается в новом поле. 64-узловая решётка `lattice.h` уже
существует, `route_step` уже даёт O(1) шаг к любому узлу, и у него **до сих пор
нет потребителя** ([master_prompt.md](../../master_prompt.md) §7 #11: *«`route_step`
still awaits a consumer»*). Патруль — его естественный первый клиент.

```cpp
// src/game/ai.h — ДОПОЛНЕНИЕ к AiBrain. Влезает в существующие 16 байт?
// НЕТ: AiBrain уже ровно 16 Б и static_assert это пинует. Патрульная цель
// кладётся в отдельный РАЗРЕЖЕННЫЙ компонент, который есть только у тел с
// ролью Duty — их единицы процентов от толпы, поэтому дорогой плотной
// колонки они не стоят.
struct PatrolPlan {
    std::uint8_t nodeFrom = 0;   // lattice id 0..63
    std::uint8_t nodeTo = 0;
    std::uint8_t hops = 0;       // сколько узлов пройдено в текущем обходе
    std::uint8_t pad_ = 0;
};
static_assert(sizeof(PatrolPlan) == 4);
```

### 3.5. Производители памяти — закрытие §2.4

Ни одна из шести дыр не требует новой системы: у каждой уже есть система,
которая знает факт и его выбрасывает.

| Вид | Кто обязан вызвать `ai_remember_*` | Файл |
|---|---|---|
| `MemFood` / `MemWater` | открытие контейнера с едой/водой | `container.cpp` |
| `MemRest` | тело успешно поспало в комнате | `room_zone.cpp` |
| `MemToilet` | тело сняло давление в Bathroom | `room_zone.cpp` |
| `MemFoe` | получен урон от именованного NPC | `combat.cpp` |
| `MemAlly` | завершён положительный социальный обмен | `speech.cpp` |

Каждый вызов — одна строка, без аллокации, без реестра. Это заявлено самим
заголовком как дизайн: *«filing a fact is ONE call ... which is what makes it
cheap for combat/loot/container code to become a producer later»*.

## 4. Алгоритмы и псевдокод

### 4.1. Скоринг с ролью — умножение, не ветвление

```
score_intents(p, needs, out[13]):
    # существующий код без изменений до этой точки
    ft = faction_traits(p.faction)      # кто мы
    rt = role_traits(p.role)            # чем заняты   <- НОВОЕ

    # Роль МАСШТАБИРУЕТ уже посчитанный терм. Ни один коэффициент
    # референса не переписывается — это второй множитель, а не новая формула.
    out[IntentWork]   *= rt.workDrive
    out[IntentPatrol] *= rt.patrolDrive
    out[IntentSocial] *= rt.sociability

    # Два НОВЫХ аддитивных терма, оба гасятся угрозой тем же способом,
    # что и все прочие невыживательные интенты.
    out[IntentWork]   += rt.scavengeDrive * p.localScore[IntentWork] * (1 - threat)
    out[IntentHeal]   += rt.careDrive * p.nearbyWounded01 * (1 - threat)

    clamp each to [0, 100]
```

**Почему умножение, а не своя строка на роль:** пятнадцать ролей × тринадцать
интентов = 195 коэффициентов, которые придётся балансировать вручную. Умножение
даёт то же поведенческое разделение из пяти чисел на роль и сохраняет
референсный баланс как базу.

### 4.2. Паника как поле, а не как флаг

Манифест требует «механику паники и групповой защиты». Честная реализация —
**переиспользовать существующее диффузионное поле**, а не заводить эмоцию на теле:

```
panic_publish_step(reg, layer, danger_field, dt):
    # Тело в аварийном интенте ИЗЛУЧАЕТ в то же поле, из которого читает.
    # Это замыкает контур: один побежал -> поле поднялось -> соседи прочли
    # угрозу -> побежали -> подняли ещё. Стадо возникает само, кода стада нет.
    for each body on layer with AiBrain:
        if intent_is_emergency(brain.currentIntent):
            cell = wrap_macro(body.pos / kCellSize)
            danger_field.at(cell) += kPanicEmit * dt * ft.panic
            # ft.panic уже существует в kFactionTraits и до сих пор
            # использовался только на чтение
```

Стоимость: один O(n) проход, одна запись во float-поле на тело. Диффузия и
испарение уже есть и уже вызываются. **Групповая защита** — обратный знак того же
приёма: тело с высоким `risk` (Ликвидатор, `risk = 0.74`) излучает в поле
`rally` вместо `danger`, а `IntentCombat` читает его как аллюр.

### 4.3. Иерархия в запертой секции

Манифест требует «иерархию в запертых секциях Хруща». Не нужен ни граф власти, ни
новая система: иерархия — **производная от уже существующей матрицы отношений**.

```
# Вожак секции = argmax по (level, |rel_| положительных рёбер внутри секции).
# Считается ОДИН РАЗ при загрузке этажа, кладётся в RoomZones — это бейк,
# а не тик. AGENTS.md: «bake at load, tick in O(1)».
bake_section_hierarchy(pool, rooms, out):
    for each hermetic section S (комнаты, связные по дверям):
        best = argmax over residents r in S of
                   (pool.level(r) * kLevelWeight + positive_rel_count(r, S))
        out.leader[S] = best
```

Потребитель: `IntentWork`/`IntentPatrol` получают бонус, если вожак секции жив и
близко; смерть вожака обнуляет бонус, и секция видимо «разваливается». Это
проверяемое поведение, а не декоративный титул.

## 5. Критерии приёмки (Definition of Done)

Ни один пункт ниже не принимается зелёным тестом в одиночку. §27 закрывалась
именно печатаемыми числами на живом прогоне, и это правильный образец.

### 5.1. Роли

- [ ] `role_traits(RoleId)` — чистая функция, `constexpr`-таблица, `static_assert`
      на ширину.
- [ ] `suite_role.inl`: при **одной и той же** фракции и одном и том же
      `identity_seed` тела с разными ролями дают **различающийся** argmax
      минимум на 3 из 13 интентов. Это ровно тот тест, которого не хватает
      сегодня: он проверяет, что роль что-то меняет.
- [ ] Живой прогон печатает `[aimem] roles resident=N duty=N medic=N looter=N
      cultist=N` — гистограмма ролей.

### 5.2. Аффордансы work/social/patrol

- [ ] `AiTick::roomOwned` растёт после добавления строк — сегодня в него
      попадают только eat/drink/toilet/sleep.
- [ ] `AiTick::errandDistCells / (errandStep + errandColumn)` — **среднее
      оставшееся расстояние — ПАДАЕТ** на протяжении 2000 тиков. Это единственное
      число, отделяющее «идёт» от «упирается в стену»; счётчик владения не может.
- [ ] `errandColumn` не превышает `errandStep` — иначе толпа ходит по азимуту в
      обход геометрии, а не по полю.
- [ ] Бейк печатает `[rooms] baked bits=N bytes=N` и N ≤ 16 МиБ.

### 5.3. Heal-дедлок

- [ ] Тело с hp < 30 %, помещённое в Medical, за 60 с восстанавливает HP —
      печатается до/после.
- [ ] `crowd_dead_total` на прогоне 10 минут **не растёт** после появления
      Санитара на этаже, при том что до изменения растёт. Обе цифры в отчёте.

### 5.4. Производители памяти

- [ ] Для каждого из шести видов: `AiTick::remembered` растёт после

- [ ] Один испуг в углу 128³ поднимает `danger` у соседей в радиусе 6 клеток за

## 6. Порядок работ и зависимости

```
A. Heal-банк + строка Medical           <- ни от чего не зависит, снимает дедлок
B. Производители памяти (6 вызовов)     <- ни от чего не зависит, оживляет термы
C. RoleId + таблица + колонка в пуле    <- зависит от решения по attrs vs role_
D. Строки work/social/heal в аффордансах<- зависит от A (Medical) и C (workDrive)
E. Патруль через route_step             <- зависит от C, первый потребитель route_step
F. Паника через diffusion               <- зависит от B (иначе нечем помнить испуг)
G. Иерархия секций                      <- зависит от C и от гермозон (спека 02)
```

**A и B можно делать параллельно и они самые дешёвые.** E закрывает годовой долг
`route_step` без потребителя. G упирается в гермозоны, которых ещё нет, —
см. [02_VOXEL_PHYSICS_AND_FLUIDS.md](02_VOXEL_PHYSICS_AND_FLUIDS.md) §гермозоны.

## 7. Чего эта спека НАМЕРЕННО не делает

- **Не трогает `needs_step`.** [needs.h:25-35](../../src/game/needs.h) несёт
  письменный аргумент за узкую область, и 63 CHECK-а в `suite_needs.inl:865-891`
  её пинуют. §27 уже один раз откатили за попытку начать отсюда.
- **Не вводит суточный клок.** `Perception::minuteOfDay = -1` гасит все
  ритмические термы; включение клока — отдельное решение с собственными
  последствиями для `Living`/`Office` (обе строки `kRoomRecovery` ждут именно его).
- **Не переписывает скорер.** Коэффициенты выверены по референсу; роль входит
  множителем именно чтобы их не трогать.
