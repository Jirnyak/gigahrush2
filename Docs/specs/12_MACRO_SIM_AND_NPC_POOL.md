## 1. Круг воплощения ЗАМКНУТ — макромир не декоративен

Это главный вывод, и он опровергает разумное подозрение. Макроголовы
действительно становятся телами и возвращаются обратно.

| Направление | Путь | Строка |
|---|---|---|
| Воплощение | `ensure_loaded` → `embody_crowd` читает `pool.floor_bucket` | floor_stream.cpp:130-131 |
| | → `embody(ecs, pool, id, layer)` | floor_stream.cpp:222-227 |
| | → `pool.set_embodied(id, true)` | embody.cpp:81 |
| Развоплощение | `unload` → `fold_back(ecs, pool, id, e)` | floor_stream.cpp:377,406 |
| | → пишет `cx/cy/cz` из `Transform`, снимает биты, `reg.destroy(e)` | embody.cpp:113-129 |

**Что переживает круг:** позиция сворачивается в макроячейку
(`embody.cpp:119-121`); `hp`, инвентарь и нужды **остаются каноничными в строке
пула** и никогда не копируются в компоненты (`npc_pool.h:524`). Это верное
решение: нет двух источников истины, нечему рассинхронизироваться.

**Настоящее ограничение — не декоративность, а триггер.** Воплощение
происходит по загрузке этажа, а не непрерывно. Переезд в макросиме — O(1) запись
в ведро этажа (`macro_sim.cpp:470`), но телом это станет лишь на **следующем**
`ensure_loaded`. Мигрант существует как метка задолго до того, как обретёт тело.

## 3. Тик макросима — четыре прохода, и только три забюджетированы

| Проход | Сложность | Строка | Гейт |
|---|---|---|---|
| Возраст + смертность + резервуар родителей | **O(n), без предела** | macro_sim.cpp:280-340 | всегда |
| Рождения | O(рождений) | :349-422 | ≥1 плодовитый |
| Прибытие в путешествии | O(путешествий) | :449-475 | вне гейта миграции, намеренно |
| Кольцевое сканирование миграции | O(64) | :477-548 | ≥2 этажа |
| Рост социальных связей | O(64) | :563-603 | **ВЫКЛЮЧЕНО** |

Период: `kMacroPeriodTicks = kSimHz * 2` = **250 тиков = 2.000 с**. Шаг
продвигает **7 суток** (`daysPerTick`).

### 3.1. Демографический проход не имеет предела

Три из четырёх проходов забюджетированы. **Проход возраста и смертности —
полный обход `pool.count()` каждый тик, без бакетирования и без константы.**

`macro_sim.h:73-79` рассуждает о нём против бюджета 8 мс, но **не ограничивает**.
При проектных 2²⁰ это ~10 колонок × 10⁶ строк внутри одного шага симуляции.

На демо-населении 1 930 это невидимо. **Дефект проявится ровно тогда, когда
макромир начнут наполнять** — то есть в момент, когда заявленная фича станет
настоящей.

### 3.2. Социальный проход выключен по умолчанию

`socialFormRatePerYear = 0.0f` (`macro_sim.h:228`), и `main.cpp` его не
переопределяет: `game::MacroParams macroParams;` (`main.cpp:1776`) без единого
присваивания поля.

Следствие: **`rel_` — самая широкая колонка пула, 128 Б/строка — имеет
единственного писателя, который никогда не запускается, и ни одного читателя.**
При проектных 950k это 122 МБ на структуру, которой никто не пользуется.

### 3.3. Инверсия: видимые NPC — единственные, кто не живёт

`macro_sim.cpp:288-291` — воплощённые считаются среди живых и `continue`:
**ни старения, ни смертности, ни родительства**.

> Те NPC, которых игрок видит, — единственные, кто заморожен во времени.
> Все, кто вне экрана, стареют и умирают.

И зеркально (§6): **выгрузка этажа переводит его толпу из замороженной в
полностью симулируемую.**

| Колонка | В `src/` | В тестах | Вердикт |
|---|---|---|---|

**180 Б/строка DEMAND-колонок с одним путём записи каждая.** При проектных 950k
это 171 МБ. Плюс 8 Б/строка безымянного блока перков, которого не читал никто —
эти 8 МБ больше не считаются: колонка **СНЕСЕНА 2026-10-12** решением владельца
(«перков пока нет и не будет до пострелиза, пока они только планы и никакого
кода, вес лишний вырезаем»). Провод строки пула 385 → 377 Б, сейв v23 → v24.
Один из четырёх пунктов §9 закрыт не «подключением» и не «отложением», а
вычитанием.

`npc_pool.h:216-221` приходит к тому же счёту независимо — то есть автор это
знает и оставил намеренно.

**Связь с [спекой 09](09_COMBAT_BALLISTICS_AND_RPG.md):** снесённый блок был тем
самым восьмислотовым, где `Attr` «называл» три (Str/Agi/Int) и пять оставлял
свободными. ВАЖНО, и это выяснилось при сносе: `Attr` называл слоты блока только
НА СЛОВАХ — характеристики игрока лежат в собственном `RpgStats::attr[3]`
([rpg.h]), а блок пула не читал НИКТО. Спека 09 показывает, что INT декоративен
на стороне боя; на стороне пула был декоративен весь блок. **Одна дыра с двух
концов — и со стороны пула она закрыта сносом.**

## 6. Резидентность этажа и симуляция

Головы принадлежат этажу **по метке**, не по резидентности:

| Механизм | Строка |
|---|---|
| `floor_` — знаковый `int16_t` | npc_pool.h:500 |
| Все записи через `set_floor()`, индекс не рассинхронизируется | npc_pool.h:501 |
| Обратный индекс `floorBuckets_` + `slotInBucket_`, O(1) swap-remove | npc_pool.h:618-619 |
| Индексация `(метка − kMinFloor)`, 255 вёдер | npc_pool.h:622-626 |
| Часовой `kNoFloorLabel = -32768` | npc_pool.h:124 |

**Головы на выгруженном этаже симулируются полностью.** Проход `macro_sim.cpp:280`
обходит `id = 0 .. pool.count()` **без всякой проверки резидентности**;
единственный пропуск — `pool.embodied(id)`. Поскольку выгрузка **снимает** этот
бит (`fold_back` → `embody.cpp:126`), она **включает** для этой толпы старение,
смертность, рождения и миграцию.

Миграция и социальное дополнительно пропускают воплощённых (`:494, :574, :590`),
поэтому **холодные не-резиденты — единственная популяция, которую эти проходы
вообще трогают**.

## 8. Проектируемое

### 8.1. Забюджетировать демографический проход — форма уже есть в дереве

```cpp
// macro_sim.h, рядом с migrateRecordsPerTick
// Тот же приём, что уже применён к миграции и социальному: кольцевой курсор
// плюс предел записей. Копируется с macro_sim.cpp:477-548, ничего не изобретая.
std::uint32_t demographyRecordsPerTick = 4096;
```

```
demography_step(pool, params, dt):
    budget = params.demographyRecordsPerTick
    scanned = 0
    while scanned < budget and scanned < pool.count():
        id = demographyCursor_
        demographyCursor_ = (demographyCursor_ + 1) % pool.count()
        scanned++
        if pool.embodied(id): continue
        # Возраст продвигается на ФАКТИЧЕСКИ прошедшее для этой строки время,
        # а не на daysPerTick. Иначе бакетирование замедлит старение
        # пропорционально населению — тихий баг, который никто не заметит.
        elapsed = days_since(pool.lastVisitDay(id), currentDay)
        advance_age(pool, id, elapsed)
```

**Ловушка, из-за которой это не однострочная правка:** при бакетировании нельзя
продвигать возраст на `daysPerTick`. Нужна метка последнего посещения строки, то
есть **+2 байта на голову**. Иначе старение замедлится пропорционально
населению, и заметить это будет почти невозможно.

### 8.2. Решение по мёртвым колонкам — три варианта, не один

| Вариант | Экономия при 950k | Цена |
|---|---|---|
| Удалить `rel_`, `name_`, `surname_` | **171 МБ** | ломает 44 проверки, убивает социальное навсегда |
| Оставить как есть | 0 | 171 МБ на DEMAND-колонки, которые не аллоцируются, пока не тронуты |
| Включить социальное (`socialFormRatePerYear > 0`) | −122 МБ (тратится) | `rel_` оживает, нужен читатель |

**DEMAND-политика уже защищает от худшего:** колонка не аллоцируется, пока её не
коснулись. `name_`/`surname_` не тронуты нигде в `src/`, значит **не занимают
ничего** в реальном прогоне. Настоящая цена — не память, а **ложное впечатление
готовности**: заголовок обещает имена, которых никто не даёт.

**Рекомендация:** включить социальное и дать `rel_` читателя
([спека 01](01_ALIFE_AND_UTILITY_AI.md) §3a.5 — Сектанты), либо пометить три
колонки как «зарезервировано, потребителя нет» прямо в заголовке. Тихо оставлять
нельзя.

### 8.3. Непрерывное воплощение вместо загрузочного

Сегодня мигрант становится телом лишь на следующем `ensure_loaded`. Если этаж уже
резидентен, а голова только что на него переехала, тела не появится **вовсе** до
перезагрузки этажа.

```
# После кольцевого сканирования миграции: если целевой этаж РЕЗИДЕНТЕН,
# воплощать немедленно. Функция уже написана — не хватает вызова.
if registry.is_resident(arrival.floor):
    embody(ecs, pool, id, registry.layer_at(arrival.floor))
```

## 9. Критерии приёмки

### 9.1. Бюджет демографии

- [ ] Проход **забюджетирован** константой, как миграция.
- [ ] **Старение не замедляется** от роста населения. Это главный гейт: тест
      прогоняет 1 000 и 100 000 голов и сравнивает средний возраст через равное
      симулированное время. Расхождение = баг метки посещения.
- [ ] Стоимость шага макро при 100 000 голов измерена и напечатана.

### 9.2. Круг воплощения

- [ ] Голова, переехавшая на **резидентный** этаж, получает тело **без
      перезагрузки этажа**.
- [ ] `hp`/инвентарь/нужды переживают круг — они каноничны в пуле, значит
      проверяется отсутствие копий, а не совпадение значений.
- [ ] ABA-защита `gen_` держится: убитая и переиспользованная строка не
      получает чужое прибытие.

### 9.3. Инверсия заморозки

- [ ] Задокументировано и **осознанно**: воплощённые не стареют, выгрузка этажа
      возобновляет их демографию.
- [ ] Игрок, простоявший на этаже час, **не** обнаруживает, что весь остальной
      Хрущ вымер. Тест на распределение возрастов после долгого пребывания.

### 9.4. Мёртвые колонки

- [x] По `attr_` решение владельца принято и ИСПОЛНЕНО 2026-10-12: вариант
      «удалить». Колонки, константы, аксессора и единственного писателя больше
      нет, сейв бампнут 23 → 24, провод 385 → 377 Б, надгробие с числами стоит в
      шапке `npc_pool.h`, воскрешение ловит гейт
      (`tools/check_source_rules.cmake`, правило «БЛОК ПЕРКОВ В ПУЛЕ МЁРТВ»).
      Снос был УЖЕ оплачен: 8 МБ при 950k за ноль читателей.
- [ ] По `rel_`, `name_`, `surname_` принято **явное** решение из трёх
      вариантов §8.2, и оно записано в заголовке. ВНИМАНИЕ: решение владельца
      2026-10-12 было ПРО ПЕРКИ и только про них — расширять снос на этих трёх
      соседей без его слова нельзя.
- [ ] `sex_` либо получает читателя, либо помечается декоративным прямо в
      объявлении.

## 10. Явные не-цели

- **Не переписывать SoA.** Компоновка верна: id = индекс, вёдра этажей O(1).
- **Не копировать `hp`/инвентарь/нужды в компоненты.** Единственный источник
  истины — строка пула, и это правильно.
- **Не удалять DEMAND-колонки механически.** Они не аллоцируются, пока не
  тронуты; проблема в обещании, а не в памяти.
- **Не наполнять пул до 950k**, пока §8.1 не сделан. Без бюджета
  демографического прохода наполнение — это гарантированный выход за кадровый
  бюджет.
