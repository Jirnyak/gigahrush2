## 2. Контекст и проблемы

### 2.1. `source_rules` — пин, который нельзя провалить

```cmake
set_tests_properties(source_rules PROPERTIES
    PASS_REGULAR_EXPRESSION "files_scanned=[0-9][0-9][0-9]")
```

Пин требует **трёхзначного числа просканированных файлов**. Он совпадёт при
`files_scanned=203` и совпадёт при `files_scanned=100`. Сам скрипт печатает
`GIGA_SOURCE_RULES=PASS` / `=FAIL` (`check_source_rules.cmake:452,462`) и падает
через `message(FATAL_ERROR)`, поэтому реальная защита есть — **но она в коде
возврата, а не в пине**, и пин не проверяет ни одного правила.

Если скрипт когда-нибудь перестанет падать (например, кто-то заменит
`FATAL_ERROR` на `WARNING`), ctest останется зелёным, пока печатается трёхзначное
число.

### 2.2. Известный ложный негатив в самом гейте

`check_source_rules.cmake:42-47` документирует честно: строка усекается по
**первому `//`**, включая `//` внутри строкового литерала. Значит

```cpp
const char* u = "http://x"; throw y;   // <- throw НЕВИДИМ для гейта
```

Проверено на 2026-07-29: ни одной строки с запрещ��нным токеном после `://` нет,
то есть дефект **латентный, а не живой**. Но это ровно тот класс, который
переходит в живой молча.

### 2.3. Гейт «набор скомпилирован» гасится комментарием

[problems.md](../../problems.md) §36: проверка того, что suite попал в сборку,
сделана сырым `string(FIND …)` по конкатенированному тексту всех `tests/*.cpp`.
Значит **закомментированный** `#include` или закомментированный вызов диспетчера
удовлетворяют её. Идиома в дереве уже присутствует (`game_test.cpp:4262`).

### 2.4. Бюджетов производительности нет **ни одного**

Ни один ctest не утверждает время, память или лимит. Отсутствуют гейты на:

- время бейка этажа (сегодня измеряется, но не пинуется);
- размер воксельного зеркала (958 МиБ — см. [спеку 04](04_RENDER_AND_ACOUSTICS.md) §3.1);
- `kMaxCarveProposals` и число молчаливых отказов (см. [спеку 02](02_VOXEL_PHYSICS_AND_FLUIDS.md) §2.1);
- стоимость `ai_step` при 16k тел;
- 128 МиБ `FineNav` + 2 МиБ nearest-node + 6..16 МиБ `RoomZones` на этаж.

Это прямое противоречие с [performance.md](../../performance.md), который
объявляет CPU-тик **единственным дефицитным ресурсом**: у дефицитного ресурса нет
ни одного автоматического стража.

### 2.5. `sim_bench` печатает `FAITHFUL`, сравнивая **времена**

§36. Вердикт «бенчмарк верен оригиналу» выводится из сопоставления времён
выполнения, а не траекторий. Два разных алгоритма с одинаковой стоимостью дадут
`FAITHFUL`. Плюс заголовок таблицы печатает `@120Hz @60Hz` над числами,
посчитанными при 125 Гц.

### 2.6. `wrapf` — ноль утверждений

Функция, через которую **дважды за шаг** проходит позиция каждой сущности, не
имеет ни одной проверки. При этом §30 фиксирует: `wrapf` может вернуть ровно
`size`, что выходит за документированный `[0, size)`.

### 2.7. Регрессии гравитации не ловит ничто

Мандат просил «авто-тесты для исключения регрессий гравитации». Проверка: **ни
один тест не гоняет физику под режимом, отличным от `NegZ`**. Именно поэтому §9,
§15 и §34 живут месяцами, а `cellular.cpp:365` пережил весь антуражный проход
изотропии.

### 2.8. Версия сейва — 9, а не 6

Мандат называл «загрузку сейвов v6». Актуальная — `kSaveVersion = 9`
([save.h:110](../../src/game/save.h)); история версий 2→9 расписана в том же
файле. Версии 1 отвергаются. Спеки 03 и 04 обе требуют версии 10.

### 2.9. Пять генерируемых таблиц без единого упоминания в тестах

`craft_table`, `monster_traits_table`, `prop_table`, `ranged_pick`, `status_table`
не встречаются ни в одном `tests/*.inl` или `tests/*.cpp`. Для генерируемых таблиц
это частично покрывается CSV-дрейф-гейтом, но `ranged_pick` — **не таблица, а
логика выбора оружия**, и она не покрыта ничем.

## 3. Проектируемые гейты

### 3.1. Гейт изотропии — самый ценный тест из ненаписанных

```cpp
// tests/suite_gravity_regimes.inl — НОВЫЙ.
//
// ПОЧЕМУ ЭТО ГЛАВНЫЙ ТЕСТ НАПРАВЛЕНИЯ: изотропия — единственный закон
// движка, который выигрывался ОДИН РАЗ и не распространился (problems.md
// «Второй диагноз»). Причина ровно одна: ни один тест не проверяет
// не-NegZ, поэтому регрессия не наблюдаема.
//
// Метод — DIAGNOSIS, а не верификация: прогон по всем восьми режимам
// ОБНАРУЖИВАЕТ дефекты, а не подтверждает их отсутствие. Именно так §8
// нашла многолетний баг в самом Z-фрейме.
for (GravityRegime r : {NegX, PosX, NegY, PosY, NegZ, PosZ, Zero, Custom}) {
    // 1. Падение: тело, отпущенное в покое, движется ВДОЛЬ regime_down()
    //    и ни по одной другой оси.
    // 2. Жидкость: вода собирается на грани, которую называет режим.
    //    Под Zero — НЕ течёт никуда (сегодня течёт в +X).
    // 3. Карвинг: сфера остаётся сферой; открепление изотропно.
    // 4. Локомоция: базис контроллера строится из фрейма, а не из литералов.
    // 5. Отбрасывание: толкает НАЗАД, а не вверх (§34).
}
```

**Тест ставится красным.** Гейт, написанный после правки, доказывает только то,
что автор написал тест под свой код; гейт, поставленный до и падающий, доказывает,
что дефект существует.

### 3.2. Бюджеты как утверждения, а не как печать

```cpp
// tests/suite_budgets.inl — НОВЫЙ.
//
// Правило формы: КАЖДЫЙ бюджет печатает измеренное И порог, всегда, даже
// когда проходит. AGENTS.md §Measure: «Print the number every run» —
// молчащий зелёный тест не даёт следующей сессии увидеть тренд.
CHECK_BUDGET("voxel_mirror_bytes", mirror.resident_bytes(), 1024u * 1024 * 1024);
CHECK_BUDGET("floor_nav_bytes",    nav.resident_bytes(),     160u * 1024 * 1024);
CHECK_BUDGET("room_zones_bytes",   zones.resident_bytes(),    16u * 1024 * 1024);
CHECK_BUDGET("carve_dropped_full", queue.droppedFull,          0u);
CHECK_BUDGET("floor_bake_ms",      bakeMs,                  4000u);
```

**Порог — верхняя граница с запасом, а не текущее значение.** Пин на текущем
значении превращает любое улучшение в красный тест и провоцирует его подкрутку.

**Что НЕ пинуется:** абсолютное время кадра и FPS. [render.md:286-291](../../render.md)
уже вывел правило — FIFO-present делает счётчик кадров каппой, слепой ко всему под
ней. Пинить каппу значит пинить константу vsync.

### 3.3. Гейт «система построена и не подключена»

Дефект §13 повторился четырежды: `cellular.cpp` (1484 строки), `fluid_step`,
`VoxelMirror::mark_fluid_dirty()`, затухание пятен. Точечная починка класс не
закрывает.

### 3.4. Гейт колонок CSV — зеркало §35

`source_rules` считает **строки** CSV, но никогда — **колонки**. Колонка без
потребителя невидима для всех гейтов дерева. Сегодня таких групп около десяти,
включая **272 навигационных числа** в `data/mobs.csv`
(`nav_step_sub`/`nav_climb_sub`/`nav_drop_sub`/`nav_fly`), которые бейк навигации
не открывает никогда, и колонку `ai_flags`, которую генератор молча игнорирует,
строя `aiFlags` из **других** колонок (46 строк из 68 расходятся).

```
Правило: колонка CSV обязана иметь читателя в src/ ЛИБО строку в списке
«отложено, причина». Колонка, у которой нет ни того, ни другого, роняет сборку.
```

**Ловушка, названная в [master_prompt.md](../../master_prompt.md) PLAN B:** три
строки в таблице §35 были **неверны** в первой редакции — у них читатели есть.
Проверять каждую своим `rg` до удаления.

### 3.5. Тест обратной полярности для гейтов

Гейт, который никогда не падал, неотличим от гейта, который не работает. Для
каждого нового гейта — **вторая половина**:

```
Для КАЖДОГО гейта: намеренно внесённая мутация обязана его уронить.
  * source_rules       -> `throw` в новом файле -> FAIL
  * source_rules       -> `throw` после `://` в литерале -> сегодня PASS (§2.2)
  * wired              -> новый *_step без вызова -> FAIL
  * csv_columns        -> новая колонка без читателя -> FAIL
  * gravity_regimes    -> литерал `-1` вместо regime_down() -> FAIL
```

Строка про `://` записана **как известный провал**, а не как проходящий случай:
это честная фиксация границы гейта, а не его подделка.

## 4. Метрики этапа генерации

Мандат просит замеры генерации этажа. Все три величины уже вычислимы, ни одна не
пинуется.

```cpp
// Печатается КАЖДОЙ загрузкой этажа, в одну строку, в формате, который
// grep-ается следующей сессией:
// [floorgen] n=0 kind=Residential gen_ms=? nav_ms=? rooms_ms=? antourage_ms=?
//            nav_bytes=136314880 rooms_bytes=6291456 carve_props=? dropped=?
struct FloorBakeStats {
    std::uint32_t genMs, navMs, roomsMs, antourageMs;
    std::size_t   navBytes, roomsBytes, mirrorBytes;
    std::uint32_t carveProposals, carveDropped;
};
```

Известные величины для проверки арифметики:
`FineNav.flow` = `uint8[64 × 128³]` = **128 МиБ**, nearest-node = **2 МиБ**,
`RoomZones` = 2 МиБ на бит (3 бита сегодня = 6 МиБ, до 8 бит после
[спеки 01](01_ALIFE_AND_UTILITY_AI.md) = 16 МиБ).

## 6. Порядок работ

```
A. suite_gravity_regimes (красным)   <- ГЛАВНОЕ. Ставится ДО правок
B. Пин source_rules на PASS          <- одна строка, закрывает 2.1
C. Тесты обратной полярности         <- доказывают, что гейты работают
D. suite_budgets                     <- первые бюджеты в истории проекта
E. check_wired                       <- закрывает класс §13
F. Гейт колонок CSV                  <- закрывает класс §35
G. wrapf + ranged_pick               <- точечное покрытие
H. sim_bench: траектории             <- закрывает §36
I. Сейв v10 round-trip               <- когда приземлятся спеки 03/04
```

**A и B первыми.** B — одна строка. A — единственный тест, который сам по себе
находит дефекты, а не подтверждает их отсутствие.

## 7. Явные не-цели

- **Не пинить FPS и время кадра.** FIFO-каппа слепа ко всему под ней.
- **Не поднимать пины проверок ради «роста покрытия».** Число CHECK-ов — не
  метрика: 900k проверок в `test_needs_decay` — это один цикл, а не 900k
  инвариантов.
- **Не пинить набор с ненулевыми отказами.** [AGENTS.md](../../AGENTS.md)
  запрещает прямо: чинить или удалять с причиной в коммите.
- **Не заменять живой прогон тестом.** §27 закрывалась печатаемыми числами на
  реальном запуске, и это правильный образец: зелёный ctest доказывает
  согласованность, а не достижимость.
