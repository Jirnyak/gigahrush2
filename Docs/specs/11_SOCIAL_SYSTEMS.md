## 3. Слухи не распространяются — и это дизайн, а не дефект

Ожидание «диффузия слухов между NPC» неверно. `rumour.h:112`:

> built on demand from world state and thrown away, **never stored per NPC**

Слух — **чистая функция** `(говорящий, этаж, часы)`, `rumour_for` при
`rumour.h:208`. Ни графа, ни хранения, ни передачи. Модель — «подслушанная
реплика», а не эпидемия.

**Но одна связь оборвана.** Приложение зовёт **5-аргументный шим**
(`rumour.h:227`), а не 6-аргументную форму с часами. Из-за этого четыре вида
слухов недостижимы (`rumour.h:213-219`): `Imminent`, `Variant`, `Veteran`,
`Lull` — все четыре самосборные.

Итого: **самосбор → слухи** объявлен, но severed. Игрок не может услышать
«скоро тряхнёт», хотя механизм написан.

## 4. Квесты: награда не含 XP, и это тоже дизайн

`quest.h:34` заявляет прямо: движок «не имеет XP». Награда — деньги и предмет:

```

quest.cpp:443-446:  quest_grant_item(...)    // недостача идёт в rewardItemsLost
```

Значит `xp_for_quest` (`rpg.h:211`) без вызовов — **сирота другой системы**, а не
дыра в квестах. Мой первый проход
([спека 03](03_ECONOMY_MASS_AND_CRAFTING.md) §2.5) назвал это дефектом квестов;
**это неверно**, и поправка здесь.

Три вида квестов, переиспользованных из `contract.h:54`: `Fetch`, `Hunt`,
`Descend`. Собственного enum у `quest.h` нет намеренно (`quest.h:6-11`).

## 6. Матрица фракций

| Свойство | Значение |
|---|---|
| Форма | `std::int8_t v[6*6]` = **36 байт** |
| Размер | `kRelFactionCount = kFactionCount + 1` = 6 (пять обществ + строка игрока) |
| Индексация | `a * 6 + b` |
| Симметрия | **по построению** (`faction_relations.h:64`) |
| Мутируемость | рантайм; гнётся смертями (`relations_drain_deaths`) |
| Монстры | **не строка** — отдельный `kMobVsFaction[6]` |
| Читатели | combat, contract, wander, investigate, rumour, hunt, macro_sim, main |

**Одна намеренная асимметрия** внутри симметричного хранилища
(`faction_relations.h:143`): строка игрока гнётся иначе — «Ликвидаторы забывают,
что ты сделал». То есть симметрия хранения ≠ симметрия обновления.

## 7. Перекрёстные связи — что с чем говорит

| A → B | Подключено | Доказательство |
|---|---|---|
| слухи → торговля | **НЕТ, РАЗРЫВ** | §2 |
| квест → торговля (цены) | нет | `vendor_buy_price` читает только `ItemDef` |
| квест → инвентарь | да | `quest.cpp:445` |
| квест → казна | да | `quest.cpp:436` |
| квест → фракции | **нет** | grep `standing\|reputation` в `quest.cpp` → 0 |
| торговля → фракции | **нет** | тот же grep в `vendor.cpp` → 0 |
| слухи ↔ речь | **нет, намеренно** | `speech.h:3-29` — раздельные каналы |
| слухи/речь общий транспорт | да | оба через `nearest_speaker` |
| самосбор → слухи | объявлено, **severed** | §3 |
| самосбор → речь | да | `main.cpp:3949` |
| фракции → речь | да | вторая ось банка, `speech.h:118` |
| фракции → торговля | объявлено, **severed** | §2 |
| убийство → квест | да | `main.cpp:2498` |
| квест → сейв | да | `save.cpp:444,462,533,582` |

**Две дыры в репутации, обе одного класса:** ни квест, ни торговля не меняют
отношение фракций. Матрица есть, гнётся только смертями. Значит **социальных
последствий у поступков игрока нет** — можно обокрасть всех и остаться своим.

## 8. Проектируемое

### 8.1. Восстановить разрыв торговли — одна строка

```cpp
// main.cpp, код прибытия на этаж, рядом с существующей установкой активного слоя.
// vendor.h:50-54 предупреждал ровно об этом; предупреждение сбылось.
vendorKind = game::vendor_kind_for(game::dominant_faction(pool, floorNumber));
```

Оживляет: `kSellMult[1]`, `kSellMult[2]`, слух `Territory` и всю связь
фракция→цена.

### 8.2. Позвать 6-аргументную форму слуха

```cpp
// main.cpp:3965 — вместо шима
r = game::rumour_for(pool, speaker, floorNumber, seed, samosbor, clockTicks);
```

Оживляет четыре самосборных вида слуха. Игрок начинает слышать предупреждение о
кризисе от толпы — то, ради чего слухи и существуют.

### 8.3. Репутация как последствие — новая связь

```cpp
// Матрица уже есть и уже гнётся смертями. Нужны ещё три источника изгиба.
// НИ ОДНОЙ новой структуры: relations_nudge уже написан.
on_quest_complete(q):  relations_nudge(rel, playerRow, q.giverFaction, +3);
on_theft_witnessed(f): relations_nudge(rel, playerRow, f, -8);
on_trade_completed(v): relations_nudge(rel, playerRow, v.faction, +1);
```

Это замыкает петлю: поступок → отношение → цена (через §8.1) → доступность
товара. Четыре системы связываются тремя вызовами существующей функции.

## 9. Критерии приёмки

### 9.1. Разрыв торговли

- [ ] `vendor_kind_for` и `dominant_faction` имеют вызовы. Гейт: обе не в списке
      мёртвых.
- [ ] Цена продажи **различается** на этажах с разной доминирующей фракцией.
      Два числа, не ощущение.
- [ ] Слух `Territory` начинает влиять на цену — иначе он остаётся косметикой.

### 9.2. Слухи

- [ ] Четыре самосборных вида (`Imminent`/`Variant`/`Veteran`/`Lull`)
      **достижимы**. Тест перечисляет виды и требует, чтобы каждый хоть раз
      выпал.
- [ ] Шим `rumour_for` 5-арг либо удалён, либо помечен как совместимость с
      причиной.

### 9.3. Репутация

- [ ] Кража на глазах у NPC **меняет** отношение фракции. Число до/после.
- [ ] Изменённое отношение **меняет цену** — сквозная проверка петли, а не
      каждого звена по отдельности.
- [ ] Отношение переживает сейв.

### 9.4. Мёртвые функции

- [ ] `quest_objective_text` получает вызов или удаляется.
- [ ] Гейт мёртвых функций **различает** экспорт-для-тестов и настоящую
      мертвечину. Механическое «ноль вызовов = удалить» уничтожило бы
      тестируемость десяти функций.

## 10. Порядок работ

```
A. vendor_kind_for + dominant_faction   <- ОДНА СТРОКА, живой дефект
B. rumour_for 6-арг                     <- одна строка, +4 вида слухов
C. quest_objective_text: вызвать/удалить<- решение
D. Репутация от квестов                 <- 1 вызов
E. Репутация от кражи                   <- 1 вызов, нужен свидетель
F. Репутация от торговли                <- 1 вызов
G. Сквозной тест петли                  <- зависит от A и D-F
```

**A и B — две строки, оживляющие две системы.** Лучшее соотношение во всём
аудите.

## 11. Явные не-цели

- **Не делать слухи распространяющимися.** Модель «подслушанная реплика»
  заявлена в `rumour.h:112` и она дешевле: ноль хранения на NPC.
- **Не соединять речь и слухи.** `speech.h:3-29` держит их раздельными
  намеренно, с разными кулдаунами (2 с против 3 с).
- **Не вводить XP за квесты.** `quest.h:34` заявляет отсутствие XP как факт
  дизайна; награда — деньги и предмет.
- **Не удалять функции по правилу «ноль вызовов».** Десять из тринадцати
  мёртвых — экспорт для тестов или внутренние помощники.
