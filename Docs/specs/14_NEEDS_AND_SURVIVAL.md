## 1. Нужды — редкий случай законченной системы

Пять нужд, у каждой есть зуб, петля замкнута у всех пяти. Переделывать нечего;
работа — в трёх дырах §4–§6.

```cpp
struct Needs {          // npc_pool.h:161-173, ровно 36 байт (static_assert)
    float food  = 0;    // 0..100 резерв, убывает; 0 = голод
    float water = 0;    // 0..100 резерв, убывает; 0 = обезвоживание
    float sleep = 0;    // 0..100 резерв, убывает; стоит скорости, не HP
    float pee   = 0;    // 0..100 давление, растёт; 100 = переполнение
    float poo   = 0;    // 0..100 давление, растёт
    float pendingPee = 0;  // выпито/съедено, не переварено
    float pendingPoo = 0;
    float hpDebt = 0;      // дробная убыль HP между тиками
    std::uint8_t seeded = 0;
    std::uint8_t pad_[3] = {};
};
```

**Это колонка пула, не компонент ECS.** Каноничное значение — в строке пула,
поэтому нужды переживают воплощение и лифт бесплатно
([спека 12](12_MACRO_SIM_AND_NPC_POOL.md) §1).

## 2. Ставки и зубы

| Нужда | Ставка | Источник | Тип |
|---|---|---|---|
| food | 0.08/с | `needs.h:87` литерал | убывает |
| water | 0.12/с | `needs.h:88` | убывает |
| sleep | 0.05/с | `needs.h:89` | убывает |
| pee | 0.10/с | `needs.h:96` | **только из очереди** |
| poo | 0.06/с | `needs.h:97` | **только из очереди** |

Все пять — `inline constexpr` литералы в заголовке, **не таблица**. Порядок
навязан: `needs.h:90-91` статически утверждает `water > food`.

| Нужда | На пределе | HP/с | Скорость | Интент |
|---|---|---|---|---|
| food ≤ 0 | голод | **0.3** | ×0.75 | `IntentEat` |
| water ≤ 0 | обезвоживание | **0.5** | ×0.65 | `IntentDrink` |
| **sleep < 10** | истощение | **0** намеренно | **×0.5** | `IntentSleep` |
| pee ≥ 100 | переполнение | 0.1 | нет | `IntentToilet` |
| poo ≥ 100 | переполнение | 0.1 | нет | `IntentToilet` |

Сумма ровно `1.0 HP/с` при четырёх отказах — заявлено `needs.h:99-101`, сходится.

### 2.1. Три решения, которые надо сохранить

**Порог сна — 10, а не 0.** `needs.cpp:244` штрафует скорость при `sleep < 10`,
то есть **зуб срабатывает до опустошения полосы**. `needs_failed_mask` при этом
сообщает отказ на ≤0 (`needs.cpp:193`), а `needs_hp_rate` сон пропускает вовсе.
Три разных порога в одной нужде, и все три осмысленны.

**Урон идёт по `kAttritionChannel`** — на единицу выше последнего реального
канала (`needs.h:200-201`). Проверка `if (i < kDamageChannels)` в `apply_damage`
его пропускает, поэтому **броня не спасает от голода**.

Это же место — предмет `static_assert`, которого нет
([спека 09](09_COMBAT_BALLISTICS_AND_RPG.md) §2.4): добавление шестого канала
урона сделает `kAttritionChannel` валидным индексом, и **броня начнёт
митигировать голод**. Дыра открывается молча.

**`hpDebt` копит дробь** (`needs.cpp:318-322`). Без него 0.1 HP/с при 125 Гц
усекалось бы в ноль **вечно**. Классическая ошибка, которой здесь избежали.

### 2.2. Давления — самые слабые зубы, и это следствие, не решение

0.1 HP/с каждое, скорости не стоят, и растут **только** если тело что-то
потребило. Игрок, который не ест, не видит их никогда.

## 3. Пищеварение замкнуто и доказано устойчивым

`digest()` (`needs.cpp:30-38`) переливает из `pendingPee`/`pendingPoo`; наполняет
их только потребление. **Автономного роста давлений нет.**

Именно это делает петлю кухня→туалет→кухня физичной: кухня заряжает очередь,
давление растёт, выигрывает `IntentToilet`, тело идёт в `Bathroom`.

`needs.h:167-170` статически утверждает, что обе скорости переваривания
превышают собственный приток в установившемся режиме — **вечный долг
невозможен**. Запас по кишечнику **7 %**, и это стоит знать при любой правке
ставок.

## 4. Дыра первая: туалета не существует как объекта

`needs.h:191-194` признаёт это прямо.

Единственный вызов `relieve_needs` — «физиологический запасной вариант» на
клавише взаимодействия (`main.cpp:3724-3729`), передающий `100.0f, 100.0f`:

(`room_zone.h:251-263`, две сковороды с `useSpot = true`), путь построен, зуб
работает — и всё это обходится.

## 5. Дыра вторая: холодные NPC не имеют нужд

`needs_step` фильтрует по слою (`needs.cpp:270`): только воплощённые тела на
активном этаже. Проверка `macro_sim.cpp` и `population.cpp` на `Needs` — **пусто**.

`needs.h:42-44` заявляет намерение — макросим владеет холодными 950k — но
**грубые часы не реализованы**. Нужды холодных **заморожены**, а `needs_advance`
(`needs.cpp:181`) оставлен как чистая заготовка под них.

Две связи ломаются:

- **Роли через нужды существуют на одном этаже из 255.** Мародёр
  ([спека 01](01_ALIFE_AND_UTILITY_AI.md) §3a.4), ушедший с активного этажа, не
  голодает и потому не мародёрствует.
- **Зеркальная инверсия к демографии.** В макросиме воплощённые **не стареют**
  ([спека 12](12_MACRO_SIM_AND_NPC_POOL.md) §3.3), а здесь — наоборот, только
  воплощённые и живут. Две системы разделили популяцию строго
  противоположно, и ни одна не покрывает обе половины.

## 6. Дыра третья: NPC беззвучны

`main.cpp:3370-3374` — база 6 м × `noiseMult`, каждые 28 тиков при боковой
скорости² > 0.5, с вычетом вертикали через вектор гравитации слоя (падение не

Но `noiseMult` — из `EncumbranceTick::playerEffect`, заполняемого **только под

`noise.h:90` до сих пор помечает `Footstep` как «reserved; nothing publishes this
yet» — для игрока неверно, для толпы верно.

**Следствие:** Дежурный ([спека 01](01_ALIFE_AND_UTILITY_AI.md) §3a.2) не может
услышать Мародёра. Роль, чья механика — реакция на шум, лишена входа, потому что
шум производит один объект в мире.

## 7. Перегруз — четыре штрафа, два новых механизма

`EncumbranceEffect` (`encumbrance.h:84-89`) плюс запись компонента.

| # | Штраф | Формула | Новизна |
|---|---|---|---|
| 1 | **Шум** | `noiseMult = 1 + 0.6·ratio` | **новый** эффект на **старом** поле |
| 2 | **Скорость** | `scale = 1/ratio`, пол 0.35 | **новый** множитель в **старой** цепочке |
| 3 | **Усталость** | `extraSleep = 0.10·(ratio−1)` /с | **новый** отток в **старую** полосу сна |
| 4 | **Масса** | `Mass.kg = body_mass(h) + carriedG·0.001` | **новый** вход в **старые** законы |

**Ни один из четырёх не создал новой системы.** Каждый — вход в существующую, и
это образец, которому должны следовать все спеки.

### 7.1. Поведение, которое стоит знать

- **Шум берётся с первого грамма**; скорость и усталость — только при
  `ratio > 1.0` (`encumbrance.cpp:24`). При ровно 1.0 множитель ровно 1.0, ступени
  не чувствуется.
- **`capacityG == 0` даёт отсутствие штрафа, не бесконечный** (`encumbrance.cpp:14`).
- **Скорость сообщается, не пишется** (`encumbrance.h:110-113`). Приложение
  складывает её на `main.cpp:2973` вместе с нуждами, статусом и AGI. Один писатель
  `moveSpeed` — верно.
- **Усталость ложится только на засеянную строку** (`encumbrance.cpp:87`), иначе
  засеяла бы её неверным значением.
- **Бакетирование 1 из 8** по `hash_u32(id) % 8`, **но носитель камеры
  посещается каждый тик**. Толпе выставляется `slice = dt*8`, игроку `dt` — верно,
  не баг.

### 7.2. Отдельной выносливости нет и не должно быть

Перегруз уходит в **существующую** полосу сна (`encumbrance.cpp:81-84`);
`encumbrance.h:33-36` объясняет: одна усталость, а не две. `Needs` не имеет поля
стамины, и размер зафиксирован `static_assert` на 36 байт.

Единственное упоминание `stamina` в дереве — комментарий `combat.h:442`,
объясняющий её отсутствие.

**Вводить стамину значит отменить это решение.** Не делать.

## 9. Проектируемое

### 9.1. Туалет как объект — закрытие §4

```cpp
// Убрать полное облегчение из main.cpp:3724-3729. Взаимодействие с
// kPropToiletPan даёт АВТОРСКОЕ частичное облегчение; в чистом поле —

```

Три следствия из одной правки: мебель обретает смысл, поле становится хуже
туалета, а облегчение в коридоре — слышно.

### 9.2. Грубые часы нужд для холодных — закрытие §5

```
# macro_sim.cpp, в тот же проход, что демография (спека 12 §8.1).
# needs_advance УЖЕ НАПИСАН как чистая заготовка — не хватает вызова.
macro_needs_step(pool, id, elapsedDays):
    # Грубо: 7 суток за шаг — это 604800 с, при 0.08/с еда ушла бы
    # в минус 48000 раз. Значит холодные нужды НЕЛЬЗЯ считать теми же
    # ставками — нужен насыщающий вид.
    #
    # Модель: холодная голова ЕСТ, если у неё есть еда в инвентаре,
    # и голодает иначе. Не полоса, а бинарное состояние.
    if pool.inventory(id).has_tag(ItemTag::Food):
        pool.inventory(id).consume_one(ItemTag::Food)
        needs.food = kColdFedLevel          # 60
    else:
        needs.food -= kColdStarveStep       # 20 за шаг
        if needs.food <= 0: pool.kill(id, DeathCause::Starvation)
```

**Ловушка, из-за которой это не подключение одной строки:** горячие ставки на
холодных часах бессмысленны — 7 суток за шаг умножают всё на 604 800. Холодная
модель обязана быть **другой по форме**, а не той же с другим `dt`. Это и есть
работа, а `needs_advance` — только точка входа.

## 10. Критерии приёмки

### 10.1. Туалет

- [ ] Взаимодействие с `kPropToiletPan` даёт **70/65**, поле — **40/35**. Числа,
      не ощущение.
- [ ] Полного облегчения (100/100) в дереве **не осталось**. Гейт: grep на
      `relieve_needs(.*100` пуст.
- [ ] Облегчение в поле **слышно** и **пачкает**; в туалете — нет.
- [ ] Тело NPC пользуется той же мебелью, что игрок. Один путь, не два.

### 10.2. Холодные нужды

- [ ] Холодная голова **может умереть от голода**. Счётчик
      `DeathCause::Starvation` печатается за прогон.
- [ ] Холодная модель — **бинарная, не полосная**. Гейт: прогон 100 шагов
      (700 суток) не даёт значений вне 0..100.
- [ ] Инвентарь холодной головы **расходуется** — сегодня макро его не касается
      вовсе ([спека 12](12_MACRO_SIM_AND_NPC_POOL.md) §4).
- [ ] Мародёр, ушедший с активного этажа, **продолжает** голодать.

### 10.3. Шаги NPC

- [ ] NPC публикуют шум шагов. Гейт: `noise.h:90` перестаёт быть верным и
      **переписывается**.
- [ ] Тяжёлый NPC слышен дальше лёгкого. Два числа радиуса.
- [ ] 1930 тел **не затапливают** поле шума: бакетирование 1-из-8 проверено
      счётчиком публикаций за тик.
- [ ] Дежурный **находит** Мародёра по шуму. Сквозная проверка, а не звено.

### 10.4. Регрессии

- [ ] Сумма зубов остаётся ровно **1.0 HP/с** при четырёх отказах.
- [ ] Запас устойчивости пищеварения (**7 %** по кишечнику) не съеден правками
      ставок. `static_assert` `needs.h:167-170` держит это сам — не удалять.
- [ ] `sizeof(Needs) == 36` держится.
- [ ] Порог сна остаётся **10**, а не 0. Правка на 0 выглядит как исправление
      несогласованности и убьёт зуб.
- [ ] `static_assert` на `kAttritionChannel` добавлен.

силе. Разница между этими двумя строками — ровно то, что не-цель защищала.

**3. Полевое облегчение выставлено, но потребителя надо проверить отдельно.**
Константы есть; вопрос «вызывает ли их код, когда рядом нет `kPropToiletPan`»
остаётся к приёмке §10.1. Наличие константы — не наличие пути. Ровно тот класс,
который вся эта серия спек и ловит: **засеяно, читается, но не шагается**.

Мелочь для чужой правки, не моей: `role.h:33` содержит `another body''s` —
удвоенная кавычка в стиле SQL-экранирования внутри C++-комментария. Компиляции не
мешает, но это опечатка, а не намерение.

## 11. Явные не-цели

- **Не вводить стамину.** `encumbrance.h:33-36` объясняет, почему одна усталость
  лучше двух, и `Needs` зафиксирован `static_assert` на 36 байт.
- **Не выносить ставки в CSV.** Пять литералов со `static_assert` на порядок
  дешевле таблицы, читаемой в одном месте.
- **Не давать давлениям автономный рост.** «Не ел — не хочешь» физично и делает
  петлю честной.
- **Не заполнять 7 нулевых строк `kRoomRecovery` механически.** Office и Medical
  занулены с причинами; заполнить их — значит отменить эти причины, а не
