# 10 — Сейв, персистентность и что мир забывает

> Сверено с деревом **2026-08-09** на `sync/gravity-on-owner-main`.
> Контракт: [save.h](../../src/game/save.h), [save.cpp](../../src/game/save.cpp),
> тесты в [tests/suite_saveload.inl](../../tests/suite_saveload.inl).

---

## 1. Поправка к постановке задачи

Мандат владельца просил авто-тесты на «**загрузку сейвов v6**». В дереве этого не
может быть:

```cpp
// save.cpp:492
if (h.version != kSaveVersion) return fail(SaveError::BadVersion);
```

`kSaveVersion = 9`. Проверка — **на точное равенство**, не на `>=`. Сейв v6
отвергается, как и v7, и v8. **Миграции в дереве нет ни одной.** Тест на загрузку
v6 написать нельзя, пока не написана миграция; и это не пробел в тестах, а
проектное решение, которое надо либо подтвердить, либо изменить.

## 2. Что построено — и построено аккуратно

История версий ведётся в самом файле, каждая версия названа с содержимым
(`save.h:81-106`):

| Версия | Что добавила |
|---|---|
| 2 | `QuestLog` |
| 3 | лог карв-операций |
| 4 | встроенный снимок активного этажа |
| 6 | **макромир целиком** — вся таблица `NpcPool` |
| 7 | лист персонажа `RpgStats` + банк крафта |
| 8 | состояние патронника + накопленный счёт убийств |
| 9 | живые статус-эффекты `StatusSet` |

**Главное решение сделано верно и повторено трижды.** `save.h:222`, `:228`,
`:237` — каждая структура пишется **поле за полем в little-endian, а не
`sizeof`**:

> Version 7: RpgStats wire — field-by-field LE, **NOT sizeof** (pad_ is written so
> the layout stays explicit)

Это ровно то, что делает сейв переносимым между Windows-хостом владельца и его
Mac. `sizeof`-дамп POD-структуры дал бы файл, зависящий от паддинга компилятора,
и разошёлся бы между двумя платформами молча. Автор написал это трижды и трижды
объяснил — переделывать нечего.

Есть даже защита от собственной ошибки роста (`save.cpp:405`):

> `ContractBook` is serialized; grow it and bump `kSaveVersion` in the same...

## 3. Что мир забывает при загрузке

Проверено грепом по `save.cpp` — ноль упоминаний:

| Символ | Упоминаний | Следствие |
|---|---|---|
| `SamosborState` | **0** | **часы самосбора сбрасываются** |
| `AiMemory` | **0** | **NPC забывают всё** |
| `RoomZones` | 0 | перепекается — законно |
| `FineNav` | 0 | перепекается — законно |
| `CoarseGraph` | 0 | перепекается — законно |

Три последних — **правильно**: они выводимы из геометрии, и `performance.md`
требует печь их при загрузке. Хранить их в блобе было бы дублированием истины.

Первые два — дыры, и разные по цене.

### 3.1. Часы самосбора не сохраняются

[Спека 06](06_SAMOSBOR_AND_CRISIS.md) описывает `SamosborState` как автомат с
`count`, переносимым через поездку (`samosbor_enter_floor`), кулдауном, зависящим
от глубины, и duty cycle до 93.8 % на \|z\|=50. Ничего из этого не в сейве.

Следствие: **сохранение и загрузка — это способ отменить самосбор.** Игрок в
активной фазе на глубине 50 сохраняется, загружается — и автомат в `Idle` с
нулевым `count`, то есть с самым длинным кулдауном. Центральная кризис-механика
обнуляется штатной кнопкой.

Цена исправления мала: `SamosborState` — это счётчик, фаза, тик перехода и
вариант. Единицы байт.

### 3.2. NPC забывают всё

[Спека 01](01_ALIFE_AND_UTILITY_AI.md) §2.4 нашла шесть видов памяти ИИ, из
которых у пяти нет производителей. Здесь — обратная сторона: **у той памяти,
что производится, нет персистентности.**

Житель, видевший игрока убийцей, после загрузки не помнит. Слух, прошедший по
`rumour`, исчезает. Это делает социальные системы `speech`/`rumour`/`vendor`
существующими **только внутри одного сеанса**, что противоречит их назначению:
репутация, которая не переживает сохранение, — не репутация.

**Но здесь есть настоящий проектный выбор**, и его надо сделать осознанно:
`NpcPool` — таблица на много тысяч голов. Память каждой головы, сохранённая
целиком, может весить больше остального блоба. Варианты:

| Вариант | Цена | Что теряется |
|---|---|---|
| Сохранять всю память | размер блоба ×N | ничего |
| Сохранять только «видел игрока» + репутацию | ~2 байта на голову | детали слухов |
| Не сохранять, признать сеансовой | 0 | вся социальная память |

**Рекомендация: второй.** Репутация игрока — то, ради чего система существует;
детали слухов восстановимы естественным путём. Первый вариант оптимизирует не то
измерение.

## 4. Проектируемые структуры

### 4.1. Версия 10 — часы самосбора

```cpp
// save.cpp — SAVSAM блок, по образцу SAVSTAT из версии 9.
// Поле за полем LE, НЕ sizeof — тот же закон, что для RpgStats и StatusSet.
//
// ПОЧЕМУ ОТДЕЛЬНЫМ БЛОКОМ, А НЕ ПОЛЯМИ В ГОЛОВНОЙ СТРУКТУРЕ:
// три предыдущие версии добавлялись именно так, читатель уже умеет
// пропускать незнакомый блок, и это единственная форма, которая
// позволит миграции из §4.3 работать.
void samosbor_write(Archive& ar, const SamosborState& s) {
    ar.u32(s.count);        // перенос через поездку — самое важное поле
    ar.u8 (s.phase);        // Idle/Warning/Active/Aftermath
    ar.u8 (s.variant);      // какой из 7
    ar.u64(s.phaseTick);    // когда фаза началась
    ar.u64(s.nextTick);     // когда следующий
}
```

### 4.2. Репутация — два байта на голову

```cpp
// Компактная память, переживающая загрузку. НЕ вся AiMemory.
struct NpcPersistentMemory {
    std::uint8_t sawPlayerKill : 1;   // видел убийство
    std::uint8_t wasHelped     : 1;   // игрок лечил/кормил
    std::uint8_t wasRobbed     : 1;   // игрок обокрал
    std::uint8_t knowsPlayer   : 1;   // вообще знаком
    std::uint8_t reserved      : 4;
    std::int8_t  attitude;            // -100..+100, свёрнутая репутация
};
static_assert(sizeof(NpcPersistentMemory) == 2);
```

При `NpcPool` в несколько тысяч голов это единицы килобайт — против сотен, если
сохранять память целиком.

### 4.3. Миграция или явный отказ от неё

Сегодня `if (h.version != kSaveVersion)` отвергает всё. Два честных пути, и
выбор — за владельцем:

```cpp
// ВАРИАНТ A: миграция вперёд. Читатель знает, какие блоки появились когда,
// и подставляет умолчания для отсутствующих.
if (h.version > kSaveVersion) return fail(SaveError::BadVersion);  // из будущего — нет
if (h.version < kMinMigratableVersion) return fail(SaveError::TooOld);
// дальше: блоки, добавленные после h.version, получают умолчания

// ВАРИАНТ B: отказ остаётся, но становится ЯВНЫМ решением с тестом.
// Тест утверждает: сейв версии 8 отвергается с BadVersion, а НЕ падает
// и НЕ читает мусор. Это тоже контракт, и он тоже требует пина.
```

**Вариант B дешевле и честнее для проекта в текущей фазе.** Пока формат меняется
раз в несколько недель, миграция — это N путей кода, каждый из которых надо
тестировать. Но отказ обязан быть **протестирован как отказ**, иначе неизвестно,
отвергает он или читает мусор.

## 5. Критерии приёмки

### 5.1. Часы самосбора

- [ ] Сохранение в активной фазе на \|z\|=50, загрузка → фаза и `count`
      **те же**. Прямая проверка, число к числу.
- [ ] Сохранение/загрузка **не** сбрасывает кулдаун. Это тест на то, что
      сохранение перестало быть способом отменить кризис.
- [ ] `kSaveVersion` поднят до 10, история версий в `save.h` дополнена строкой.

### 5.2. Память NPC

- [ ] Житель, видевший убийство, помнит это после загрузки.
- [ ] Размер блоба до/после печатается. Прирост укладывается в объявленный
      бюджет, и бюджет назван числом заранее.
- [ ] Решение по объёму памяти (весь / репутация / ничего) записано в `save.h`
      с причиной — иначе следующий правящий переоткроет вопрос.

### 5.3. Версионирование

- [ ] Тест: сейв версии 8 отвергается с `BadVersion`, **не** падает и **не**
      читает мусор. Проверка отказа, а не только успеха.
- [ ] Тест обратной полярности: рост `ContractBook` без подъёма `kSaveVersion`
      **роняет сборку**. Комментарий на `save.cpp:405` уже просит об этом;
      просьба в комментарии — не гейт.
- [ ] Ни одна структура не пишется через `sizeof`. Гейт:
      `rg 'ar\.(bytes|raw)\(.*sizeof' src/game/save.cpp` пуст. Это защита от
      единственной ошибки, которая расходит Windows и Mac молча.

### 5.4. Roundtrip

- [ ] Тест сравнивает **равенство данных** после цикла запись→чтение, а не
      только «загрузка не упала». Второе — это `green gate proving consistency,
      not reachability`, и оно проходит на пустом блобе.
- [ ] Перепекаемые поля (`RoomZones`, `FineNav`, `CoarseGraph`) после загрузки
      **непусты** — иначе перепекание не случилось, а сейв «успешен».

## 6. Порядок работ

```
A. Тест на отказ v8 (проверка отказа)   <- 20 минут, пинует текущее поведение
B. Гейт «нет sizeof в сейве»            <- 10 минут, защита Mac-сборки
C. Часы самосбора -> версия 10          <- единицы байт, закрывает отмену кризиса
D. Решение по объёму памяти NPC         <- решение владельца, не техническое
E. NpcPersistentMemory -> версия 11     <- зависит от D
F. Roundtrip на равенство данных        <- независим
G. Тест обратной полярности на рост     <- зависит от A
```

**A и B — полчаса на двоих**, и они пинуют то, что сегодня держится только
комментариями.

**C — лучшее соотношение цены к последствиям во всём документе:** единицы байт
закрывают возможность отменить центральную кризис-механику кнопкой сохранения.

## 7. Порядок полей внутри блока — закон, а не стиль

Поле за полем LE решает вопрос паддинга, но **не** вопрос порядка. Порядок полей
внутри блока — второй, независимый контракт, и он держится только тем, что
писатель и читатель написаны рядом.

```cpp
// ЛОВУШКА. Обе функции компилируются, гейт `нет sizeof` проходит,
// тест «загрузка не упала» проходит. Файл читается как мусор.
void write(Archive& ar, const S& s) { ar.u32(s.a); ar.u32(s.b); }
void read (Archive& ar,       S& s) { ar.u32(s.b); ar.u32(s.a); }  // <- порядок
```

Пока `a` и `b` — оба `u32`, ни один компилятор и ни один существующий тест этого
не заметят. Ловит только roundtrip на **равенство данных** с **различными**
значениями полей: `a=1, b=2`. Тест с `a=0, b=0` — а именно так выглядит
свежесконструированная структура — проходит при перепутанном порядке.

**Отсюда требование к тесту:** заполнять поля **различимыми** значениями, и ни
одно не оставлять нулём. Это дешевле любой схемы самоописания и ловит ровно тот
класс, который переживает все остальные проверки.

## 8. Что сейв не может выразить в принципе

Три вещи не «забыты» — они **невыразимы** в текущей форме блоба, и каждая
требует решения раньше кода.

| Что | Почему невыразимо |
|---|---|
| Незавершённое действие | Интент — это результат ежекадрового скоринга, а не хранимое поле. NPC на полпути к кухне после загрузки пересчитает интент с нуля. |
| Полёт снаряда | Пул снарядов не в блобе. Сохранение в момент выстрела теряет выстрел. |
| Незакрытый карв | Очередь предложений карва (`kMaxCarveProposals`) — кадровая, не сохраняемая. |

Первое — **правильно** и должно остаться. Интент, восстановленный скорингом,
всегда согласован с миром; интент, поднятый из файла, может ссылаться на комнату,
которую самосбор уже съел. Это ровно тот случай, когда **не** сохранять — сильнее.

Второе и третье — тоже правильно, но по другой причине: их время жизни короче
кадра ожидания, и игрок не может сохраниться «в момент выстрела» иначе как
скриптом. Записать это решение в `save.h` явно — иначе следующий правящий увидит
пропуск, а не решение.

**А вот четвёртое — настоящая дыра.** Состояние лифта. Если поездка между этажами
это последовательность шагов (см. спеку по лифтам), сохранение **в кабине** либо
невыразимо, либо восстановится в геометрию, которой на новом этаже нет. Проверить
до того, как писать версию 10.

## 9. Явные не-цели

- **Не переходить на `sizeof`-дамп ради скорости.** Поле за полем — это то, что
  делает сейв переносимым между двумя хостами владельца. Автор написал это
  трижды и трижды объяснил.
- **Не сохранять `FineNav`/`CoarseGraph`/`RoomZones`.** Они выводимы из
  геометрии; хранить их — дублировать истину и создавать возможность
  расхождения.
- **Не писать миграцию с v2.** Восемь путей кода, каждый со своим тестом, ради
  сейвов, которых ни у кого нет. Если миграция понадобится — только вперёд с
  ближайшей версии.
- **Не сохранять всю `AiMemory` без замера.** Несколько тысяч голов × полная
  память может превысить остальной блоб. Сперва число, потом решение.
