## 2. Пять дефектов, найденных сверкой

### 2.1. Предикатная цепочка существует ДВАЖДЫ

Одно и то же правило «номер этажа → тип» реализовано в двух местах:

| Реализация | Где | Форма |
|---|---|---|
| **Авторитетная** | `build_default_floor_catalog`, [floor_catalog.cpp:65](../../src/game/floor_catalog.cpp) | строки данных с предикатами |
| **Дубль** | `floor_spec_for(int)`, [floor_spec.cpp:58-73](../../src/game/floor_spec.cpp) | та же цепочка как `if`/`else if` |

Каталог — единственный, кого спрашивают о типе в рантайме
([main.cpp:872](../../src/app/main.cpp): `return floor_catalog().resolve(number).kind;`).
`floor_catalog.cpp:46` помечает `floor_spec_for` как вытесненный, но он **жив** и
поставляет набор правил (население, фракции, враждебность).

Предикаты, дублированные буквально:

```cpp
bool pat_hub(int n)             { return n == 0; }              // Residential
bool pat_padic_extreme(int n)   { return mag(n) >= 25; }        // Padic
bool pat_derelict_deep(int n)   { return mag(n) >= 20; }        // Derelict
bool pat_padic_mod(int n)       { return mag(n) % 11 == 10; }   // Padic
bool pat_derelict_mod(int n)    { return mag(n) % 7 == 6; }     // Derelict
bool pat_industrial_mod(int n)  { return mag(n) % 5 == 4; }     // Industrial
bool pat_commercial_mod(int n)  { return mag(n) % 3 == 2; }     // Commercial
// pat_all -> Residential (catch-all)
```

**Почему это опасно именно здесь.** Правка одной цепочки без другой даёт этаж, у
которого **тип из каталога, а правила из спека не совпадают** — население
жилого дома на промышленной геометрии. Компилятор молчит, тест этого не ловит,
а симптом выглядит как «генератор странно себя ведёт».

Явные заявки перебивают предикаты: padic заявляет номер 4
([floor_catalog.cpp:79](../../src/game/floor_catalog.cpp)) — и там же отмечено,
что по одним предикатам 4 был бы Industrial через `4 % 5 == 4`. То есть цепочки
уже расходятся с заявками, и это управляется вручную.

### 2.2. Шаблонов комнат нет — тип комнаты это хэш координат

Мандат просил «шаблоны комнат». В дереве шаблонов нет: тип комнаты —
**детерминированный хэш координат**, `floor_room_mask(kind, number, rx, ry)`
([floor_gen.h:136](../../src/game/floor_gen.h)). Размер — один скаляр на тип
этажа, `floor_room_stride(FloorKind)` ([floor_gen.h:75](../../src/game/floor_gen.h));
интерьер `(stride-1)²` = 9 клеток при stride 4.

Существует таблица **содержимого**, `kRoomFurniture[]`
([room_zone.h:251-263](../../src/game/room_zone.h)), 6 строк:

```cpp
struct RoomFurniture {          // room_zone.h:229
    std::uint16_t room;         // RoomBit
    std::uint16_t prop;         // PropId
    std::uint8_t slot;          // 0..kRoomSlots-1
    bool useSpot;               // может ли NPC встать К нему
};
```

Покрытие: Kitchen (плита + стол), Bathroom (два унитаза), Living (две койки).
**7 типов комнат из 11 — без мебели вообще:** Storage, Common, Office, Medical,
Production, Smoking, Hq, Corridor.

11 типов, enum `RoomBit` — [mob_table.h:117-128](../../src/game/mob_table.h),
`kFloorRoomBits = 11`.

### 2.3. Поля комнат заполнены на 3 из 11 слотов

`RoomZones` ([room_zone.h:331-345](../../src/game/room_zone.h)) — 5 полей, все
живые, но два массива заполнены частично:

| Поле | Пишет | Читает | Состояние |
|---|---|---|---|
| `kind` | `bake_room_zones` | `ai.cpp:593,798` | живое |
| `number` | то же | `ai.cpp:798` | живое |
| `baked` | `room_zone.cpp:319,365` | `room_zone.cpp:507` | живое |
| `flow[11]` | `bake_flow` | `room_zone.cpp:523,524` | **3 слота из 11** |
| `nearRoom[11]` | `bake_near` | `room_zone.cpp:523,527` | **3 слота из 11** |

Заполняются только биты из `kRoomFieldMask` — Kitchen, Bathroom, Living.
**8 слотов каждого массива пусты постоянно.** Это ровно тот же разрыв, что
[спека 01](01_ALIFE_AND_UTILITY_AI.md) §2.2 нашла со стороны ИИ: у `work`,
`social`, `patrol` нет строки аффорданса, потому что **некуда идти** — поля их
комнат никогда не пеклись.

> **ЗАКРЫТО 2026-08-12, и «три слота» было ЗАНИЖЕНИЕМ.** Три — потолок, взятый
> только на Residential: бейк пересекает `kRoomFieldMask` со смесью комнат этажа,
> а Commercial, Industrial и Padic не содержат ни Kitchen, ни Bathroom, ни Living.
> На **шести демо-этажах из десяти** не пеклось ничего, `ready()` был false и
> ветка поручений была выключена целиком. Добавлены `IntentSocial → Common` и
> `IntentWork → Production`. Замер и три сознательных отказа —
> [problems.md](../../problems.md) §49.

> **Про «мёртвый метод» ниже — утверждение НЕВЕРНО, проверено 2026-08-12.**
> `ready()` вызывается в `ai.cpp:592` (`const bool useRooms = (rooms != nullptr)
> && rooms->ready();`) — это гейт **всей** ветки поручений, то есть самый
> нагруженный смыслом вызов во всей системе комнат, — и ещё трижды в
> `tests/suite_rooms.inl`. `room_route` действительно проверяет `mask & z.baked`,
> но это не «вместо», а вторая, более узкая проверка на другом уровне.

Один мёртвый метод: `ready()` ([room_zone.h:343](../../src/game/room_zone.h)) без
вызовов; `room_route` вместо него проверяет `mask & z.baked` напрямую
(`room_zone.cpp:507`).

### 2.4. `RoomRecovery`: 8 строк из 11 — нули

`RoomRecovery` ([room_zone.h:182-190](../../src/game/room_zone.h)) — 7 float-полей,
все пишутся строками таблицы и читаются `room_recover`. Но **8 из 11 строк
целиком нулевые**: Corridor, Common, Storage, Office, Medical, Production, Smoking,
Hq. (Заголовок этого раздела говорил «7», а перечисление под ним называло восемь;
пересчитано по коду 2026-08-12. Та же описка разошлась в
[спеку 14](14_NEEDS_AND_SURVIVAL.md) §8 и в
[роадмап](../MASTER_ROADMAP.md) §12a.2 — там же, где соседняя строка про мебель
называет «7 из 11» при восьми перечисленных видах.)

**Восемь нулей и восемь непечёных полей — это НЕ одно и то же множество, и путать
их дорого.** С 2026-08-12 Common и Production имеют аффорданс и печутся, а строки
восстановления у них по-прежнему нулевые — сознательно: таблицы независимы,
общение и работа никого не кормят, а референсные ставки Common и Office гейтятся
часами, которых в сборке нет.

Две из них — **осознанно отложенные**, и это задокументировано
(`room_zone.h:165-180`): Office требует часов, Medical — банка лечения на толпу.
Остальные пять — просто пусты.

### 2.5. Аномалий этажей не существует

Мандат просил «генерируемые аномалии этажей». Проверка:

```
rg 'anomaly|Anomaly|hazard|Hazard|modifier|Modifier|FloorRule|special_rule' src/
```

19 файлов, **ни одного этажного**: модификаторы урона в `combat`/`status`,
модификаторы рецептов в `craft`, черты мобов в `monster_traits`. Ни `FloorRule`,
ни `Anomaly`, ни `FloorModifier` в дереве нет.

Ближайшее — пара хуков модуля padic, `padic_declare_rules` / `padic_apply_rules`
([padic.h:81,88](../../src/game/floors/padic/padic.h)). Это хук на модуль, а не
таблица видов аномалий.

### 2.6. Размещение пропов не имеет бюджета

`seed_room_furniture` ([room_zone.cpp:446-498](../../src/game/room_zone.cpp)),
вызывается раз на вход в этаж (`main.cpp:1082`). Тип комнаты читает
(`room_zone.cpp:457,459`).

**Ни одной бюджетной константы:** нет максимума пропов, нет лимита на комнату.
Цикл исчерпывающий по решётке × 6 строк мебели. Ограничители только
геометрические: `blocked(grid, cx, cy, z)` (`:466`) и `floor.height < 0.0f`
(`:468`, «no honest solid support»).

Фактический потолок структурный: при stride 4 это 32×32 = **1024 комнаты**, и
комната получает 0 или 2 предмета в зависимости от хэша. То есть бюджет есть, но
он **следствие** геометрии, а не решение дизайнера, и при смене stride он
меняется молча.

## 3. Проектируемые структуры

### 3.1. Одна цепочка предикатов вместо двух

```cpp
// src/game/floor_catalog.h — floor_spec_for перестаёт дублировать цепочку
// и начинает СПРАШИВАТЬ каталог.
//
// ПОЧЕМУ НЕ УДАЛИТЬ floor_spec_for ЦЕЛИКОМ: он поставляет набор правил
// (население, фракции, враждебность), а каталог — тип. Это две разные
// работы. Дублируется только РЕШЕНИЕ О ТИПЕ, и убрать надо именно его.
inline FloorSpec floor_spec_for(int number) {
    const FloorKind kind = floor_catalog().resolve(number).kind;
    return kFloorSpecs[static_cast<std::size_t>(kind)];
}
```

Один вызов вместо восьми `if`. Расхождение становится невозможным по построению —
это сильнее любого теста на согласованность.

### 3.2. Аномалии как строки таблицы, а не как код

```cpp
// src/game/floor_anomaly.h — НОВЫЙ.
//
// ФОРМА СКОПИРОВАНА С kSamosborVariants: POD-строка, фиксированная точка
// x100 вместо float, имя вне строки, чтобы строка осталась
// pointer-free и тривиально сериализуемой. Тот шаблон в этом дереве
// уже доказан семь раз.
struct FloorAnomalyDef {
    std::uint8_t anomaly;         // FloorAnomaly; == индекс строки
    std::uint8_t weight;          // вес выбора
    std::uint8_t dangerMultX100;  // множитель к floor_danger
    std::uint8_t lightMultX100;   // множитель к освещению
    std::int8_t  gravityDeltaX10; // сдвиг гравитации, -30..+30
    std::uint8_t fogBaseX100;     // базовый туман БЕЗ самосбора
};
static_assert(sizeof(FloorAnomalyDef) == 6);

// Аномалия — свойство НОМЕРА, не слота. Она обязана быть детерминированной
// функцией (number, worldSeed), иначе перезаход на этаж её меняет —
// та же ошибка, что samosbor_new_game на каждой поездке
// (samosbor.h:513-535).
FloorAnomaly floor_anomaly_for(int number, std::uint32_t worldSeed);
```

**Почему `gravityDeltaX10` — самая ценная строка таблицы.** Гравитация в этом
движке уже вектор, `GravityRegime` уже имеет 8 режимов, и
[спека 02](02_VOXEL_PHYSICS_AND_FLUIDS.md) §5.1 ставит гейт изотропии на все
восемь. Аномалия «этаж с инвертированной гравитацией» — это **бесплатный**
геймплей поверх уже существующей и уже гейтящейся механики. Ни строки новой
физики.

### 3.3. Шаблон комнаты — надстройка над хэшем, а не замена

```cpp
// src/game/room_template.h — НОВЫЙ.
//
// Хэш координат остаётся источником ТИПА комнаты: он детерминирован,
// не требует памяти и уже работает. Шаблон добавляет СОДЕРЖИМОЕ.
//
// ПОЧЕМУ НЕ ЗАМЕНЯТЬ ХЭШ АВТОРСКОЙ РАСКЛАДКОЙ: 1024 комнаты на этаж
// при 255 этажах — это 261 тысяча комнат. Авторская раскладка такого
// объёма невозможна, а генератор поверх хэша даёт вариативность
// бесплатно. Тот же довод, по которому samosbor.h отказался от
// авторской кривой в пользу lerp по |z|.
struct RoomTemplate {
    std::uint16_t room;          // RoomBit — какому типу принадлежит
    std::uint8_t  variant;       // 0..3, вариантов раскладки на тип
    std::uint8_t  weight;        // вес выбора варианта
    std::uint8_t  propCount;     // сколько строк мебели ниже
    std::uint8_t  firstProp;     // индекс в общий массив RoomFurniture
    // Бюджет ЯВНЫЙ, а не следствие stride — закрывает §2.6.
    std::uint8_t  maxProps;
};
```

Это **расширяет** `kRoomFurniture`, а не отменяет: сегодняшние 6 строк
становятся вариантом 0 для своих трёх типов, и восемь пустых типов получают по
строке.

## 4. Алгоритмы

### 4.1. Печь поля всех 11 комнат, а не трёх

```
bake_room_zones(...):
    # СЕГОДНЯ: kRoomFieldMask ограничивает работу тремя битами.
    # ПОСЛЕ: маска строится из того, что кто-то ЧИТАЕТ.
    #
    # НЕВЕРНО, исправлено 2026-08-12 — эта строка ошибалась на три порядка
    # по памяти и была самой дорогой ошибкой в спеке: тот, кто реализовал
    # бы её как написано, ожидал бы ~2 КиБ и ~1 мс на бит.
    #
    # Стоимость: 11 полей вместо 3. Каждое — ДВЕ вещи, а не одна:
    #   bake_flow — многоисточниковый BFS по ВСЕМУ 128^3 (2 097 152 клетки),
    #               плотное поле в 1 байт на макроклетку = 2.000 МиБ на бит;
    #   bake_near — вот ЭТО решётка 32x32 = 1024 узла, 2 048 байт на бит.
    # Итого 2 099 200 байт на бит. Решётка комнат — второй, копеечный
    # продукт, а не единственный.
    #
    # По времени дёшево и правда, но по другой причине: bake_walkable
    # считается ОДИН раз на все биты, а сами биты идут через parallel_for,
    # который уже перебирает все 11 индексов и просто выходит из ненужных.
    #
    # Потолок на этаж задаёт НЕ 11, а смесь: ни один вид этажа не объявляет
    # больше 6 видов комнат, поэтому худший реальный случай — 6 бит ~ 12 МиБ,
    # а не 11 бит ~ 22 МиБ.
    for bit in all 11 RoomBits:
        if nobody_reads(bit): continue      # честный пропуск, не молчаливый
        bake_flow(bit)
        bake_near(bit)
    # Печатать, СКОЛЬКО битов испеклось. Три из одиннадцати должно
    # выглядеть как решение, а не как норма.
    log("[rooms] baked %u of %u fields", bakedCount, kFloorRoomBits);
```

Это разблокирует три интента ИИ из [спеки 01](01_ALIFE_AND_UTILITY_AI.md) §2.2
одним изменением: `work` → Production/Office, `social` → Common/Smoking,
`patrol` → Corridor.

### 4.2. Аномалия входит в генерацию одной точкой

```
generate_floor(number, seed):
    kind    = floor_catalog().resolve(number).kind
    spec    = floor_spec_for(number)               # теперь спрашивает каталог
    anomaly = floor_anomaly_for(number, seed)      # НОВОЕ, детерминированно

    # Аномалия МОДИФИЦИРУЕТ, а не подменяет. Все три множителя
    # применяются к уже посчитанным значениям, поэтому этаж без
    # аномалии (weight 0) генерируется байт-в-байт как сегодня —
    # это и есть критерий обратной совместимости.
    danger  = floor_danger(number) * anomaly.dangerMultX100 / 100
    gravity = base_gravity + anomaly.gravityDeltaX10 / 10.0f
    fogBase = anomaly.fogBaseX100 / 100.0f          # спека 06 §5.1
```

## 5. Критерии приёмки

### 5.1. Одна цепочка

- [ ] `floor_spec_for` не содержит ни одного предиката типа. Гейт:
      `rg '% 11 == 10|% 7 == 6|% 5 == 4|% 3 == 2' src/game/floor_spec.cpp` пуст.
- [ ] Тест: для всех номеров −127..127 тип из `FloorCatalog::resolve` и тип,
      подразумеваемый `floor_spec_for`, совпадают. **255 номеров — полный
      перебор**, а не выборка.

### 5.2. Поля комнат

- [ ] Каждый прогон печатает `[rooms] baked N of 11`.
- [ ] Все 11 полей печутся, либо непеченые перечислены явно с причиной.
- [ ] Время бейка комнат печатается и укладывается в бюджет загрузки этажа.
- [ ] `ready()` либо получает вызов, либо удаляется.

### 5.3. Мебель и бюджет

- [ ] Каждый из 11 типов комнат имеет хотя бы одну строку мебели, либо помечен
      отложенным с причиной — как уже сделано для Office и Medical.
- [ ] `maxProps` **явный**. Гейт: смена `floor_room_stride` не меняет число
      пропов на этаж больше, чем на заданный допуск.
- [ ] Печатается число размещённых пропов на этаж.

### 5.4. Аномалии

- [ ] Аномалия детерминирована по `(number, worldSeed)`: перезаход на этаж даёт
      ту же аномалию. Прямая проверка, и она ловит ровно ту ошибку, что
      `samosbor_new_game` на каждой поездке.
- [ ] Этаж с `weight 0` генерируется **байт-в-байт** как до изменения.
- [ ] Аномалия гравитации проходит гейт изотропии из
      [спеки 02](02_VOXEL_PHYSICS_AND_FLUIDS.md) §5.1 — все восемь режимов.
- [ ] Аномалия попадает в сейв или выводится из seed. Второе предпочтительно:
      меньше полей в блобе.

### 5.5. Реестр

- [ ] Тест на `LevelStack::above(kInvalidLayer)`: не возвращает слой 0.
      Обёртка `w < layers_.size()` — единственное, что это держит
      ([level_stack.h:42-48](../../src/world/level_stack.h)), и её надо
      пинуть тестом, а не комментарием.
- [ ] `next_labelled_floor` — единственный способ шагать по этажам. Гейт: нет
      арифметики `layer ± 1` вне `level_stack.h`.

## 6. Порядок работ

```
A. Слить цепочку предикатов в одну      <- 20 минут, снимает класс расхождения
B. Тест перебором 255 номеров           <- гейт под A
C. Печь все 11 полей комнат             <- разблокирует 3 интента ИИ
D. Мебель для 8 пустых типов            <- зависит от C
E. Явный maxProps                       <- независим
F. Тест LevelStack::above(invalid)      <- 10 минут
G. FloorAnomaly (таблица + генерация)   <- зависит от A
H. Аномалия гравитации                  <- зависит от G и гейта изотропии
I. RoomTemplate варианты                <- зависит от D
```

**A первым: 20 минут работы снимают целый класс расхождений**, который сегодня
удерживается только вниманием правящего.

**C — самая высокая отдача на единицу работы во всём документе.** Один бейк
разблокирует три интента ИИ, которые уже написаны, уже вызываются и сегодня
никогда не выигрывают, потому что им некуда идти.

## 7. Явные не-цели

- **Не заменять хэш комнат авторской раскладкой.** 261 тысяча комнат не
  размечается руками; генератор поверх хэша даёт вариативность бесплатно.
- **Не делать аномалии кодом в модуле.** `padic_declare_rules` — хук на модуль;
  аномалии обязаны быть строками таблицы, иначе каждая новая аномалия — это
  новый `.cpp`, а не новая строка.
- **Не расширять `FloorRegistry` за 255 этажей** без замера: три плотных массива
  на 255/256 слотов — это 1.5 КБ, и они дают O(1). Разреженная замена дала бы
  хэш в горячем пути.
- **Не трогать `dirWeight = floor < 0 ? 4.0f : 1.0f`.** Спуск опаснее подъёма —
  это дизайн, зафиксированный в `floor_spec.cpp:80`, а не асимметрия-дефект.
