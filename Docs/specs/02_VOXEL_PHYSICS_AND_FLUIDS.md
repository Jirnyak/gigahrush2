**Ловушка, из-за которой это читается как построенное.** Засев живой:

подавление спавна на мокром (`mob_spawn.cpp:50,235,605`), флотация ящиков

об этом не знает.

**Почему мёртвое не воскрешают тривиально.** [performance.md](../../performance.md)

не засеял» (эта причина записана в [ARCHITECTURE.md](../../ARCHITECTURE.md) и она
**ложная** — там же и опровергнута).

## 2. Контекст и проблемы кода

### 2.1. Карвинг: очередь на 128 с молчаливым отбрасыванием

[combat.h:600-626](../../src/game/combat.h):

```cpp
inline constexpr std::size_t kMaxCarveProposals = 128;
struct CarveProposalQueue {
    CarveProposal items[kMaxCarveProposals];
    std::uint8_t count;
    bool push(...) {
        if (count >= kMaxCarveProposals) return false;   // <- тишина
        if (radius <= 0 || power == 0) return false;     // <- вторая тишина
        // radius молча зажимается до 8.0 м                <- третья
    }
};
```

Ни счётчика, ни лога, ни ассерта. Мили — `combat.cpp:1597` — **отбрасывает
возвращаемое значение полностью**. Второй молчаливый сброс: `main.cpp:3840`
игнорирует всю очередь, пока идёт бейк (`doors.frozen`), то есть во время
перепекания навигации попадания в стену не разрушают ничего.

Это прямое нарушение правила [AGENTS.md](../../AGENTS.md) §Measure the thing:
«**Print the number every run**».

### 2.2. `kSubDim` — не однострочный переключатель, вопреки двум документам

[types.h:6-7](../../src/world/types.h) и [voxels.md:31-33](../../voxels.md)
обещают: сменить `kSubDim` на 16 — правка одной строки. **Это неверно.**
`destruct.cpp` зашивает 8³ и 128³ в упаковку ключей:

| Сайт | Литерал | Что означает |
|---|---|---|

| `destruct.cpp:23-28` | `&127`, `>>7`, `>>14` | 128 макро-клеток |
| `destruct.cpp:39-41` | `>>3`, `&7` | 8 субвокселей на ось |
| `destruct.cpp:46,51,53,61-64` | `>>9`, `&511` | то же |
| `destruct.cpp:209,318-319,346` | `>>9`, `&511` | то же |

`subfield.h` и `macro_grid.h` — чистые, они выведены из констант. Дефект локален в
одном файле, но обещание в документах ложное, и это класс §23 «документы,
расходящиеся с кодом».

### 2.3. Жидкость: анизотропия и обход `regime_down`

`fluid.cpp:76-84` резолвит «низ» **собственным** классификатором по
`gravity().global`, минуя `regime_down()` и региональные переопределения — при том
что [gravity.h:16-22](../../src/world/gravity.h) прямо называет «fluid's down
axis» каноническим клиентом `regime_down`.

Следствие при `GravityRegime::Zero`: условие `ax >= ay && ax >= az` вырождается в
`0>=0 && 0>=0` → истина → **вода течёт в +X в мире без гравитации**.

Вторая анизотропия: `fluid.cpp:125-144` уменьшает `remaining` **внутри** цикла по
четырём соседям, поэтому `+a0` получает полный остаток, а `-a1` — минимальный.
Обещание независимости от порядка ([fluid.h:11-12](../../src/sim/fluid.h))
выполняется по клетке, но не по соседям.

### 2.4. Структурной прочности нет; то, что похоже на неё — мертво

Существуют две частичные вещи, и обе с оговорками.

**Открепление** (`destruct.cpp:187-215`) — это **связность, а не нагрузка**.
Ограниченный 6-связный заливкой обход от каждого соседа удалённого вокселя; если
компонента полностью перечисляется в пределах `detachLimit` (по умолчанию 512
субвокселей = одна клетка), она падает. [destruct.h:31-35](../../src/world/destruct.h)
честно пишет ограничение: **на торе нет «земли»**, поэтому большая подрытая плита
остаётся стоять.

**Песочная модель напряжений** (`cellular.h:26-35`, `cellular.cpp:364-379`) —
задуманная структурная модель, и она **полностью недостижима**. `cellular_step`,
`cellular_tick`, `CellularDriver`, `cellular_add` не имеют ни одного вызова.
`cellular.cpp:103-107` пишет о себе: *«this whole translation unit is
unreachable»*. При этом GLOB её компилирует и линкует в каждый бинарник.

Две мины внутри мёртвого кода, которые сработают при подключении:
- **Обрушение зашито в −Z** (`cellular.cpp:365-369`): `below = i + g.zm`,
  `zb = wrap_macro(z - 1)`. Ни одного чтения гравитации во всём файле. При `PosZ`
  это обрушает потолок.
- **`tests/suite_cellular.inl` не существует.** Файл цитируется в `cellular.h:67,
  147, 310, 376` и `cellular.cpp:285,348` как источник доказательств. Значит
  **каждое измеренное число в этом файле — непроверенное**.

### 2.5. Трубы — только меш; сети для газа нет

`bake_pipes` ([antourage.cpp:253-524](../../src/game/antourage/antourage.cpp))
строит настоящий граф: узел — это **`(клетка, грань)`**, 6 граней на клетку,
плотный `std::vector<NetNode> net(kMacroCells * 6)`, многоисточниковый Дейкстра на
вёдрах с ценой изгиба 3 и прямого шага 1.

Но: `net` и `dist` — **локальные переменные `bake_pipes`**. Они умирают на
возврате; переживают только меш-инстансы и статистика. Плюс закон антуража
([antourage.cpp:97-99](../../src/game/antourage/antourage.cpp)): *«PURE MESH:
nothing is written into the grid»*, а трубы занимают **воздушные** клетки. Значит
поле газа на макро-сетке не может отличить «внутри трубы» от «в комнате».

## 3. Проектируемые структуры

### 3.1. Гейт очереди предложений — закрытие §2.1 одной строкой на сайт

```cpp
// src/game/combat.h — CarveProposalQueue обзаводится счётчиками отказов.
// Ни байта на горячем пути: три uint16 рядом с count.
struct CarveProposalQueue {
    CarveProposal items[kMaxCarveProposals];
    std::uint8_t count = 0;
    // ПОЧЕМУ СЧЁТЧИКИ, А НЕ ЛОГ: AGENTS.md «Print the number every run».
    // Молчаливое отбрасывание неотличимо от «никто не стрелял», и разница
    // видна только как «стена почему-то цела» — то есть как баг геймплея.
    std::uint16_t droppedFull = 0;    // очередь была полна
    std::uint16_t droppedDegenerate = 0; // radius<=0 или power==0
```

HUD и лог печатают их каждым прогоном рядом с существующими числами. Если
`droppedFull` вообще ненулевой при 128 слотах — это сигнал, что бой генерирует
больше предложений, чем дизайн предполагал, и число решает спор о размере
очереди вместо интуиции.

### 3.2. Газ как ПЕРВОЕ поле на GPU — образец для всех остальных

Газ, а не вода, должен быть первым по трём причинам: поле уже засеяно и никем не
читается (значит ничего не сломается), у него нет потребителей с ожиданиями, и
геймплей от него виден мгновенно (удушье, факел, видимость).

```glsl
// shaders/gas_sim.comp — НОВЫЙ. Форма ровно как у particle_sim.comp,
// который уже работает: один диспатч на 128^3, двойная буферизация.
layout(local_size_x = 8, local_size_y = 8, local_size_z = 4) in;

layout(std430, binding = 0) readonly  buffer GasIn  { float gIn[];  };
layout(std430, binding = 1) writeonly buffer GasOut { float gOut[]; };
layout(std430, binding = 2) readonly  buffer Class  { uint  cls[];  };

layout(push_constant) uniform Push {
    ivec4 downStep;   // regime_down(), НЕ литерал -Z. Изотропия — закон.
    vec4  params;     // x=rate, y=buoyancy, z=evaporate, w=dt
} pc;

void main() {
    // Плотная 6-точечная релаксация с no-flux на твёрдых клетках, плюс
    // снос ПРОТИВ вектора гравитации (газ легче воздуха). Целочисленных
    // атомиков нет, гонок нет, поэтому результат бит-точен на любом GPU
    // — то же требование, что манифест ставит самосбору.
}
```

**Закон изотропии на GPU.** `downStep` приходит push-константой из
`regime_down(world.gravity().regime)`. Ни одного литерала оси в шейдере — именно
та ошибка, которая уже сидит в `cellular.cpp:365` и в `fluid.cpp:81`.

### 3.3. Структурная прочность: напряжение как поле, «земля» как якорь

На торе нет земли — это настоящая причина, по которой открепление не может быть
структурной моделью. Решение — **объявить якорь явно**, а не искать его
топологически:

```cpp
// src/world/destruct.h — ДОПОЛНЕНИЕ
// Якорь: клетка, которая держит НАГРУЗКУ и сама не падает никогда.
// На торе такой клетки нет по построению, поэтому она НАЗНАЧАЕТСЯ модулем
// этажа: несущие стены, шахты лифтов, гермокапсулы. Ровно тот же приём,
// что kHardnessUnbreakable уже применяет к прочности.
inline constexpr std::uint16_t kAnchorFieldName[] = "anchor";

struct StressParams {
    float carryPerHardness = 1.0f; // сколько веса держит единица твёрдости
    float collapseAt = 1.0f;       // доля превышения, за которой клетка идёт
    int   relaxIters = 4;          // итераций релаксации на бейк
};
```

Алгоритм — **бейк, не тик**, ровно по правилу «bake at load, tick in O(1)»:
напряжение считается один раз при загрузке и после самосбора, а карвинг во время
игры трогает только грязный регион (regime 2 из
[performance.md](../../performance.md)).

### 3.4. Сеть труб как переживающая бейк структура

Чтобы газ пошёл по трубам, граф `(клетка, грань)` обязан пережить `bake_pipes`.
Плотный вектор на 12.6 М узлов хранить незачем — нужен только **компонент
связности на грань**:

```cpp
// src/game/antourage/antourage.h — ДОПОЛНЕНИЕ к результату бейка
struct PipeNetwork {
    // Метка компоненты связности для каждой (клетка, грань). 0 = не труба.
    // 6 граней * 2^21 клеток = 12.6 М байт при uint8 -> 12 МиБ, и это
    // ПЛОТНО, как требует AGENTS.md «dense over sparse».
    std::vector<std::uint8_t> component; // kMacroCells * 6
    std::uint8_t componentCount = 0;
    // Объём газа в каждой компоненте — вот что делает трубу проводником,
    // а не картинкой. Компонент десятки, поэтому массив крошечный.
    float volume[256] = {};
};
```

Теперь «газ идёт по вентиляции» — это перенос между компонентами, а не диффузия
по комнате, и разрушение трубы (`antourage_carve_step` уже знает, какие куски
перерезаны) **разрывает компоненту** и стравливает газ в помещение.

## 4. Алгоритмы и псевдокод

### 4.1. Напряжение: релаксация от якорей

```
bake_stress(grid, anchorField, out stressField):
    # Шаг 1: якоря держат бесконечность, воздух не держит ничего.
    for each cell c:
        stress[c] = is_anchor(c) ? INF : (is_solid(c) ? 0 : NONE)

    # Шаг 2: релаксация. Клетка получает поддержку от соседей
    # ПРОТИВ вектора гравитации — то есть снизу, если гравитация вниз.
    # Направление берётся из regime_down(), НЕ из литерала.
    down = regime_down(grid.gravity().regime)
    repeat relaxIters times:                       # parallel_for по срезам z
        for each solid non-anchor cell c:
            support = stress[c - down]             # клетка «под» нами
            stress[c] = min(support * kFalloff,
                            hardness(c) * carryPerHardness)

    # Шаг 3: то, что не получило поддержки, помечено как висящее.
    # Оно НЕ падает при бейке — падает при следующем карвинге рядом,
    # иначе загрузка этажа обрушит половину декораций.
```

**Почему релаксация, а не точное решение.** Точная задача — линейная система на
2 М неизвестных. Четыре итерации дают качественно верный ответ (плита без опор
имеет нулевое напряжение, плита у якоря — высокое) за O(n·4), и это укладывается в
бейк. Правило «дёшево и приблизительно» — прямая цитата regime-2.

### 4.2. Обрушение при карвинге — уже есть половина механизма

```
on_carve(result):
    # detach_sweep уже вернул компоненты, которые отвалились. Расширяем
    # критерий: не только «маленькая компонента», но и «нулевое напряжение».
    for each cell in result.dirtyCells:
        for each solid neighbour n of cell:
            if stress[n] <= 0:
                queue_collapse(n)        # в СУЩЕСТВУЮЩУЮ очередь предложений

    # Обрушение — это карвинг, а не новая система. Оно течёт по тому же
    # CarveProposalQueue, через то же зеркало, теми же dirtyCells.
    # Один путь применения, много предложителей — закон, который в дереве
    # уже действует для частиц и для карвинга.
```

### 4.3. Огонь как поле поверх материала, а не новая сущность

`kMatFireCell` уже существует и уже наносит урон через `hazard_step`. Огню не
нужна отдельная система — ему нужно **поле температуры** и одна таблица:

```
fire_step(GPU):                                   # тот же compute, что и газ
    for each cell:
        # Горючесть — КОЛОНКА material_props, а не if-цепочка.
        heat[c] += flammability(material[c]) * oxygen[c] * dt
        heat[c] -= cooling * dt
        if heat[c] > ignitionPoint(material[c]):
            propose_material_change(c, kMatFireCell)  # предложение, не запись
        # Кислород тратится, дым рождается — два поля, одна форма.
        oxygen[c] -= burnRate * dt
        smoke[c]  += burnRate * dt * smokeYield(material[c])
```

Дым и кислород — те же плотные float-поля 8.4 МБ, тот же шейдер по форме. Три поля
(`heat`, `oxygen`, `smoke`) + газ = 33.6 МБ на этаж. Против бюджета RAM ~8 ГБ это
ничто; против **958 МиБ, которые уже занимает зеркало**
([04_RENDER_AND_ACOUSTICS.md](04_RENDER_AND_ACOUSTICS.md) §2) — тоже.

## 5. Критерии приёмки

### 5.1. Изотропия — гейт, которого нет и который всё это охраняет

Сегодня **ни один тест не гоняет физику под не-`NegZ` режимом**. Это и есть
причина, по которой §9/§15/§34 живут годами и по которой `cellular.cpp:365`
пережил весь антуражный проход изотропии.

- [ ] `suite_gravity_regimes.inl`: **все восемь** режимов `GravityRegime`,
      прогон падения, жидкости, обрушения и карвинга в каждом.
- [ ] При `Zero` вода **не течёт в +X** — сегодняшнее поведение падает этим
      тестом, что и требуется.
- [ ] `fluid.cpp` вызывает `regime_down()` и `axis_frame()`, а не собственный
      классификатор. Гейт: `rg 'downAxis' src/sim/fluid.cpp` пуст.

### 5.2. Карвинг

- [ ] Каждый прогон печатает `[carve] proposals=N dropped_full=N
      dropped_degen=N clamped=N`.
- [ ] `dropped_full` == 0 на обычном бою; ненулевое значение — предмет решения о
      размере очереди, а не тишина.
- [ ] Тест на `kSubDim`: либо `destruct.cpp` выводит сдвиги из констант, либо
      `static_assert(kSubDim == 8, "destruct.cpp key packing hardcodes 8^3")`
      и правка [voxels.md](../../voxels.md), убирающая ложное обещание.

### 5.3. Газ (первое GPU-поле)

- [ ] Газ, выпущенный в герметичной комнате, **не покидает её** за 60 с.
      Прямая проверка no-flux на стенах.
- [ ] Открытая дверь — газ уходит; закрытая — нет. Дверь уже есть
      (`door.cpp`, `dirtyCells`), поле обязано её видеть.
- [ ] Бит-точность: два прогона с одним seed дают побайтово равные поля.
      Целочисленный автомат без атомиков — это требование выполнимо и обязано
      быть проверено, иначе реплей самосбора из манифеста невозможен.
- [ ] Стоимость диспатча печатается в `gpu_timer` **как отдельный канал**.
      Сегодня канала нет — см. [спеку 04](04_RENDER_AND_ACOUSTICS.md) §6.

### 5.4. Структурная прочность

- [ ] Плита, подрытая до якоря, **падает**; плита у якоря — стоит.
      Оба случая — числа в тесте, а не скриншот.
- [ ] Обрушение идёт через `CarveProposalQueue`, а не пишет в сетку напрямую.

## 6. Порядок работ

```
A. Счётчики очереди карвинга          <- 30 минут, снимает молчание
B. suite_gravity_regimes (8 режимов)  <- ГЕЙТ. Ставится ДО правок, красным
C. fluid.cpp -> regime_down/axis_frame<- падает под B, чинится под B
D. Гейт «система без вызова»          <- ловит cellular и всё будущее
E. Решение по cellular.cpp            <- удалить или починить, D заставляет
F. Газ на GPU (первое поле)           <- образец для остальных полей
G. Поле напряжений + обрушение        <- зависит от F (та же compute-форма)
H. Огонь/дым/кислород                 <- зависит от F
I. PipeNetwork переживает бейк        <- зависит от F, даёт вентиляцию
```

**B — первый содержательный шаг.** Гейт, поставленный до правок и падающий,
доказывает, что дефект существует; гейт, поставленный после, доказывает только
то, что автор написал тест под свой код.

## 7. Явные не-цели

- **Не переносить воду на GPU первой.** У неё живые потребители с ожиданиями
  (мокрое подавляет спавн, ящики всплывают); включение эволюции изменит геймплей
  в местах, которые к этому не готовились. Газ безопаснее: у него потребителей нет.
- **Не делать плотное поле на субвокселях.** 1024³ ≈ 1 ГБ на поле —
  [performance.md](../../performance.md) называет это стеной. Поля живут на макро-сетке.
- **Не чинить `main.cpp:3840`** (сброс предложений во время бейка) до того, как
  появится dirty-local re-bake: сегодняшний сброс — грубая, но честная защита от
  карвинга по перепекаемой геометрии.
