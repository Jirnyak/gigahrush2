## 1. Главный факт: акустики не существует, и это не оптимизация, а новая подсистема

Мандат просил «пространственную акустику: затухание и отражение звуков через
трубы, закрытые двери и пробитые стены». Проверка дерева:

**Аудиосистемы нет вообще.** Ноль попаданий по `src/`, `tests/`, `tools/`,
`CMakeLists.txt` для `SDL_Audio`, `SDL_OpenAudio`, `SDL_INIT_AUDIO`, `miniaudio`,
`OpenAL`, `fmod`, `wwise`, `xaudio`, `PortAudio`, `.wav`, `.ogg`, `AudioDevice`,
`play_sound`. Единственные совпадения по `fmod` — арифметический `std::fmod`
(`core/wrap.h:14`, `main.cpp:272`).

Тридцать одно упоминание слов `sound`/`audio` в `src/` — **исключительно
сим-сторона**: слух ИИ и эмиссия шума дверью (`main.cpp:3378-3379`, `:3550`).

**Формулировка, которая должна попасть в мандат:** акустика в gigahrush2 сегодня —
это **поле шума без звукового выхода**. Есть честная сим-модель того, что слышат
NPC, и нет ни одного сэмпла, который слышит игрок. Любая работа здесь начинается с
инициализации SDL-аудио (SDL3 уже прилинкован для видео и ввода), а не с
«затухания через трубы».

## 2. Что построено хорошо и трогать не надо

### 2.1. Двухуровневый DDA-марчер — честный, с обоснованными границами

Один fullscreen-треугольник, `vkCmdDraw(cmd, 3, 1, 0, 0)`
([raymarch_pass.cpp:393](../../src/render/raymarch_pass.cpp)).

- **Макро-уровень** идёт клетками по 2.0 м (`raymarch.frag:86`, цикл `:209`). На
  клетку читается **один байт класса**: `0` пусто → пропуск без чтения маски,
  `1` полностью твёрдо → попадание по входной грани **без битовых тестов**,
  `2` частично → спуск вниз.
- **Суб-уровень** (`march_cell`, `:153-183`) идёт атомами 0.25 м по маске 8³.
- **Границы не усекают:** внешних шагов 224 при худшем случае ≈ 111 (радиус тумана
  64 клетки × √3), внутренних 32 при нужных ≤ 22. Обоснование стоит в комментарии
  на `:208`.

**Субвоксельная гранулярность 0.25 м разрешается по-настоящему, тремя путями:**
геометрия (`march_cell`), материал (`sub_mat`, страница на атом, `:110-116`) и
**AO** (`voxel_ao`, `:247-269`) — который берёт отсчёты на 0.25 м на пиксель, а не
запечённую маску на клетку. Пятна тоже на атом (`sub_stain`, `:120-127`).

Глубина честная: `gl_FragDepth = clip.z/clip.w` через тот же `pc.viewProj`
(`:562-563`).

> **Замечание, которого нет в документации:** запись в `gl_FragDepth`
> **отключает early-Z для этого прохода**. Было ли это измерено — НЕ ПРОВЕРЕНО.

### 2.2. Торическое размещение — правило соблюдается везде

Ни один проход не рисует в абсолютных координатах. Марчер получает правило
**по построению** (камеро-относительный марш, обёртка только индекса клетки через
`c &= (kMacroDim - 1)`, `raymarch.frag:89-92`). Растровые проходы несут явный
`nearest_image` в вершинных шейдерах (`prop.vert:37-63`, `wire.vert:29-56`,
`cloth.vert:30-59`, `particle.vert:31-51`).

**Один документационный дефект, не рендерный.** `body.vert:55` считает
`world = inCenter + (inPos - 0.5) * ...` **без обёртки в шейдере**; корректно это
только потому, что `BodyPass::record` обёртывает на CPU заранее
(`body_pass.cpp:279-281`). При этом [render.md:84-86](../../render.md) утверждает,
что растровые проходы держат `nearest_image` **в вершинных шейдерах** — для тел
это неверно.

**Мёртвые ссылки:** `shaders/cube.vert` **не существует** (удалён вместе с
мешером), но цитируется как живая авторитетная ссылка в
[render.md:84](../../render.md), `core/wrap.h:48`, `body_pass.cpp:262`,
`main.cpp:5686`. `CubePass::record` не вызывается никогда — `cubePass` выживает
только как поставщик текстур, материалов и layout-а.

### 2.3. `gpu_timer` — хорошо сделанная измерительная система

`timestampPeriod` читается, а не предполагается (`:73`); счётчик маскируется по
`validBits` (`:97`, `:200-209`); readback отложен на `kMaxFramesInFlight` кадра и
собирается сразу после ожидания fence-а; дропы считаются, а не замалчиваются;
статистика — **медиана по окну 31 кадра** плюс пик окна, с письменным аргументом
за медиану против среднего (`gpu_timer.cpp:213-228`).

## 3. Контекст и проблемы кода

### 3.1. Воксельное зеркало — 958 МиБ, из которых 768 МиБ выделяются целиком

Посчитано из объявленных размерностей при `kMacroDim=128` (`kMacroCells = 2 097 152`,
`kSubVoxels = 512`):

| Буфер | Формула | Байт |
|---|---|---|
| masks | 2 097 152 × 64 | 134 217 728 |
| types | × 2 | 4 194 304 |
| pageIdx | × 4 | 8 388 608 |
| **pagePool** | 786 432 × 1024 | **805 306 368** |
| class | × 1 | 2 097 152 |
| fluid | × 4 | 8 388 608 |
| stainIdx | × 4 | 8 388 608 |
| stainPool | 16 384 × 2048 | 33 554 432 |
| **итого device-local** | | **1 004 535 808 = 958 МиБ** |
| staging (host-visible) | 12 МиБ × 2 кадра | 25 165 824 |
| **всего** | | **≈ 982 МиБ** |

Пул на 768 МиБ **аллоцируется целиком при инициализации**
([voxel_mirror.cpp:75](../../src/render/voxel_mirror.cpp)) независимо от
заполненности, тогда как измеренная потребность — ~690k страниц ≈ 706 МБ
([voxel_mirror.h:66-77](../../src/render/voxel_mirror.h)).

Против бюджета «RAM ~8 ГБ» из [performance.md](../../performance.md) один
подсистемный буфер съедает **12 % всего бюджета**, и ~62 МиБ из них — заведомо
неиспользуемый запас.

Загрузка двухпутевая и обе ветки корректны: `upload_all` (полная, только экран
загрузки, пик ~706 МБ device + ~706 МБ host-visible) и `flush` (грязные регионы,
слияние в пробеги, батч `vkCmdCopyBuffer`, переполнение **остаётся в очереди** на
следующий кадр). **Исключение — жидкость:** при любом изменении перезаливаются все
8 МиБ, потому что там флаг, а не список клеток (`voxel_mirror.cpp:433-442`).

### 3.2. CRT-оверлей: ~720 ImGui-команд на кадр, без переключателя

`imgui_layer.cpp:177-234` рисует CRT **командами ImGui, а не шейдером**:

- фосфорная засветка `#59F266` alpha 10/255 на весь экран (`:198-199`);
- **скан-линии: период 3 px, два прохода `AddLine`** (`:204-212`) — на 1080p это
  `1080/3 × 2 = 720` вызовов `AddLine` **каждый кадр**;
- виньетка — четыре градиентных квада (`:218-230`).

`draw_crt_overlay()` вызывается безусловно (`main.cpp:5477`). Ни флага, ни
переменной среды, ни бинда: `crt`/`crtEnabled`/`showCrt` дают только объявление и
один вызов. Сравните с A/B-переключателями, которые в дереве **есть**:
`GIGA_GPU_TIMER`, `GIGA_NO_GPU_CULL`, `GIGA_WIRE_NOSIM`, `GIGA_PARTICLE_NOSIM`.

Это самая крупная устранимая CPU-цена на кадр в рендер-пути.

### 3.3. `gpu_timer` мерит три прохода из десяти

`gpu_timer.h:72-77` объявляет каналы `World`, `Bodies`, `Hud` + кадр целиком
(`kGpuMarksPerFrame = 8`).

**Не измеряется, хотя пишется в тот же командный буфер:** диспатч сетки света, GPU
cull, flush зеркала, симуляция проводов, ткани, частиц, проходы пропов, проводов,
тканей, частиц. `GpuPass::World` оборачивает **только** `raymarchPass.record`
(`main.cpp:5695-5698`); пропы/провода/ткань/частицы на `main.cpp:5706-5711`
попадают **вне всех скобок** — ни в один канал, но в сумму кадра.

Комментарий `World = 0, // CubePass: the instanced voxel world` (`gpu_timer.h:73`)
устарел — мешера нет.

Следствие: регрессия в проходе пропов **невидима по каналам** и видна только как
рост суммы кадра, то есть неатрибутируема.

### 3.4. Пост-обработки как прохода нет

Оффскрин-таргета не существует: единственный render pass рисует прямо в
swapchain-образ (`vk_renderer.cpp:50-107`, один subpass,
`finalLayout = PRESENT_SRC_KHR`).

Всё «пост» живёт **внутри `raymarch.frag`**: объёмный туман (`:706-722`), высотный
и дистанционный туман с мерцанием самосбора (`:724-733`), ACES-подобный тонмап
(`:736`), sRGB-кодирование (`:737`). Ничего из этого не переключается.

**Для мандата это блокер:** «адаптация зрения к темноте» и «визуализация
галлюцинаций/оглушения» — это полноэкранные эффекты с состоянием, зависящим от
игрока. Без оффскрин-таргета их можно сделать только в марчере, что смешивает
геймплейное состояние с проходом мира.

### 3.5. Пять GPU-буферов пишутся без кольца по кадрам

[problems.md](../../problems.md) §18 — ЖИВА. При `kMaxFramesInFlight = 2` запись в
буфер, который ещё читается предыдущим кадром, — это гонка, которую валидация не
поймает, а артефакт покажет через кадр.

### 3.6. Одна величина считается двумя способами

§20 — ЧАСТИЧНО ЗАКРЫТА. `samosborPulse` пересчитывается в `cube.frag` и
`raymarch.frag` с двумя ошибками, из-за чего проход мира гонит эффект на **0.457**
там, где CPU говорит 1.0. Плюс `pc.torus.w` несёт **и упакованную маску, и часы в
секундах**, поэтому проход мира получает денормал или NaN там, где ждёт время.

### 3.7. Мелкие покадровые издержки CPU

Горячий путь в целом чист: `RaymarchPass::record`, `BodyPass::record`,
`GpuCullPass::record_cull`, `GpuLightGrid::update_and_dispatch`, `GpuTimer` не
аллоцируют. Остаётся:

- `std::sort` очереди грязных клеток каждый flush (`voxel_mirror.cpp:282`);
- сортировка источников света каждый кадр, безусловно (`gpu_light_grid.cpp:214-224`);
- **некэшированный `std::getenv` на кадр**: `GIGA_WIRE_NOSIM` (`main.cpp:5613`,
  `:5646`), `GIGA_PARTICLE_NOSIM` (`:5668`). Сравните с `noGpuCull` (`:5542`),
  который корректно `static`.

## 4. Проектируемые структуры

### 4.1. Акустика: сначала выход, потом распространение

Порядок здесь обратный интуитивному. Нельзя проектировать «затухание через трубы»,
пока нет ни одного слышимого сэмпла: проверить распространение будет нечем.

```cpp
// src/render/audio.h — НОВЫЙ ФАЙЛ, слой L3.
//
// ПОЧЕМУ В render/, А НЕ В game/: аудио — платформенная оболочка ровно того же
// класса, что рендер. Данные текут sim -> audio, никогда обратно. Игра обязана
// оставаться полностью проходимой с удалённым L3 (AGENTS.md), значит звук не
// может отвечать ни на один геймплейный вопрос.
//
// SDL3 уже прилинкован для окна и ввода; SDL_INIT_AUDIO — вторая маска в том же
// вызове, новой зависимости нет.
struct AudioSource {
    vec3  pos;          // мировая позиция, ДО торической нормализации
    float gain = 1.0f;
    std::uint16_t clipId = 0;
    std::uint8_t  flags = 0;
};

// Слушатель — НЕ синглтон, по тому же закону, по которому камера им не является:
// это тот, кто держит CameraTag. Позиция и базис берутся из него.
struct ListenerFrame {
    vec3 pos, fwd, right, up;
};
```

**Торическое правило распространяется на звук дословно.** Источник в 250 м по
прямой на торе 256 м — это источник в 6 м с другой стороны. Расстояние обязано
считаться через `wrap_delta`, иначе игрок будет слышать далёкое как далёкое, а
видеть его вблизи — рассинхрон картинки и звука на шве.

### 4.2. Затухание — переиспользование уже построенного поля

Мандат просит «затухание и отражение через трубы, закрытые двери, пробитые
стены». Ни одному из трёх не нужна новая система:

| Требование | Что уже есть | Как использовать |
|---|---|---|
| Пробитые стены | `SubMask` 8³ по пути луча | Прореженный марш «источник → слушатель», доля твёрдых атомов = глухость |
| Закрытые двери | `door.cpp`, состояние + `dirtyCells` | Дверь — множитель затухания на своей клетке |
| Трубы | `PipeNetwork` из [спеки 02](02_VOXEL_PHYSICS_AND_FLUIDS.md) §3.4 | Компонента связности = канал с малым затуханием |
| Слух NPC | поле шума `noise.cpp` | **Уже честное.** Аудио читает его же, а не второй источник правды |

```
audio_occlusion(src, listener):
    # 16 отсчётов по луче, а не полный DDA: это ЗВУК, ошибка в 5 % неслышима.
    # Тот же приём, что raymarch делает для AO — грубые отсчёты вместо точной
    # геометрии, потому что потребитель не различает разницу.
    solid = 0
    for i in 0..15:
        p = lerp(src.pos, listener.pos, (i + 0.5) / 16)
        if voxel_solid_at(p): solid += 1
    wall = solid / 16.0

    # Трубы ОБХОДЯТ стену: если источник и слушатель в одной компоненте
    # трубопровода, глухость берётся по трубе, а не по прямой.
    if pipe_component(src.cell) == pipe_component(listener.cell) != 0:
        wall = min(wall, kPipeLeak)

    return gain / (1 + d²/r²) * (1 - wall * kWallAbsorb)
```

### 4.3. Оффскрин-таргет — предпосылка для трёх пунктов мандата

Адаптация зрения, галлюцинации и оглушение — это состояние **игрока**, влияющее на
**всё изображение**. Их место — отдельный проход, а не проход мира.

```cpp
// src/render/post_pass.h — НОВЫЙ ФАЙЛ.
// Один HDR-таргет + один fullscreen-проход. Тонмап и sRGB ПЕРЕЕЗЖАЮТ
// сюда из raymarch.frag: сейчас они внутри прохода мира, из-за чего
// растровые проходы (тела, пропы, частицы) кодируются в sRGB отдельно
// и любое несогласование даёт разъезд яркости между миром и телами.
struct PostState {
    float darkAdapt = 1.0f;  // экспозиция, экспоненциально ползёт к цели
    float stun = 0.0f;       // 0..1: размытие + смещение каналов
    float hallucination = 0.0f; // 0..1: искажение UV + сдвиг палитры
    float crt = 1.0f;        // 0..1 — ВЫКЛЮЧАТЕЛЬ CRT, которого нет сегодня
};
```

**Адаптация к темноте — это экспозиция, а не яркость.** Цель считается из
светимости в центре кадра (её уже даёт сетка света), а `darkAdapt` ползёт к ней
экспоненциально с разными постоянными на свет и на тьму — глаз адаптируется к
темноте медленно, а к свету быстро. Мгновенная адаптация читается как баг гаммы.

### 4.4. CRT переезжает в шейдер

720 `AddLine` на кадр заменяются одной строкой в пост-шейдере:

```glsl
// Скан-линии, виньетка и фосфор — три арифметические операции на пиксель
// на GPU, который performance.md объявляет неограниченным, вместо 720
// команд на CPU, который объявлен единственным дефицитным ресурсом.
float scan = 1.0 - kScanDepth * step(1.5, mod(gl_FragCoord.y, 3.0));
float vig  = 1.0 - kVigDepth * pow(length(uv - 0.5) * 2.0, kVigPow);
col = col * scan * vig + kPhosphor * kPhosphorAlpha;
col = mix(colNoCrt, col, post.crt);   // <- выключатель
```

Мандат CRT при этом соблюдается полностью: палитра остаётся точной
(`#59F266`/`#050A05`/`#F2C740` — проверено, все три совпадают побитово),
скругления остаются нулевыми, рамки — толстыми.

## 5. Критерии приёмки

### 5.1. Акустика

- [ ] **Этап 0 — слышно хоть что-то.** SDL-аудио инициализирован, один сэмпл
      играется по событию. Без этого этапа остальные непроверяемы.
- [ ] Тор: источник за 250 м на торе 256 м слышен **как за 6 м**. Тест на
      `wrap_delta`, а не на глаз.
- [ ] Закрытая дверь глушит, открытая — нет. Число до/после, не ощущение.
- [ ] Труба проводит: источник и слушатель в одной компоненте слышат друг друга
      сквозь стену, в разных — нет.
- [ ] **Аудио не отвечает на геймплейные вопросы.** Гейт: в `src/game` нет ни
      одного `#include` из `src/render/audio*`.

### 5.2. Зеркало

- [ ] Пул страниц выделяется **по потребности или растёт**, а не 768 МиБ
      безусловно. Печатать резидентные байты каждым прогоном.
- [ ] Жидкость переходит на список грязных клеток, как остальные семь буферов, —
      8 МиБ на любое изменение это тот же класс, что §19.
- [ ] `verify()` покрывает **каждый** буфер. §19 закрывалась ровно этим, и
      повторение — признак, что урок класса не усвоен.

### 5.3. Измеримость

- [ ] `gpu_timer` получает канал на **каждый** записываемый проход. Сегодня три
      из десяти, и это делает регрессию неатрибутируемой.
- [ ] Ни один диспатч не остаётся вне скобок. Гейт: сумма каналов сходится с
      кадром в пределах уже измеренных 0.03 мс.
- [ ] Устаревший комментарий про `CubePass` убран; мёртвые ссылки на
      `shaders/cube.vert` вычищены из пяти мест.

### 5.4. CRT и пост

- [ ] CRT переключается. **Любой** способ (флаг, env, бинд) — сегодня нет ни
      одного.
- [ ] CRT в шейдере: `AddLine` на кадр падает с ~720 до 0, и это печатается.
- [ ] Тонмап и sRGB — в одном месте. Гейт: `rg 'srgb_encode' shaders/` даёт одно
      попадание.
- [ ] Адаптация к темноте асимметрична: к тьме медленнее, к свету быстрее. Две
      разные постоянные, обе в тесте.

## 6. Порядок работ

```
A. Каналы gpu_timer на все проходы     <- ГЕЙТ. Без него ничего не измеримо
B. Кэш getenv, чистка мёртвых ссылок   <- минуты, ноль риска
C. §20 pulse + torus.w                 <- подтверждённая мелочь
D. Оффскрин-таргет + post_pass         <- предпосылка для E, F, G
E. CRT в шейдер + выключатель          <- зависит от D, снимает 720 команд
F. Адаптация зрения                    <- зависит от D
G. Оглушение / галлюцинации            <- зависит от D и от status.cpp
H. Пул страниц по потребности          <- независим, освобождает ~62 МиБ
I. Жидкость на грязные клетки          <- независим
J. Аудио этап 0 (SDL init + 1 сэмпл)   <- независим от всего рендера
K. Затухание по стенам и дверям        <- зависит от J
L. Звук по трубам                      <- зависит от J и от СПЕКИ 02 PipeNetwork
```

**A первым, и это не формальность.** Пять из перечисленных работ меняют стоимость
кадра. Мерить их каналами, которые покрывают три прохода из десяти, — это ровно
та ошибка, за которую [render.md:286-291](../../render.md) уже выписал правило:
**счётчиком кадров нельзя оценить изменение прохода**, а сегодняшний набор
каналов не лучше счётчика кадров для семи проходов из десяти.

## 7. Явные не-цели

- **Не трогать марчер.** Он корректен, его границы обоснованы, субвоксельная
  гранулярность разрешается по-настоящему в трёх местах. «Оптимизация DDA» из
  мандата — работа без обнаруженной проблемы.
- **Не заводить текстуры.** [render.md:96-126](../../render.md) содержит
  измеренный аргумент за процедурные поверхности и инвентаризацию 1784 изображений,
  давшую ноль пригодных. Решение принято и обосновано.
- **Не менять swapchain на `_SRGB`** без линеаризации стиля ImGui — HUD выцветет,
  и это записано в [render.md:236-242](../../render.md).
- **Не читать фреймбуфер для геймплея.** Ни для звука, ни для видимости, ни для
  линии огня.
