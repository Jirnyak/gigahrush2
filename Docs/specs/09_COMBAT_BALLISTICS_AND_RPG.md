Митигация урона тоже сделана правильно и **в одном месте**
(`combat.cpp:91`: *«Mitigation happens exactly once, here. Nothing downstream
sees `raw`»*):

```cpp
std::int16_t mitigate(std::int16_t raw, std::int8_t resistPct) {
    int r = resistPct;
    if (r > 95) r = 95;      // никогда не полный иммунитет
    if (r < -100) r = -100;  // отрицательный резист = уязвимость, не клампится в 0
    int out = raw - (raw * r) / 100;
    return out < 0 ? 0 : static_cast<std::int16_t>(out);
}
```

Порядок применения: уязвимость от черт → броня по каналу → множитель поведения
защитника, с полом в 1 при `dmg > 0`.

## 2. Дефекты

### 2.1. Манифест запрещает исключения для дружественного огня — в коде их пять

[ARCHITECTURE.md](../../ARCHITECTURE.md) §Манифест п.5: *«Снаряды — честная
баллистика в торе, никаких friendly-fire-исключений; граната скачет по вокселям,
осколки бьют и владельца»*.

Фактически (`combat.cpp:1115-1160`, `:1174`):

| # | Исключение | Строка | Обоснование в коде |
|---|---|---|---|
| 1 | Снаряд не бьёт владельца (игрок) | `combat.cpp:1121` | «he shoots himself the instant he fires» |
| 2 | Снаряд не бьёт владельца (моб) | `combat.cpp:1145` | выстрел рождается в 0.6 м, радиус 0.75 м |
| 3 | Выстрел игрока (`team == 1`) бьёт **только** мобов | `combat.cpp:1143` | — |
| 4 | Выстрел моба (`team == 0`) бьёт **только** толпу | `combat.cpp:1174` | — |
| 5 | Монстр не может задеть монстра | следствие 3 | «would silently invent monster-on-monster friendly fire» |

**Исключения 1 и 2 законны и должны остаться.** Они не про фракции — они про
геометрию спавна: снаряд рождается внутри коллайдера стрелка. Правильное решение
известно и стандартно: **спавнить снаряд за пределами коллайдера** либо давать
ему неуязвимость на первые N сантиметров пути, а не на владельца навсегда.

**Исключения 3, 4, 5 — прямое нарушение манифеста.** Это `team`-гейт, то есть
командная принадлежность, а игра заявлена как симулятор без команд: у неё есть
фракции с матрицей отношений 6×6, где враждебность — это **число**, а не
булев флаг стороны.

### 2.4. PSI: хранится, сохраняется, показывается — и никогда не тратится

Полный грep по `psi` в `src/` даёт 21 попадание. Каждое вне `rpg.cpp` — это либо
объявление поля (`rpg.h:98`), либо HUD (`main.cpp:4693`), либо отладочный лист

**Ни одного декремента. Ни одной проверки стоимости. Ни одной способности.**
`regen_psi` не существует, и `rpg.h:24-25` документирует это как осознанный

Значение выставляется в максимум при создании (`rpg.cpp:192`), при случайной

Это согласуется с тем, что нашла [спека 06](06_SAMOSBOR_AND_CRISIS.md) §2.1 со

## 3. Проектируемые структуры

### 3.1. Убрать `team`, оставить геометрию

```cpp
// src/game/combat.h — Projectile теряет team и приобретает честную причину
// не бить владельца.
struct Projectile {
    Entity source;
    // ЗАМЕНА team: снаряд неуязвим для своего стрелка ровно до тех пор,
    // пока не покинул его коллайдер. Это ГЕОМЕТРИЯ, а не команда:
    // рикошет обратно в стрелка после этой дистанции ПОПАДАЁТ, как и
    // требует манифест («осколки бьют и владельца»).
    float armedAfterM = 0.75f;   // == kProjHitRadius, не совпадение
    float travelledM = 0.0f;
    // team УДАЛЁН. Враждебность решается матрицей фракций, а не стороной.
};
```

```
projectile_hit_test(p, victim):
    if (victim == p.source and p.travelledM < p.armedAfterM):
        return NoHit                    # геометрия, законно
    # ВСЁ. Ни одной проверки фракции, ни одной проверки MobRef.
    # Пуля игрока бьёт жителя. Пуля моба бьёт моба. Граната бьёт бросившего.
    return Hit
```

**Цена честности, названная заранее:** мобы начнут убивать друг друга в
перестрелке. Это не регрессия, это заявленный дизайн — и `hunt.h` уже
предупреждает, что размазывание урона по большему числу тел **не снижает**
смертность, а откладывает её. Значит закрытие `IntentHeal`-дедлока из
[спеки 01](01_ALIFE_AND_UTILITY_AI.md) §2.3 — **предпосылка**, а не сопутствующая
работа.

### 3.2. Пул PSI — один компонент, два потребителя уже ждут

## 4. Критерии приёмки

### 4.1. Дружественный огонь

- [ ] `Projectile::team` **удалён**. Гейт: `rg '\bteam\b' src/game/combat.*` пуст.
- [ ] Пуля игрока, прошедшая мимо моба, **попадает в жителя** за ним. Тест на
      траекторию, не на флаг.
- [ ] Выстрел моба **попадает в другого моба**.
- [ ] Граната, брошенная в стену в упор, **ранит бросившего** — прямая проверка
      требования манифеста «осколки бьют и владельца».
- [ ] Стрелок **не** убивает себя в момент выстрела. Это регрессионный тест на
      геометрию: он обязан пройти и после удаления `team`.

### 4.2. Изотропия боя

- [ ] Отбрасывание толкает **назад**, а не вверх, под всеми восемью режимами
      гравитации.
- [ ] Труп оседает по вектору гравитации слоя.
- [ ] `combat.cpp:459-460` выводит базис из `GravityFrame`, а не из `cos/sin` yaw.

### 4.3. PSI

- [ ] Хотя бы одна способность **тратит** PSI, и трата видна числом.
- [ ] Реген **только** при полном сне. Тест: бодрствующее тело с PSI 0 не
      восстанавливает его за 10 минут.
- [ ] `psiDamage` самосбора начинает списываться.
- [ ] Четыре мёртвые INT-производные получают вызовы **или** явную строку
      отложенных — гейт из [спеки 05](05_TESTING_AND_PERF_BUDGETS.md) §3.4.

### 4.4. Статусы

- [ ] Тройка `Govnyak` получает производителей **или** удаляется с причиной.
      Читатели без писателей — это класс §35 наоборот, и он уже трижды в дереве.
- [ ] Производители статусов живут в игровых системах, а не в отладочной ветке
      `main.cpp`. Сегодня три из четырёх — там.

### 4.5. Каналы и броня

- [ ] `static_assert` связывает `kDamageChannels` и `kItemResistChannels`.
- [ ] Тест: добавление шестого канала **роняет сборку**, а не молча
      недомитигирует. Это тест обратной полярности по образцу
      [спеки 05](05_TESTING_AND_PERF_BUDGETS.md) §3.5.
- [ ] Число предметов с ненулевым резистом печатается при загрузке таблицы.
      Пять из 446 — это решение о контенте, и оно должно быть видимым.

## 5. Порядок работ

```
A. static_assert на каналы             <- ОДНА СТРОКА, закрывает латентный дефект
B. Гейт изотропии покрывает бой        <- часть спеки 02 фазы 0.1
C. Отбрасывание и оседание через фрейм <- падает под B, чинится под B
D. Heal-банк (спека 01 §3.3)           <- ПРЕДПОСЫЛКА для E
E. Удалить team, оставить armedAfterM  <- зависит от D, иначе толпа вымирает
F. Пул PSI                             <- оживляет 5 мёртвых точек в двух спеках
G. Производители статусов Govnyak      <- независим
H. Контент брони: больше 5 предметов   <- независим, работа по CSV
```

**A — одна строка, и она первая.** Латентный дефект, который сработает ровно
тогда, когда кто-то добавит канал урона, то есть в момент максимальной уверенности
в правильности своей правки.

**E строго после D.** Честный дружественный огонь без лечения толпы — это
`crowd_dead_total`, растущий линейно. `hunt.h:38-42` уже посчитал, что размазывание
урона смертность не снижает.

## 6. Явные не-цели

- **Не убирать исключения 1 и 2.** Снаряд, рождающийся внутри коллайдера
  стрелка, — геометрическая проблема, и решается она дистанцией взведения, а не
  сохранением `team`.
- **Не расширять до 8 атрибутов до того, как заработает INT.** Три атрибута, из
  которых один декоративен, — это не «мало атрибутов», это «атрибут без
  потребителей». Восемь таких будут хуже трёх.
- **Не клампить отрицательный резист в ноль.** Уязвимость — заявленная механика
  (`combat.cpp:49-50`).
- **Не трогать конус разброса.** Он уже исправлен под 3D с письменным
  обоснованием (`combat.cpp:1389-1391`).
