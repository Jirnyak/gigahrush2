## 1. Лифтов 16, а не 32 — и виноват README

| Утверждение | Факт |
|---|---|
| README: «4×4 Fast-Travel Elevators» | **Построено.** `kFastHubsPerFloor = kLatticeDim²` = **16** (`fast_travel.h:29`) |
| README: «+ 4×4 Up/Down Procedural Elevators» | **Второго набора нет.** Те же 16 шахт служат обоим |

Решётка одна: `stamp_lattice` (`padic_gen.cpp:477`) крутит `ny`/`nx` по
`kLatticeDim` и **не имеет цикла `nz` по шахтам**. `kLatticeDim = 4`,
`kLatticeCount = 64`, `kLatticeSpacing = 32`, центры `{16,48,80,112}`
(`lattice.h:26-33,42-44`).

Цифра 64 в дереве настоящая, но это **навигационный граф**, а не лифты
(`lattice.h:8-13`). `elevators.md:6-9` честен и сам это поясняет — **ложное
утверждение живёт в README**, то есть в самом читаемом файле проекта.

**Поездка ±1 вообще не привязана к шахте.** `do_ride` повешен прямо на `[`/`]` без
проверки позиции (`main.cpp:2644-2647`). Стоять в шахте требует только быстрое
перемещение (`on_fast_hub`, `fast_travel.h:33-39`). То есть игрок едет между
этажами из любой точки, включая замурованную комнату.

## 3. Полностью синхронно, и это заявлено намеренно

`ensure_loaded` — обычный вызов, возвращающий `LoadResult` по значению, с
`std::chrono::steady_clock::now()` вокруг каждой стадии и `fprintf` внутри
(`floor_stream.cpp:306-327`). Ни потока, ни future, ни job-хэндла на всём пути.

`main.cpp:2334` формулирует это прямо: *«A transition is a load screen; I/O is
sanctioned here»*.

**Решение защищаемое, но его цена выросла с момента принятия.** Загрузочный экран
на 130 мс и загрузочный экран на 6,4 с — разные продуктовые объекты. Единственный
асинхронный механизм в дереве (`nav::AsyncBake`) стример не использует.

## 4. Что теряется при выходе с этажа

`unload` (`floor_stream.cpp:377-453`) сворачивает записи толпы, затем **уничтожает
все оставшиеся сущности слоя** (`:436-444`).

| Состояние | Переживает | Доказательство |
|---|---|---|
| **Выеденная геометрия** | **ДА** | `write_floor_file` (`main.cpp:2336`) → `snapshot_floor` кодирует типы, суб-маски, страницы материалов (`save.cpp:953-1040`) |
| **Брошенные предметы** | **НЕТ** | подметание без исключения для `Pickup` (`floor_stream.cpp:436-444`) |
| **Трупы** | **НЕТ** | то же подметание; мобы детерминированно респавнятся на входе |
| **Пожары** | **системы нет вовсе** | в `src/` нет поля огня |
| **Вода / газ** | **НЕТ** | `wet->fill(0.0f)` / `gas->fill(0.0f)` и пересев из плана каждую загрузку (`padic_gen.cpp:588-594`) |
| **Открытые ящики** | **ДА** | отдельный список ключей в `run.sav` (`main.cpp:2330`, `:2398`) |

### 4.1. Экономический баг, который это подметание закрыло

`floor_stream.cpp:420-429` фиксирует, что подметания **не было** до недавнего
времени. Осиротевшие предметы сохраняли устаревший `Transform.layer`, а при
`keepRadius = 0` слот выдавался заново через две поездки — и *«floor N's gold
[appeared] on floor N+2 where pickup_step would bank it — an economy bug»*.

Это лучший пример класса, который вся серия спек ищет: **дефект не в подсистеме, а
в стыке между двумя правильными решениями** (переиспользование слотов и
персистентность `Transform.layer`).

### 4.2. Асимметрия, которую надо назвать вслух

Геометрия помнится, содержимое нет. Игрок пробил стену и бросил рюкзак — стена
останется пробитой навсегда, рюкзак исчезнет за одну поездку.

Это делает **невозможным склад**. Игрок физически не может оставить запас на
этаже, а обязан носить всё на себе — при вместимости 64 кг + 4 кг за очко Силы.
Механика переноски спроектирована вокруг выбора «что брать», но выбор
существует, только если есть куда положить остальное.

**Дешёвая починка есть, и она не требует сохранять все сущности.** Предметы,
лежащие в клетке, уже имеют естественное место в снимке этажа: `snapshot_floor`
пишет типы клеток и страницы материалов. Список «клетка → предмет × число» — это
единицы килобайт на этаж против сущностей ECS. Трупы можно не сохранять вовсе:
они мебель, и их исчезновение читается как уборку.

## 5. `LayerId` против номера этажа — три плоских массива

`floor_registry.h:119-121`:

```cpp
ModuleId numberToModule_[kFloorSlots]; // 255 знаковых меток, -127..127
int      moduleToNumber_[kMaxModules]; // 256
LayerId  moduleToLayer_[kMaxModules];  // 256
```

Два перехода, собранные в `layer_at` (`floor_registry.cpp:61-65`):

```cpp
ModuleId m = module_at(number);   // 1: метка -> содержимое   (:38)
return layer_of(m);               // 2: содержимое -> слот    (:57)
```

Причина, цитата `floor_registry.h:12-17`: *«Because every hop is data, floors can be
renumbered or reshuffled mid-game without touching module content, and a module can
stream in/out of the stack without changing its number»*.

### 5.1. Класс, который это предотвращает — и который всё равно случился

**Наложение устаревшего слота.** При `keepRadius = 0` слотов всего два, а
`ensure_loaded` выделяет **до** того, как `unload` освобождает, — поэтому `LayerId`
**чередуется на каждой поездке**.

`main.cpp:2305-2315` фиксирует дефект, проскочивший мимо защиты: `activeLayer`
остался смотреть на переиспользованный слот, и карв, двери и GPU-зеркало работали
по **покинутому** этажу. Формулировка в коде: *«the corruption was guaranteed, not
occasional»*.

**Урок методический:** трёхходовая косвенность защищает **чтение** через номер, но
не защищает **кэшированный** `LayerId` в локальной переменной. Косвенность
обязана быть единственным путём, иначе она защищает только тех, кто ей
пользуется.

### 5.2. Второй класс: номера разрежены легально

`floor_registry.h:127-131` — номера этажей **могут** идти с пропусками, поэтому
`fromFloor + dir` попадает в пустоту. `travel` теперь берёт `next_labelled_floor`
(`floor_stream.cpp:500`); `floor_stream.h:250-254` отмечает, что старая версия
*«silently made the elevator unusable on any sparse stack... it sat dormant while
the demo stack happened to be 0..4»*.

**Ловушка имени, живая сейчас:** `ride_elevator` по-прежнему принимает `dir` как
**смещение** и считает `fromFloor + dir` (`elevator.cpp:23`), а `travel` сначала
разрешает метку и передаёт **разность** `toFloor - fromFloor`
(`floor_stream.cpp:527-528`). Два разных смысла у одного имени параметра, отмечено
на `:524-526`. Переименовать в `delta` — правка на одно слово, снимающая
постоянный риск при следующей правке.

## 6. Резидентность: два слота, 264 МиБ выделены всегда

`init(stack, keepRadius = 0)` (`main.cpp:1838`). Слотов `2·keepRadius + 2` = **2**
(`floor_stream.cpp:50-52`). `keep_only` выгружает всё с `|number − active| >
keepRadius` (`:482-484`), то есть в покое жив **один** этаж, на пике поездки — два.

| Массив | Арифметика | Размер |
|---|---|---|
| `types_` (`CellType` = u16) | 2 097 152 × 2 Б | **4 МиБ** |
| `masks_` (`SubMask` = 8×u64 = 64 Б) | 2 097 152 × 64 Б | **128 МиБ** |
| **Сетка `World` итого** | | **132 МиБ** |
| `FineNav::flow` | 64 × 2 097 152 | **128 МиБ** |
| `FineNav::nearest` | 2 097 152 | **2 МиБ** |
| **Навигация итого** | | **130 МиБ** |

`MacroGrid()` выделяет оба массива **сразу и в полный размер**
(`macro_grid.cpp:5-6`), то есть **132 МиБ на слот закоммичены на старте вне
зависимости от использования** — 2 слота = **264 МиБ пола**. Плюс `Field<float>`
для влаги и газа (по 8 МиБ) и страницы суб-материалов. Навигационные 130 МиБ в
шиппинге не платятся, так как `navBake_ = false` (`floor_stream.h:324`).

Цифра 138 МБ в `save.h:461-463` независимо подтверждает арифметику сетки.

**Наблюдение о `masks_`:** 128 из 132 МиБ — это суб-воксельные маски, то есть 97 %
памяти этажа хранит гранулярность 0,25 м. Это правильная цена за закон
гранулярности, но она обязана лежать в бюджете как **осознанная**, а не как
следствие.

## 7. Гравитация: в лифте учтена, под лифтом захардкожена

`ride_elevator` **ветвится** по режиму (`elevator.cpp:71-77`):

```cpp
const CellStep down = regime_down(floor_gravity_regime());
if (down.x != 0)      pool.cx(id) = arrivalCoord;
else if (down.y != 0) pool.cy(id) = arrivalCoord;
else if (down.z != 0) pool.cz(id) = arrivalCoord;
```

Посадка на хаб делает то же для касательной плоскости (`elevator.cpp:83-90`),
нулевая гравитация обработана как «оставить клетку» (`:78`). **Это образцовый
код** — ровно та идиома, которой не хватает потребителям навигации из
[спеки 15](15_BAKED_NAVIGATION.md) §7.

**Но абстракция пустая.** `floor_gravity_regime()` возвращает константу времени
компиляции (`floor_gen.cpp:91`):

```cpp
GravityRegime floor_gravity_regime() { return kPadicGravity; }
```

и `padic.h:53`: `inline constexpr GravityRegime kPadicGravity = GravityRegime::NegZ;`

Функция **не принимает номер этажа**, поэтому все этажи `−Z`, а ветки `down.x` и
`down.y` — мёртвый код.

Ниже геометрия захардкожена по Z независимо: `stamp_lattice` крутит
`for (int z = 0; z < kMacroDim; ++z)` для шахт и индексует лобби по `z`, `b+2`,
`wz` (`padic_gen.cpp:484-508`). `on_fast_hub` принимает только `(cx, cy)` и сам
это признаёт (`fast_travel.h:35-36`): *«Z is the walkable storey... boarding is
XY-only»*.

**Следствие:** этаж с боковой гравитацией получил бы **правильную посадку по оси
гравитации в шахту, прорезанную по неправильной**. Лифт исправен, мир нет.

Порядок починки поэтому обратный ожидаемому: сначала `floor_gravity_regime(number)`
и генератор, потом лифт — который уже готов.

### 8.1. Пропущено в документе целиком

**Набор открытых этажей не доходит до диска.** `FastTravelState` живёт в `main`
(`main.cpp:2174`) и не встречается в `save.cpp` нигде. **Каждый открытый этаж
забывается при выходе из игры** — при том что `run.sav` версии 9 несёт весь пул
NPC, макро-часы и матрицу фракций (`save.h:87-108`).

Это дороже, чем выглядит: быстрое перемещение — механика **прогресса**. Игрок
открывает хабы, чтобы не ходить пешком; сброс набора возвращает его к пешему
проходу после каждого запуска. Стоимость починки — битовая маска на 255 этажей,
32 байта.

Связано: [спека 10](10_SAVE_AND_PERSISTENCE.md) §8 отдельно спрашивает, выразимо
ли сохранение **в кабине лифта**. Ответ теперь есть: поездка синхронна и
неделима, состояния «в кабине» не существует, сохраниться посреди неё нельзя.
Пункт закрыт — сохранять нечего.

## 9. Проектируемые структуры

### 9.1. Поэтажный склад — минимальная форма

```cpp
// Клетка -> что в ней лежит. НЕ сущности ECS: только счётные предметы.
// Пишется в снимок этажа рядом с типами клеток, читается при загрузке
// и превращается обратно в Pickup-сущности.
//
// ПОЧЕМУ ТАК, А НЕ СОХРАНЕНИЕМ СУЩНОСТЕЙ: сущность несёт Transform,
// Velocity, слой и полтора десятка компонентов, из которых после
// загрузки осмысленны два. Пара (клетка, предмет) — это всё состояние,
// которое у лежащего предмета есть.
struct FloorStash {
    std::uint32_t cell;   // линейный индекс клетки в 128^3
    std::uint16_t item;   // ItemId
    std::uint16_t count;  // стак
};
// 8 байт на запись. Тысяча брошенных предметов = 8 КиБ на этаж
// против 132 МиБ сетки. Стоимость не обсуждаема.
```

### 9.2. Открытые хабы в сейв

```cpp
// 255 этажей, по биту. Кладётся в run.sav новым блоком SAVFT.
// Версия 10 — вместе с часами самосбора из спеки 10 §4.1,
// одним подъёмом kSaveVersion, а не двумя.
std::uint8_t fastTravelUnlocked[32];  // 255 бит + выравнивание
```

### 9.3. Режим гравитации как функция этажа

```cpp
// БЫЛО: константа, не принимающая аргумент — ветки down.x/down.y мертвы.
GravityRegime floor_gravity_regime();                    // floor_gen.cpp:91
// СТАНЕТ: свойство этажа, как и всё остальное в FloorSpec.
GravityRegime floor_gravity_regime(int floorNumber);
// Тогда 8 режимов из GravityRegime становятся достижимыми контентом,
// и тест изотропии из спеки 05 получает, на чём работать.
```

## 10. Критерии приёмки

### 10.1. Правда в документах

- [ ] README исправлен: **16 шахт**, а не 4×4 + 4×4. Это самый читаемый файл.
- [ ] Семь расхождений §8 закрыты правкой кода или документа, с указанием выбора.
- [ ] `FastTravelState` вне сейва — записано как дефект, а не пропуск.

### 10.2. Хитч возврата

- [ ] 6,4 с чтения снимка **замерены заново** после любой правки — число в коде
      уже есть (`floor_stream.cpp:305`), пин обязан ломаться при регрессии.
- [ ] Инверсия названа в `performance.md`: возврат дороже первого визита в 50 раз.
- [ ] Решение принято: терпеть загрузочный экран 6,4 с либо резать снимок
      (дельта вместо полной сетки). **Это решение владельца, не техническое.**

### 10.3. Склад

- [ ] Брошенный предмет **переживает** поездку туда и обратно. Прямая проверка:
      положить, уехать, вернуться, найти.
- [ ] Прирост размера снимка печатается и укладывается в объявленный бюджет.
- [ ] Трупы **не** сохраняются — и это записано как решение с причиной.

### 10.4. Гравитация

## 11. Порядок работ

```
A. README: 16 шахт                        <- пять минут, самый читаемый файл
B. Открытые хабы в сейв (32 байта)        <- вместе с часами самосбора, версия 10
C. Переименовать dir -> delta             <- одно слово, снимает постоянный риск
D. FloorStash: склад в снимке этажа       <- 8 Б на предмет, закрывает переноску
E. floor_gravity_regime(number)           <- оживляет 8 режимов и тест изотропии
F. Решение по 6,4 с                       <- владельца: терпеть или резать снимок
G. stamp_lattice по оси гравитации        <- зависит от E, настоящая работа
```

**A, B, C — час на троих.** B закрывает потерю прогресса, C снимает ловушку имени.

**D — лучшее соотношение в документе:** 8 байт на предмет возвращают смысл
системе переноски, спроектированной вокруг выбора «что нести».

**E раньше G.** Лифт уже умеет гравитацию; мир нет. Починка снизу вверх, иначе
правильный лифт продолжит высаживать в неправильную шахту.

## 12. Явные не-цели

- **Не делать переход асинхронным.** `main.cpp:2334` объявил загрузочный экран
  санкционированным, и это верно: 16k тел и полная перезаливка GPU-зеркала не
  прячутся за спиннером. Резать надо **стоимость**, а не видимость.
- **Не сохранять трупы.** Они мебель; респавн мобов детерминирован, и
  исчезновение трупа читается как уборка, а не как баг.
- **Не поднимать `keepRadius` до 1.** Это +132 МиБ на слот немедленно
  (`macro_grid.cpp:5-6` выделяет полный размер), а хитч оно не убирает — чтение
  снимка останется тем же.
- **Не возвращать печение навигации в стриминг.** `floor_stream.h:157-162` уже
  показал результат: секунды и 130 МиБ, освобождённые непрочитанными.
- **Не убирать `place_body_safely`.** `main.cpp:2421-2424`: каждая пятая колонка
  Residential сплошная на высоте прибытия. Без спасателя тело замирает в стене.
