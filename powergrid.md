# Электросеть — топология на решётке (дизайн владельца, 2026-08-17)

Замысел записан со слов владельца; текущая радиусная заглушка (щиток →
power cut в 12 м, combat.h) — ВРЕМЕННАЯ и умрёт с этой системой.

## Замысел

**Сеть = НАДПОЛЕ на решётке 128³** — та же универсальная геометрия, на
которую нанизаны все поля (антураж, трубы, диффузия). Карта топологии этажа:
провода от щитков к сетевым пропам, маршруты лежат ПО СУБВОКСЕЛЯМ мира,
строятся при генерации этажа. Расширяемо тем же образом: водопровод и т.д.

## Законы

1. **Две системы, НЕ связанные между собой:**
   - **Электросеть** — чистая топология: граф «щиток → провод-маршрут →
     потребитель» на геометрии решётки. Знает только связность.
   - **Антураж-провода** — существующая система рендера/физики (верлет,
     падение при carve). Ей ВСЁ РАВНО, по какому алгоритму дали геометрию —
     при генерации она получает маршруты сети как обычные точки подвеса.
2. **Разрыв цепи = повреждение вокселей маршрута.** Игрок ломает воксели, по
   которым шёл провод → сеть видит разрыв (её ячейки маршрута умерли) → всё
   дерево за разрывом обесточено. Антураж НЕЗАВИСИМО роняет свой верлет с тех
   же вокселей. Для игрока — «оборвал провод, свет погас»; для архитектуры —
   две системы честно отработали каждая своё, не зная друг о друге.
3. **Пропы делятся флагом «сетевой / автономный»** (universal, колонка
   props.csv): лампочка — сетевая, прибор с батарейкой — автономен. Щиток
   уничтожен / цепь разорвана → сетевые потребители его дерева гаснут (свет
   И emissive, синхронно).
4. **Параметры сети живут НА ЩИТКЕ**: частота, нагрузка, перепады,
   интенсивность/энергия. **Мерцание сетевых пропов — КОНТЕКСТ от этих
   параметров**, а не собственный профиль: перегруженный щиток — глубокие
   просадки у всего его дерева (синхронные! вся ветка мигает вместе — то,
   чего независимые синусы не дадут никогда). Автономные пропы сохраняют
   табличный профиль ([game/flicker.h]) — система мерцания уже единая, сеть
   лишь подставляет свой контекст вместо константного.
5. **Минимальная элегантная модель**: v1 — связность (жив маршрут или нет) +
   один-два параметра щитка, питающих flicker_factor. Не симулировать
   электричество — симулировать ПОСЛЕДСТВИЯ.

## Как это ляжет на существующее

- **Свет**: PropLight уже гейтится питанием; меняется только источник истины
  «запитан?» — с радиуса на топологию. Коллектор не меняется.
- **Мерцание**: `flicker_factor` уже одна на свет и emissive; mains-профиль
  начинает брать амплитуды/частоту из параметров своего щитка.
- **Антураж**: система та же; при генерации этажа ей передаются маршруты
  сети как геометрия подвесов (как сейчас трубам/проводам передаёт генератор).
- **Радиусная заглушка combat.h** (destroy_shield/is_power_cut 12 м) —
  переживает до v1 топологии, затем умирает.

## Очередь постройки (обсудить перед стартом)

1. Поле маршрутов: генерация трасс щиток→потребители по субвокселям
   (маршрутизация вдоль стен/потолков, как ходят настоящие провода).
2. Связность: карта «ячейка маршрута → ветка дерева»; carve ячейки → пометка
   разрыва → потребители за разрывом обесточены.
3. Параметры щитка + контекстное мерцание ветки.
4. Антураж получает трассы как подвесы (визуальные провода = маршруты сети).
5. Смерть радиусной заглушки.
