## Закон

**E по живому NPC открывает МЕНЮ, а не действие.** Действие — это выбранная
опция. Одна система на все взаимодействия, потому что альтернатива — у
торговца свой ключ, у квестодателя свой, у партнёра по костям третий — это
ровно та россыпь спецкейсов, которую «игрок не особенный» запрещает для тел,
а этот файл запрещает для разговоров.

**Опция = строка таблицы** ([AGENTS.md] data-driven): `kConvOptions` в
conversation.cpp — id, порядок, ярлык, предикат видимости, активация.
Новая опция (игра, урок рецепта, платная услуга) — одна строка с двумя
функциями, никакого `if`-каскада в меню и ни одной правки в UI. Порядок —
`(order, id)`, как в референсе: разговор 0, задание 10, торг 20, игры
100.., уйти 9000.

**Меню предлагает — app исполняет.** Тот же шов, что у всего ввода
([netcode.md], [inventory_ui.h]): `conv_activate` возвращает `ConvAction`
(показать строку / открыть бартер / закрыть), сам не мутирует ни
инвентарь, ни камеру, ни окна. Мутации идут через существующие примитивы
на сим-клоке.

## Встроенные опции

| id | ярлык | что делает |
|----|-------|-----------|
| talk | РАЗГОВОР | строка речи говорящего — `speech_say` ([speech.h]): голос фракции, ситуация из живого состояния, память «не повторяться» |
| quest | ЗАДАНИЕ (! если даватель) | контракт этого NPC: `Contract::giver == pool.handle(npc)` — живой даватель помечается, активация показывает состояние работы; не даватель — честное «работы нет» |
| trade | ТОРГ | бартер-сделка на экране обыска — см. ниже |
| leave | УЙТИ | закрыть |

Первая игра построена и доказала строку делом: `{"dice", 100, ...}` —
гейт `conv_party_holds(kItemDiceBone)` (предмет у ЛЮБОЙ из сторон, одного
комплекта достаточно, как в референсе), ставка — десятина физических
рублей NPC (ликвидность = что в кармане, [barter.h] закон 2), отказы
словами («карман пуст» / «нечем крыть»), рандом — пер-игровой поток от
сим-тика, НЕ мировой сид: перезагрузка не читает следующий бросок.
Дурак/домино/шашки — те же строки band'а 100.. с теми же гейтами.

## Бартер — сделка, не магазин

Политика экрана обыска ([inventory.md]), не отдельное окно. Обе стороны —
НАСТОЯЩИЕ инвентари: 8×8 игрока и пул-строка NPC. Сделка:

1. **Метки.** Enter помечает слот в оффер (обе сетки, слот целиком).
   Деньги не помечают — **рубли текут сами**: превью считает разницу
   оценок, коммит двигает ровно столько рублей от должника. Пометить
   рублёвый стек можно — он идёт по номиналу.
2. **Оценка — спред референса** ([vendor.h], выжившие константы): взять
   чужое стоит value×1.15, своё уходит по value×kSellMult[вид], вид — из
   ФРАКЦИИ САМОГО NPC (`vendor_kind_for`): учёный платит лучше дикого.
   Рубль освобождён от спреда в обе стороны — иначе размен сам себя
   облагал бы.
3. **Платят тем, что лежит в кармане.** P0 референса («богатый скупщик без
   капа ликвидности») закрыт физикой: NPC, не покрывающий разницу своими
   рублями, сделку не подписывает, и отказ ПОКАЗЫВАЕТ недостачу. Старый
   суррогат kSellPerVisitCap удалён вместе с окном Vendor.
4. **Коммит атомарен.** Обе передачи — на копиях обоих инвентарей
   (`inventory_give`, износ едет); любой остаток — полная сумка, надетый
   предмет в оффере — отказ, никто не сдвинулся ни на байт. Полусделка =
   кража багом в любую сторону.

Лут (ящик/труп) — вырожденный случай: баланс не требуется, переносы
мгновенные, как построено в 61e6d7cf.

## Что выпилено

Окно «Trader Supply & Exchange» и вся RunLedger-торговля: vendor_buy /
vendor_sell_all / vendor_resupply / vendor_stocks* / vendor_ammo_for /
цены. Магазин, где стоком был каталог, а кассой — банковский счёт,
противоречит обоим законам бартера (реальные инвентари, физическая
ликвидность). Из vendor.h выжили ровно константы оценки: VendorKind,
kBuyMult, kSellMult, vendor_kind_for. Банкноты banked ↔ рубли-предметы —
инкремент C (банкир); склад-магазин от продакшн-петли — D.

## Границы

- `giga_game`, headless: меню и сделка тестируются без GPU.
- UI строго читает и возвращает заявку; CRT-эстетика [AGENTS.md].
- Речь/слухи НЕ дублируются: talk зовёт speech, не хранит своих строк.
- NPC не особенный: любой живой `NpcRef` разговороспособен — торговец
  отличается только содержимым карманов (а с инкремента D — складом).
